# 分档要读讲稿：低置信提示不能在真实高风险组合上沉默

## 背景

预填分档（`classifyBand`）只读**版面**：页内有 ≥3 个编号标记或有卡片簇就判 `structured`，
否则 `low-confidence`。这条判据的原始依据是「版面把讲解顺序编码出来了，规则就能跟上」——
真实讲义上实测内容召回 0.972，纯文字页 0.533。

2026-11-01 的结构词消融（`scripts/fidelity/ablate_structure.py`，见 fidelity README）证明这句话
只对了一半：

| 讲稿 | 版面 | 内容召回 |
|---|---|---|
| 含结构词（「第二部分」「分五个部分」「右边那张图」） | 有结构 | **0.972** |
| 不含结构词 | 有结构 | **0.667** |
| 不含结构词（`base` 档） | 无结构 | 0.500 |
| — | 无结构 | 0.533 |

把讲稿里 13 处结构词（序数 8 / 数量 3 / 空间 2）删掉、golden 一字不动，召回从 0.972 掉到
0.667。也就是说：**0.972 成立的前提是讲稿把版面结构念了出来**，而这个前提由讲稿侧决定，
分档却完全没看讲稿。

于是有一个具体的漏报：

> 版面有编号/卡片（判 `structured`），但讲稿是口语直讲、没有「第几条」「分几块」这类说法。
> 实测召回 0.667，编辑器却按结构化呈现——不给低置信样式、不给复核提示。

低置信提示恰好在真实的高风险组合上沉默。这和「门禁看起来在守、实际没守住」是同一类问题：
判据只覆盖了它当初被写下的那个样本。

## 决策

1. **分档 MUST 同时读两侧**：版面结构信号（markers / clusters）与讲稿结构词（序数 / 数量 /
   空间指代）。只有两者都在才判 `structured`。
2. **低置信 MUST 说明缺的是哪一侧**：`layout`（版面没信号，沿用现有 0.533 文案）、
   `script`（版面有结构、讲稿没讲出来，0.667）、`both`（两侧都缺，0.533）。
   三种情况的数字不同、下一步动作也不同（改版面是改 PPT，改讲稿是改写讲解词）。
3. **讲稿结构词 MUST 与新信号一起透出**：`script-structure` / `script-flat`，与既有三条信号
   同序输出，供复核表直接显示。
4. **不改绑定结果**。分档只决定呈现形态，不改一条 `withSegment:`——这条边界从上一个变更起
   就定死了，本变更不越界。

## 不做什么

- **不动规则与阈值**。0.667 不是靠调参能补的缺口（缺口是讲稿没给信号），补它要动的是模型通道，
  那需要 6.2 的对照数据。
- **不按召回率动态分档**。没有真值就没有召回率；分档只能用可观测的输入特征。
- **不把「模糊数量」当结构词**。消融显示「分几个部分」与整句不说等价，规则只认精确数字。
  分档跟规则同一口径，否则会出现「分档说有信号、规则一条都绑不上」的错配。
- **不给讲稿侧判据单独开新字段**。`bandReason` 只用三个值，够了；再拆会把「原因」变成
  「配置」。

## 风险

- 真实用户页面会有一批从 `structured` 掉到 `low-confidence`，看起来像「功能变差了」。
  这是如实呈现，不是退化：那批页面的预期召回本来就只有 0.667。需要在前端文案里写清楚
  「掉档的原因在讲稿，不在版面」，否则用户会去改 PPT。
- 讲稿结构词的判定与三条规则共用正则是**有意的**（同一口径），但这也意味着未来改规则会影响
  分档。这条耦合写进 design，作为可接受的代价。
