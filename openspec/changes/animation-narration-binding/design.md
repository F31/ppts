# 设计：绑定预填的落点、分档与置信

## 1. 架构落点（已核实，不是推断）

绑定需要两侧输入：**元素文本**与**段落文本**。

- 段落文本来自讲稿分段（`segments[].text`），在 `animation.Revision` / `PageContext` 一侧可得。
- 元素文本只存在于 `project.Shape.Text`。**`render.Element` 只有 `{ID, Kind, Bounds}`，
  没有文本字段**（`internal/render/compile.go:35`）；`app.PageElements`
  （`internal/app/animation_geometry.go:105`）是唯一的「形状 → 元素」换算点，它拿得到
  `*project.Page`，但产出已经丢掉了文本。

结论：**绑定器 MUST 落在 `PageElements` 之上、编译之前**，输入是 `*project.Page` +
分段列表，输出是每条要绑定的元素的 `withSegment:<id>`。落在编译之后就只能拿到 ID 与几何，
规则里字面、数量词、序数三条全部失效。

这也是为什么绑定不能做成「渲染期特性」：渲染侧本来就没有文本。

## 2. 分档：先判版面有没有结构信号

同一套规则在结构化版面 0.972、纯文字页 0.533。硬套会得到一个「大概能填一半」的平均值，
掩盖掉可用与不可用的差别。因此预填 MUST 先做分档：

| 信号 | 检测方式（纯几何 + 文本形态，不调模型） | 命中后的规则 |
|---|---|---|
| 编号标记 | 页内存在 `01`–`99` 形态的短文本块，且 ≥3 个 | 序数规则（「第 N 条」→ 第 N 块）、数量词规则（「五个部分」→ 5 个编号块） |
| 卡片/分组 | 存在互相包含或上下紧邻（≤60px）且横向重合 ≥0.6 的元素簇 | 同块带出 |
| 方位指代可用 | 页内元素分布覆盖 ≥2 个方向区域且各区域非空 | 方位规则（「右边那张图」） |
| 无上述信号 | — | 只走字面 + 标题先验，并标记为**低置信预填** |

低置信预填 MUST 仍产出（否则纯文字页得到空轨道），但 MUST 在编辑器里以不同样式呈现，
让用户知道这批该多看一眼。

### 实现修正（落地时发现，回写进设计）

上表三条信号在真实讲义上的判别力**并不相等**，实现时按实测收紧了定档逻辑：

- 「方位覆盖 ≥2 个方向区域」几乎恒真：任何有元素的页面都会同时占住「左」和「上」
  两个半区，横竖都过 2 的门槛。把它放在 `or` 里，分档就永远返回「结构化」，
  纯文字页拿不到低置信标注——规格形同虚设。
  处理：方向覆盖仍然检测、仍然输出（`Result.Signals` 与 `DirectionCoverage`），
  但**不单独定档**；定档只看编号标记与卡片簇。
- 「上下紧邻 ≤60px」在兄弟规则里允许负 gap（同卡片内轻微重叠是常态），
  但在**分档**里要求 `0 ≤ gap ≤ 60`：同一行左右并排的两个文本框 gap 恒为负，
  放行的话任何一行并排文字都会被判成卡片簇，这条信号也就跟方向覆盖一样失效了。
  两个判据用途不同，不共用一个宽松口径。

分档不改绑定结果，只决定呈现形态，因此这次收紧不影响 2.6 的金标数字
（金标只算召回/精确，与 Band 无关）。

## 3. 置信度而不是硬阈值

现有阈值 0.12 是看分布定的，样本量不足以交叉验证。所以：

- 阈值继续用于「绑不绑」的判决（保持与实验一致，便于复现 0.972/0.962）；
- 但每条绑定 MUST 同时输出**连续置信度**与**来源**，编辑器按置信度升序呈现，
  用户先看最可疑的。

理由与「来源标注」相同：把复核成本从 O(全部) 降到 O(最可疑的那批)。

## 4. 对齐必须是单调 DP

`dp[i][j]` = 前 i 个元素只用到前 j 段时的最大相似度和。三种转移：段 j 空着 / 元素 i 不绑 /
元素 i 绑段 j。`bind` 分支不推进 j，所以一段可以连续带出多个元素。

不单调会怎样：逐个取最大值会把四行条目全绑到第一段（它们共享「本期」这类高频词），而且真实
讲解不会「讲到第三行又退回第一段」。这条约束不来自数据，来自「讲解是线性的」这一事实。

## 5. 确定性

预填 MUST 是纯函数：同一 `(project.Page, segments)` MUST 产出同一结果。MUST NOT 依赖随机数、
当前时间、网络调用或 map 遍历顺序。否则「重跑一次结果不同」会让用户对预填失去信任，
而信任一旦丢掉，预填就等于没有。

## 6. 与既有触发器语义的关系

预填只写 `withSegment:<segmentId>`，不写 `atTime:`。理由：分段时长会随讲稿修订变化，
绝对毫秒在改稿后就错了；相对引用由编译期解析（`resolveTrigger`），改稿后自动跟着走。

分段 id 不存在时的行为沿用既有实现（`DiagSegmentUnresolved`，起点退化为 0 并记诊断），
预填不另造一套降级逻辑。

## 7. 验收口径

单测数字不能代表成片。本变更的验收 MUST 包含：

1. **金标复现**：在 `sample-customer-deck.pptx` 的 1/2/4/8/10 页 + `q8-script.json` 上，
   Go 实现的召回（内容元素）与精确 MUST NOT 低于 0.972 / 0.962。低于即视为移植走样。
2. **字节不变**：无来源标注的既有规格，序列化与 `planHash` MUST 与引入前一致。
3. **带配音样片**：出 30s 级带音轨样片，逐段核对「讲到第 N 段时第 N 条才出现」，
   沿用 Q7 已有判据（开口前 400ms 内区域变化为 0）。静音样片测不了这件事。

## 8. 已知未定（不写进规格）

- 眉标/小标要不要被「同块带出」带进（`p1-s5` 一处口径分歧）；
- 图注要不要单独淡入（`p3-caption` 一处口径分歧）。

两处都需要第三份样本才敢定，本变更按现状（带出、白名单退掉图注）落地，不新增规则。
