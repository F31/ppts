# 提案：动画视觉基线（批次一）

## 为什么

设计方案 §19.1 把"像不像参考片"的贡献拆成六项，结论是：资产 35%、版式 20%、镜头 15%、运动质感 15%、音频 10%、**渲染引擎本身只有 5%**。而当前仓库对前四项的覆盖度全是"无"或"低"，只有渲染通道（`internal/media` 的编码、`timeline.json` 的拼装）是完整的。

这意味着：如果直接开 M2（渲染服务），拿到的第一个成品会是"元素动了，但排版像默认 PPT、节奏全靠硬编码、每个元素同时开始动"。**观感问题是不可后期修复的**——它不在渲染器里，而在渲染器读什么、按什么规则排版与计时里。所以 M2 之前必须先把标准写成代码。

本变更只做"标准"，不做渲染器。它是 M2 的输入契约，而不是 M2 的一部分。

## 变更内容

新增 `internal/design` 包与一个预览生成器，四块内容：

1. **设计令牌**（`tokens.go`）：1920×1080 画布、12×8 栅格、字阶、间距标尺、色板、安全区、圆角与描边。全部是数据 + 不变量，不含任何绘制逻辑。
2. **版式原型**（`archetypes.json` + `archetypes.go`）：10 个版式（封面/章节卡/要点/图文/全幅图/大数字/引文/图表主角/对比/结尾），每个原型用栅格行列声明槽位，供 M2 按内容填充。
3. **运动质感档案**（`motion.go`）：stagger 序列、预备动作、回弹、停顿、速度分层、节拍单位与节拍数区间、命名缓动曲线。这是 §19.4 那张表的代码化。
4. **观感度量**（`metrics.go`）：对比度、最小字号、元素数、留白比例、节奏密度，输出带规则编号与严重级别的 `Report`。

外加 `cmd/design-gallery`：把上述令牌、版式与运动曲线渲染成一个自包含 HTML（双击可开，零外链），让"好不好看"在没有渲染器的阶段也能被讨论和评审。

## 能力边界

- **不产出插画资产。** G1 的资产体系需要设计资源，代码库只能定义契约：`assets.go` 声明资产清单结构（id/kind/version/license/file）与校验规则，其中 `license` 必填——§12.3 的许可风险必须在数据层就拦住，不能靠流程自觉。
- **不做交互式预览（G6）与性能基准（G15）。** 两者都需要渲染器，归 M2；本变更只提供它们要读的令牌。
- **不做像素级视觉回归。** 没有渲染器就没有基准图，基线只能是"可评审的预览页 + 可断言的规则"。

## 影响

- 新增依赖：**零**。`internal/design` 只用标准库，不 import `internal/animation`、`internal/project`（度量接受的是纯数值的事实结构），避免标准与实现互相锁定。
- 对既有代码：**零改动**。不碰 `export.go`、`internal/media/`、`web/`。
- 后续消费者：M2 渲染服务按 `Theme` 排版、按 `Archetype` 填槽、按 `MotionProfile` 排时序，并在渲染前调用 `CheckPage` 做门禁。

## 风险

| 风险 | 应对 |
|---|---|
| 令牌是我"拍"的，不是设计师定的 | 所有数值集中在一处、带出处注释（§19.4 参考值）；`cmd/design-gallery` 的作用就是让这些数值可被非工程师质疑和替换，换的是 JSON 常量，不是渲染代码 |
| 版式原型过度约束内容 | 原型只是槽位建议，M2 允许越界回退到自由排版；本变更的校验只保证原型自身合法（槽位不重叠、不越界） |
| 度量变成"为了通过而通过" | 严重级别分 error/warn：只有字号与对比度是 error（可读性硬底线），其余是 warn（建议），避免把启发式当法律 |
| 与 `web/` 控制台令牌重复 | 两者服务不同介质（控制台 UI vs 1080p 成片），刻意不共享：字号差一个数量级，共享只会互相迁就 |
