# 设计：页内镜头切片（Page.Shots）

> 三条设计取舍已经拍板：**只做 Page.Shots 切片**、**切换用 120ms 叠化**、**特写图由渲染侧额外产 2x**。本文件把这三条落成可执行的契约，然后才写代码。

## 1. 三条决定各自带来什么

| 决定 | 好处 | 必须现在就定死的东西 |
|---|---|---|
| 只做 Page.Shots | 不动 `DurationMs`、不动分段的粒度、不动 clips 的时间基准 | `shots` 与页级 `image` 谁是权威；层在镜头切换时怎么办 |
| 120ms 叠化 | 观感像「一镜内转场」，与页间 `fade` 同宗 | 叠化占谁的 120ms；门禁取样怎么避开混合帧 |
| 2x 局部图 | 「全图 → 特写」不糊 | 特写镜头的坐标基准；层的位移怎么映射；2x 图由谁产、什么时候产 |

## 2. 数据模型

```go
type Shot struct {
    Index       int    `json:"index"`
    Image       string `json:"image"`             // 铺满舞台的图（整页图，或裁切放大后的特写图）
    Crop        *Box   `json:"crop,omitempty"`    // 该图取自原页的哪一块（原页像素坐标）；nil = 整页
    StartMs     int64  `json:"startMs"`           // 页内相对
    DurationMs  int64  `json:"durationMs"`
    CrossFadeMs int    `json:"crossFadeMs"`       // 本镜头开头的叠化时长；0 = 硬切
}
```

三条校验（编译期 + 打包期各一次，报错带页码与毫秒）：

1. 首尾相接、无空洞无重叠；
2. 总长等于页时长（容差 1 帧）；
3. `Crop` 非空时必须在原页范围内（`x+w <= 页宽`、`y+h <= 页高`）。

**宽高比那条放在打包期**，不放在 IR：IR 里 `Image` 只是一个路径，拿不到像素尺寸；打包时图已经落盘，才能量出「`Crop` 的宽高比与 `Image` 的宽高比差 ≤1%」。比例不对说明裁切算错了，浏览器会拉伸，而拉伸后的画面「看着还挺正常」——所以它必须在能读到图的那一层拦。

`shots` 为空时，页级 `image` 是唯一权威，产物 MUST NOT 写出该字段。`shots` 非空时，首镜的 `image` MUST 等于这一页**呈现出来的底图**——有 `PlateImage` 时是底板，否则是 `BaseImage`。写成 `BaseImage` 只在一种页上出错：既有分层动画、又切镜头。那时元素本来就在图里，层再从透明淡入一次，画面出现一层重影，而两边都不报错。

首镜 MUST NOT 声明 `crop`：首镜就是整页，声明一个裁切框等于说「这张整页图是从某个局部裁出来的」，打包期还得为它去找原图量比例。

## 3. 时间语义：叠化占后一镜的开头

与页间转场保持同一套语义（`renderer/src/Timeline.tsx:85-100`）：转场挂在**后一段**的开头，`easeOutCubic`，期间两张图同时可见。

于是：第 2 个镜头 `startMs=2000, crossFadeMs=120` 表示 2000–2120ms 期间 A 淡出、B 淡入，**2120ms 之后画面才是纯 B**。

这条直接决定门禁取样：

- 「切图了」的判据 MUST 取在 `startMs + crossFadeMs + 1 帧` 之后，不能在切点上取——切点那一帧两张图各半，跟哪张都不像。
- 叠化窗口是**左闭右开**：`startMs + crossFadeMs` 那一毫秒 MUST 已经是纯 B。写成闭区间会多停一帧，而 33ms 的混合帧在门禁里就是一条与哪张参照物都对不上的样本。
- `crossFadeMs` MUST ≤ `durationMs`，否则这一镜还没淡完就结束了。

## 4. 几何：特写镜头的坐标基准

这是本设计里唯一会「悄悄画错」的地方，必须写死：

- `Image` **总是铺满舞台**（浏览器按舞台尺寸缩放整张图）。
- `Crop` 只描述「这张图取自原页的哪块」，用来做两件事：核实裁切比例（第 2 节第 3 条）、以及决定层在这一镜里能不能显示。
- **`Crop` 非空的镜头内，层 MUST NOT 显示。** 层的 `box` 是整页坐标（`ir.go:133` 的 `Box`），特写把原页局部放大后，同一套坐标落上去必然错位；而错位的层不会报错，只会看起来「元素飘了」。第一版直接不给它显示，比算错强。
- 层的时间轴不因镜头切换而重排：`Layer.Clips` 仍是页内相对毫秒，跨镜头边界**不重建图层**（重建会让元素重新入场）。

因此推荐用法是：**有元素动画的页不切特写；要切特写时，特写那一镜是纯画面。**

## 5. 素材：2x 图由谁产

现状：`internal/integrations/render/render.go` 用 LibreOffice 整页栅格化，只有 `RenderOptions{DPI}`，没有区域参数；产物是 150 DPI 的 1080p PNG。直接把 1080p 局部放大 2 倍必然糊。

分两步：

- **第一步（本变更内）**：`Shot.Image` 接受任何尺寸的图，先用现有页图裁切（会糊）。目的是让「切图 + 叠化 + 校验 + 门禁」这条链先跑通、先能验收。糊是已知代价，写进规格。
- **第二步（本变更后置任务）**：对声明了 `Crop` 的页，导出时用 `RenderOptions{DPI:300}` 重渲一次整页 → 按 `Crop` 裁切 → 作为 `Shot.Image` 落盘。一次高 DPI 渲染可服务同页的多个特写，成本是「每张有特写的页多一次 soffice」，不是全片翻倍。

第二步的验收不看观感，看一条可量的东西：特写图的**边缘梯度能量**不低于 300 DPI 源裁切的 95%（糊图会明显低）。这条比「看起来清楚了」可靠。

## 6. 清单与校验

`share.SlideEntry` 增 `Shots []SlideShot`（`omitempty`），字段与 IR 同构。新增校验：

- `shots` 非空时，`slide.Image` MUST 等于首个镜头的 `image`（否则「这一页长什么样」有两个说法）；
- 每个 `shot.Image` 必须在包内存在（复用 `checkBundlePath` 与 `files` 集合，与层图同一条规则）；
- 打包期能读到图，因此在这里补 IR 算不了的那条：`Crop` 的宽高比与 `Image` 的宽高比之差 MUST ≤1%。
- **层与镜头允许共存**：层是整页的，镜头切到 `Crop` 那一镜时层不显示（第 4 节）。清单不禁止多镜头页带层——否则「先全图动画、后切特写」这个最常见的用法就做不了。

## 7. 门禁怎么取样

| 门禁 | 今天 | 加 Shots 之后 |
|---|---|---|
| V13b（终态帧 == 源页） | 页尾前 250ms | 取**最后一个镜头**的中点（避开叠化窗口），参照物是该镜头的 `Image` |
| V13（包端 vs 成片同帧） | 页首 / 首段 clip 中点 / 页尾前一帧 | 页首、**每个镜头的切点后 1 帧**、页尾前一帧 |
| 新增：切图判据 | 无 | 跨过 `startMs + crossFadeMs + 1 帧` 时，舞台主图 MUST 是第 2 张；且在 `startMs - 1 帧` 时 MUST 是第 1 张 |

## 8. 兼容与回归

- 无 `shots` 的包：IR、清单、播放器、渲染端行为与今天逐字节一致；V13/V13b 读数同量级（0.9968 / 0.99994）。用 golden 守 IR，不靠人看。
- 有 `shots` 的包：**不升 `schemaVersion`**。查过证据——播放器（`web/src/sharePlayer/main.ts`）根本不读这个字段，升版本只让 Go 的 `Validate` 拒绝 v2 包，客户端行为一点没变；而 `shots` 是可选字段，旧播放器读到它会忽略，画面停在首镜图（`slide.image` 就是 `shots[0].image`，已由校验绑死）。
  - 所以旧播放器上的表现是「**降级可播放，但不换镜**」：不白屏、不报错，只是少了一次切镜。这比「拒绝整包」好，也比「声称兼容」诚实——写进规格，不写成「已兼容」。

## 9. 分期

1. **IR + 校验 + golden**（Go）：结构、三条校验、无 shots 时字节不变。
2. **播放器 + 渲染端**（TS）：按时间选图、叠化、层在 crop 镜头内隐藏。
3. **清单 + 打包**（Go）：字段、三条校验、`schemaVersion` 3。
4. **门禁**：取样点调整 + 新增切图判据 + 夹具加一页双镜。
5. **2x 素材**（Go + soffice，后置）：300 DPI 重渲 + 裁切 + 边缘梯度验收。

前四组做完就有可见效果；第五组只影响清晰度，可独立验收、独立回退。

## 10. 落地时被证据改掉的三处

写代码的过程改了本文件原先的三条判断，记在这里而不是悄悄改掉：

1. **首镜的基准不是 `BaseImage`，是「呈现底图」**。原稿写「首镜等于 baseImage」，依据是「旧播放器只认页级 image」。查 `bundle.go:311` 才发现：有分层动画的页，写进清单的页级图是**底板**（元素被挖空）。两条约束一起成立时，一份计划要么过不了校验，要么在画面上留一层重影。改成「有 `PlateImage` 时等于它，否则等于 `BaseImage`」。
2. **首镜不得声明 `crop`**。原稿允许，实际是矛盾数据：首镜的图就是整页，却声称自己取自某个局部。禁掉之后打包期也不必为首镜找原图量比例。
3. **`schemaVersion` 不升**（已写进第 8 节）。查证结论与「升到 3」相反：播放器不读这个字段，升版本只让 Go 自己拒绝旧包。

另有两处是踩出来的实现细节，值得留档：

- **两张图必须显式叠放**。播放器里两张 `<img>` 是块级元素，默认竖排，第二张被排到面板下方、被舞台 `overflow:hidden` 裁掉；渲染端两张 `<Img>` 落在 `AbsoluteFill`（flex 列）里同样竖排。两处表现完全一样：「叠化没生效」，而 DOM、`src`、`opacity` 全都正确。播放器靠 `.ppts-slide{position:absolute;inset:0}`，渲染端靠各套一层 `AbsoluteFill`。
- **微秒与毫秒**。`us - slide.startUs` 是微秒，镜头的 `startMs` 是毫秒。漏除 1000 不会报错，只会让每一帧都超出末镜——画面永远停在最后一镜，而「最后一镜」本身是一张合法画面。
