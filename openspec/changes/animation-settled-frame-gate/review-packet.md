# 评审记录：终态帧门禁（V13b）

## 1. 为什么这条判据不是「再加一个 SSIM」

现有五条门禁的覆盖边界很清楚：

| 判据 | 问的问题 | 参照物 | 能发现「包画错了」吗 |
|---|---|---|---|
| V14 | 有没有外链 | 包内文件 | 否 |
| V15 | 体积超没超 | 预算 | 否 |
| V16 | 能不能播 | 真实浏览器 | 否（只问在不在播） |
| V17 | 降级后还在不在 | 真实浏览器 | 部分（只问层是否存在、是否停在终态） |
| V13 | 两端一不一致 | MP4 同帧 | 只在不一致时（两端同错则不报） |

V13 的参照物是成片，成片要渲染镜像，所以它跑不进 CI；而且两端共用 `shared/motion.ts`，共模错误在两端同时出现，SSIM 照样 0.99。V13b 把参照物换成**源页图**，于是两个问题一起解决：不需要成片，且共模错误无处可藏。

## 2. 判据成立吗——正例

夹具：`share-baseline -pages 2 -page-secs 4 -width 1280 -height 720 -layers 2 -pages-out`。

| 页 | 取样时刻 | SSIM | 平均差 | 差>32 占比 |
|---|---|---|---|---|
| 0 | 3750ms | 0.99995 | 0.0023 | 0.000% |
| 1 | 7750ms | 0.99994 | 0.0020 | 0.000% |

第一次跑是 0.66。原因不是判据不成立，是取错了画面：**舞台只占截图的 492×344**（见第 4 节），而我当时拿整张 1920×1080 去比。修完布局、改成按舞台矩形裁切后才是上表。

## 3. 判据会红吗——四个负例

| 改动 | 结果 | 退出码 |
|---|---|---|
| 清单里某层 `box.x` 右移 40px | page 0：平均差 0.941、结构性差异 0.521%（阈值 0.5 / 0.05%） | 1 |
| 底板 PNG 每通道 +10 | page 0：SSIM 0.96001、平均差 9.585 | 1 |
| 1920 的包比 1280 的页图（尺寸不符） | 落「包与页图不是同一尺寸」 | 2 |
| `PPT_CHROME` 指向不存在的文件 | 明确报文，不打印 PASS | 2 |

第一条值得注意：40px 错位下 SSIM 仍有 0.9957，**单看 SSIM 会漏过**——错位的框与它原来的位置颜色相同，重叠部分是零差异。抓住它的是结构性差异占比。这也是三条阈值同时判、而不是「SSIM 过了就算过」的原因。

## 4. 过程中挖出来的两个真问题

### 4.1 播放器在 1920 下只画出 492 宽的卡片

第一次截图量出的舞台是 `{x:714, y:24, w:492, h:344}`，而样式表写的是 `max-width: 1280px`。

根因：打包器在 `body` 与 `.ppts-share` 之间插了一层 `#ppts-share-root`（`internal/share/html.go`）。`body` 是 `display:flex`，于是这层容器成了弹性项，宽度按内容收缩；`.ppts-share` 的 `width:100%` 跟着等于内容宽度（492）。样式表里看不出问题，因为问题在**多出来的一层**里。

修法：`#ppts-share-root { display: contents }`，这层不参与布局。修完舞台 1280×720。

没有顺带修垂直居中：`body` 的 `align-items:center` 其实也没生效（`min-height:100%` 在 `html` 高度为 auto 时解析不出视口高度），当前是顶部对齐。补成真正居中要设 `html{height:100%}`，而在 1366×768 这类矮窗口里卡片（720+控制条）会高于视口，flex 居中会把顶部裁掉。先用顶部对齐，这件事单独记着。

### 4.2 播放器产物落后源码两个提交

`internal/share/assets/app.js` 最后一次生成在 `93b56eb`（2026-10-30）。之后 `3e2bd51`、`0105772` 两次改了 `shared/motion.ts` 与 `web/src/sharePlayer/animation.ts`（V12 的「压暗要有终点」、V13 的「此刻亮着几个」），**产物没有重新生成**。

后果不是「有点旧」，是：V12/V13 修掉的那个压暗 bug，在 HTML 成品包里一直还在。而 MP4 通道用的是当前代码，所以同一份讲稿的两个交付物在这件事上不一致。

CI 里其实有这条检查（`share player build (drift check)` + `git diff --exit-code`），也就是说它从 2026-10-30 起就是红的——检查在，只是没人看结果。本轮重新生成：`app.js` 11869 → 12902 字节，`app.css` 增加 `#ppts-share-root` 规则。

顺带一问：`web/package.json` 里 `"vite": "latest"`，锁文件钉住 8.3.0，所以 CI 的 `npm ci` 是确定的；但下一次 `npm install` 会换掉 vite，产物字节随之变化，drift check 会在某个无关提交上突然红。这属于依赖策略问题，记着，不在本轮改。

## 5. 两次「判据自己在骗人」

写这条门禁时踩到两处同类问题，都记在代码注释里：

1. **`--window-size` 给的不是视口**。`--window-size=1920,1080` 实际得到 1898×982（扣掉边框与滚动条），截图与页图尺寸对不上，比对只能靠缩放糊过去。改用 `Emulation.setDeviceMetricsOverride` 才是「视口就是 1920×1080」。
2. **先摘外壳再 seek 等于没摘**。seek 会走一遍播放器的 `X()`，里面把字幕重新 `hidden = false`；音频元数据迟到时还会再走一遍。于是同一份包两次运行给出 0.9999 与 0.9676 两种结果（0.9676 那次字幕压在画面底部，差异全在那块）。改用 `remove()`：播放器再改属性也改不回画面。

第 2 条差点被记成「判据不稳定」——实际是判据的**输入**被播放器改回去了。

## 6. 夹具改动

`share-baseline` 原先的层图是「一块实色矩形」，而页图里没有这块矩形，于是「底板 + 层图 == 源页」在夹具上根本不成立，V13b 无从判起。改法：

- 页图在同一批框里画出层色，层图即该框的裁片（`layerBox` / `layerColor` 一处定义，页图与层图共用）；
- 底板**不画**这些框（`layers=0`）——框由层图提供，底板画了就是「渐显的层下面压着一块不动的框」；
- 新增 `-pages-out DIR` 落盘本次用的页图；
- 顺带修掉一个真分叉：`zip` 形态与 `-out` 目录形态原先各生成一次合成页，参数不一致时同一个命令产出的两个包不是同一个包。现在页图只生成一次，三处共用。

单测 `TestSyntheticFixtureComposesToPage` 守这条等式：页图框内颜色 == 层色，且底板同位置**没有**该框。

## 7. 重构：候选表只留一份

上一轮为了把 V16/V17 从镜像里解放出来，在 `bundle-probe.mjs` 里写了浏览器候选表；这一轮再加一个截图脚本，就会出现第二份。抽成 `scripts/review/cdp.mjs`（`resolveChrome` + `launchBrowser`），探针与 `dom-shot.mjs` 都 import 它。

改完复跑 `bundle-gate.py --engine native`：**21 条判据仍全部 PASS**，判据本身一条没动。
