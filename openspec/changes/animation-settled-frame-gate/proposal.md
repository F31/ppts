# 提案：终态帧门禁（V13b）——包有没有把这一页画对

## 为什么做

`html-share-quality` 现在守四件事：自包含（V14）、体积（V15）、能播（V16）、降级可用（V17）。这四条全绿，仍然可以允许一个**画错了的包**：图层框整体偏 40px、底板颜色偏一格、画面被按 1.1 倍缩放，V16 只问「有没有在播」，V17 只问「降级后层还在不在」，没有一条比像素。

唯一比像素的是 V13（`dom-ssim.py`：成品包 DOM 截图 vs MP4 同帧）。它有两个限制：

1. 参照物是**成片**，而成片要渲染镜像才能产出——它跑不进 CI，也就意味着合并前没有人在看；
2. 它比的是「两端一致」，不是「画得对」。两端都由 `shared/motion.ts` 插值，同一个错误会在两端同时出现，SSIM 照样 0.99。

本轮补的是这两条之间空着的那一块：**用源页图当参照物，在 CI 里判「这一页画得对不对」**。它不需要成片，只需要一个浏览器。

## 目标

1. **新判据 V13b**：每页取结尾前 250ms 的一帧（此时动画已收尾，画面就是该页终态），与源页图逐像素比；SSIM、平均差、结构性差异像素占比三条同时达标才算过。
2. **落点可断言**：定位靠播放器自己的 seek 滑杆，实际落点读回来与请求比对（≤50ms），定位失效就判失败——否则「拍到了别的时刻」会被当成「画面画错了」。
3. **只判画面，不判外壳**：截图前摘掉封面按钮与字幕条（各有自己的守卫），否则外壳噪音（实测平均差 28）会盖住真正的缺陷。
4. **进 CI**：挂在 `share-browser` 作业里，与 V16/V17 同一条流水线。
5. **夹具能造出可判的包**：`share-baseline -layers N` 让层图成为页图在该框内的裁片，`-pages-out` 把源页图落盘——否则「层图叠回底板 == 源页」这条等式在夹具上根本不成立。

## 非目标

- 不替代 V13。V13 判「两端一致」，V13b 判「画得对」，两条都留。
- 不判动画过程。取样点只有页尾一个，中间态仍归 V13、V17 与 `scripts/fidelity` 那套。
- 不判 1920 页图的缩放。舞台宽度受播放器上限（1280）约束，拿 1920 的页图去比会掺入重采样误差（实测 SSIM 0.969，而 1:1 是 0.99994）——两个数字分不清「画错了」和「只是缩放了」，所以本门禁要求包与页图同尺寸，尺寸不符按输入问题退出（不判）。
- 不把 `still-check.py` 一并搬进 CI：它的输入是 Remotion 单帧，仍要渲染侧的工具链。

## 顺带修掉的两个真问题

这两个不是"顺手优化"，是被这条门禁的准备工作逼出来的，且都影响线上交付物：

1. **播放器产物落后源码两个提交**：`shared/motion.ts` 与 `web/src/sharePlayer/animation.ts` 在 `3e2bd51`、`0105772` 改过，`internal/share/assets/app.js` 没有重新生成。也就是说 V12/V13 修掉的压暗问题，在 HTML 成品包里一直还在。CI 的 `share player build (drift check)` 从那天起就是红的——检查在，只是没人看结果。
2. **播放器在 1920×1080 下只渲染成 492 宽的卡片**：打包器在 `body` 与 `.ppts-share` 之间插了一层 `#ppts-share-root`，`body` 是 flex 容器，这层成了弹性项、按内容收缩，`.ppts-share` 的 `width:100%` 于是等于内容宽度。样式表里写的是 `max-width:1280px`，谁都说不清小是从哪儿来的。`display:contents` 修掉。

## 与既有变更的关系

- 依赖 `html-bundle-quality`（已归档）的 V14–V17 与 `animation-browser-gate-ci`（已归档）的浏览器解析层；
- 复用后者带来的 `cdp.mjs`：浏览器候选表与 CDP 连接只写一处，探针与截图共用。
