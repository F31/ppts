# Spec Delta

## Purpose

定义「HTML 成品包」在交付前必须通过的质量判据：自包含（V14）、体积预算（V15）、真实浏览器可播放（V16）、四条降级路径可用（V17）、画面与源页一致（V13b）、两端画得一样（V13）。目标是让「包有没有坏」变成一条可执行的命令，而不是靠人打开看一眼——外链、体积翻倍、资源 404、降级失效、画面画错、两端分叉这六类问题在导出时都不会报警，只会在客户打开时暴露。

## MODIFIED Requirements

### Requirement: 比对范围与尺寸前提

比对范围 MUST 是播放器的舞台（`.ppts-stage`）矩形，MUST NOT 假定「截图就等于画面」——播放器有圆角、边框与控制条。

截图前 MUST 摘掉封面按钮与字幕条。它们各有自己的守卫（V16 验封面能被点掉、字幕由播放时钟的判据守），留在画面里会把判据淹没在外壳噪音中（实测平均差 28 对 0.002）。

舞台 MUST 定成**源页自己的尺寸**，判据 MUST NOT 掺入重采样：实测同一份包 1:1 为 0.99994、0.667 倍为 0.969——放宽阈值会让「画错了」和「只是缩放了」混为一谈。

播放器卡片的 1280 宽度上限是**网页嵌用的策略**，不是画面的性质：层位置按画布百分比落位，去掉上限只是让同一页按原生尺寸再画一遍。因此截图前 MUST 去掉这道上限，并 MUST 把实测舞台与目标尺寸比对（差 ≥0.5px 即失败）。

舞台与参照物对不上时，门禁 MUST 以退出码 2 结束并报出实测值与期望值，MUST NOT 缩放后照常判、MUST NOT 报成画面不合格——后者会让人去查渲染，而问题在材料上。

#### Scenario: 1920 的页不再需要缩到 1280

- **WHEN** 包与源页都是 1920×1080
- **THEN** 舞台 MUST 为 1920×1080，终态帧与源页的平均差 ≈ 0.0007（不是 0.667 倍缩放后的 0.969）

#### Scenario: 包与页图不同尺寸

- **WHEN** 拿 1920×1080 的包去比 1280×720 的页图
- **THEN** 门禁 MUST 以退出码 2 结束并说明「包与页图不是同一尺寸」，MUST NOT 报成画面不合格

#### Scenario: 舞台矩形

- **WHEN** 包与源页均为 1280×720
- **THEN** 门禁取到的舞台矩形 MUST 是 1280×720（不是 492×344），比对 MUST 在这块矩形内进行

## ADDED Requirements

### Requirement: 两端同帧一致（V13）可在没有渲染镜像的环境里验证

成品包在某一时刻画出来的画面，MUST 与成片同一时刻的解码帧一致。取样 MUST 同时包含**动画进行中**的时刻（第一段 clip 的中点）与页首、页尾；只看末帧会在动画早已结束的静态页上拿到 0.99，什么都没验。

判定 MUST 用逐页最差帧：一页里任一取样点不达标即判该页失败，MUST NOT 用全片平均盖过单页的失败。

这条判据 MUST 只依赖「一个浏览器 + ffmpeg」，MUST NOT 要求渲染镜像或 docker。为此它 MUST 能从**成品包自身**造出可复现的分段（逐帧截 DOM → 编码），并把「夹具能证明什么」写清楚：它证明截图落点、抽帧、解码与阈值这条管线，**不证明**包与真实渲染一致。

门禁 MUST 在材料不齐时以退出码 2 结束（缺分段、时间轴与包不是同一画布、舞台取不到），MUST NOT 拿缩放或错帧照常判。

#### Scenario: 夹具正例

- **WHEN** 用 `make-fixture.mjs` 造 2 页 / 2 秒的分段，再跑 `dom-ssim.py`
- **THEN** 逐页最差帧 MUST ≥ 0.95（实测 0.99686 / 0.99675，退化为编码损失），退出码 0

#### Scenario: 成片错位

- **WHEN** 把某一页的分段整体左移 40px 后重跑
- **THEN** 该页 MUST 判失败（实测 0.932），其余页不受影响，退出码 1

#### Scenario: 材料不齐

- **WHEN** 缺一页分段，或时间轴画布与包的画布不一致
- **THEN** 门禁 MUST 以退出码 2 结束并在开浏览器之前报出原因
