# 评审记录：V13 搬出渲染镜像

## 1. 这次动的到底是什么

`dom-ssim.py` 的判定逻辑（三个取样点、逐页最差、阈值 0.95）一行没改。改的是它的**上半段**——怎么拿到「包端在 t 时刻的那一帧」：

| | 之前 | 现在 |
|---|---|---|
| 浏览器 | docker 里的 `chrome-headless-shell` | `dom-shot.mjs`（`PPT_CHROME` → 平台路径 → 兜底 headless-shell） |
| 定位 | `index.html?t=N`（旧播放器的查询参数） | 播放器的 seek 滑杆，落点读回来 |
| 截图 | 整张视口 | 裁到舞台矩形 |
| 舞台尺寸 | 由 `--window-size` 顺带决定 | `--stage WxH`，断言等号 |
| 本地能否跑 | 否（WSL docker + 镜像 + 成片） | 是（一个 Chrome + ffmpeg） |

顺带的原因是：旧播放器读 `?t=`，现在的播放器不读——那一行参数早就是死代码，只是没人跑过它，所以没人发现。

## 2. 夹具能证明什么，不能证明什么

`make-fixture.mjs` 造的 MP4 来自**包自身的 DOM**：按 30fps 逐帧 seek 截图、裁到舞台、`libx264 -crf 18 -pix_fmt yuv420p` 编码。所以：

能证明：
- 截图落点准（滑杆是千分比，4 秒片子的量化步长是 4ms，实测落点偏差 ≤2ms）；
- 抽帧时刻对得上（`ffmpeg -ss` 取到的就是那段画面，不是别的页）；
- 判据的分母是真的——下面的正例分数就是这一档编码损失本身；
- 坏料会红（第 4 节的负例）。

不能证明：包与**真实渲染**是否一致。那需要真成片，本轮没有，判据与阈值也一字未改。这条写进了规格，免得下次有人拿「CI 里 V13 绿了」当作「两端一致已验证」。

## 3. 正例

夹具：`make-fixture.mjs --pages 2 --page-secs 2`（1280×720，带 2 层、每层 2 条 clip）。

| 页 | 取样点 | 页内时刻 | SSIM |
|---|---|---|---|
| 0 | first | 0ms | 0.99731 |
| 0 | clip-mid | 450ms | 0.99686 |
| 0 | last | 1966ms | 0.99736 |
| 1 | first | 0ms | 0.99743 |
| 1 | clip-mid | 450ms | 0.99675 |
| 1 | last | 1966ms | 0.99719 |

逐页最差 0.99686 / 0.99675，退出码 0。连跑两次五位小数一致——上一轮 V13b 遇到的「同包两次运行 0.9999/0.9676 交替」没有复现，因为摘外壳用的是 `remove()`（seek 之后），播放器再改属性也改不回来。

`clip-mid` 比两端低 0.0005 是取样时刻的取整：MP4 是 30fps 网格（433ms / 467ms），判据要的是 450ms，中间那 17ms 在动画里约 0.2px。真实成片同样受这个网格限制，不是夹具引入的。

## 4. 负例

| 改动 | 结果 | 退出码 |
|---|---|---|
| 第 1 页分段整体左移 40px（`crop=1240:720:40:0,pad=1280:720:0:0`） | 页 0 不变（0.99686），页 1 三点全红（0.93286 / 0.93179 / 0.93211） | 1 |
| 删掉 `segment_001.mp4` | 「缺少分段」，且**不启动浏览器** | 2 |
| 把 `plan.json` 的 `width` 改成 1920（包是 1280） | 「时间轴 width=1920 与包的 1280 不一致：不是同一份作业」 | 2 |

第一条同时验了两件事：错位会被抓住（0.95 阈值下 0.932 有 0.018 余量），以及逐页最差不会被别的页平均掉。

## 5. 顺带修掉的尺寸前提

原规格写的是「包与源页图 MUST 同尺寸……舞台宽度受播放器上限（1280）约束」，等于要求所有包都不超过 1280——而真实作业是 1920。

1280 是 `max-width`，嵌网页时的策略；层位置按画布百分比落位（`animation.ts` 的 `pct()`），去掉上限不改变任何几何。所以 `--stage` 去掉它再**断言舞台等于目标尺寸**：

- 1280 页：0.99994 / 0.99994；
- 1920 页：0.99997（此前这种尺寸会被判「尺寸不符」退出 2）；
- 舞台与源页相差 ≥0.5px：退出 2。

实测 1920 舞台与源页的整帧 meanDiff 是 0.0007——1:1 是真的 1:1，不是「差不多”。

`settled-gate.py` 也吃到了这套：舞台按源页尺寸取，`--width/--height` 两个参数删掉；清单画布与页图尺寸不符时仍在开浏览器前退出 2（这条保证没有放松，只是从「比完发现尺寸不对」提前到了「先看清单」）。

- **没有把夹具换成真成片**。本地没有渲染镜像，造不出真成片；有真成片时应直接跑 `dom-ssim.py`，参数不变。
