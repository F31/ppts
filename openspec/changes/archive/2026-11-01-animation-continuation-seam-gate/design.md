# 设计：页缝延续门禁（V19）

## 1. 判据为什么取在「清单 + 求值器」而不是像素

延续的数学定义是：同一元素在「前一页页尾」与「次页 0 点」的合成态相同。负起点方案下两侧的 raw 进度
同为 `offset / duration`，`evaluateLayer` 又是同一份代码，因此**理论上逐位相等**，容差 1e-6 只为吸收
浮点乘加顺序差异。

若改用像素比对，需要处理：同一元素在两页可见区域是否对齐、JPEG 压缩差异、字体/抗锯齿差异、转场是否
处于交叉中。这些都会让门禁对**无关改动**敏感（假红），却对「offset 写反」未必更敏感。因此 V19 选择：
在成品包清单上做结构 + 数值断言；像素层由既有 V13/V13b 各自守住「包画得对不对」，职责不重叠。

## 2. 为什么必须能红（空跑即失败）

门禁最危险的形态是「没有对象可查所以全绿」。夹具一旦退回（例如页太短、开关没传、编译退化），
V19 的所有逐条判据都会因为没有延续段而被跳过。因此显式加一条 `V19.7 包里确实存在延续段`，
并要求 `-continuation` 未满足前置时**报错退出**，而不是静默跳过。

负向验证（人工执行过一次，留作回归口径）：
- 无 `-continuation` 的包 → `V19.7` 红，退出码 1；
- 把延续段 `startMs` 改成 `+offset`、并改一处 `props.from` → `V19.2` / `V19.4` / `V19.5` / `V19.6` 红。

## 3. 为什么夹具必须显式 opt-in

V13b 的判据是「每页末帧 == 参照页图」。参照页图是**终态**合成图；延续元素在页尾处于中途态（这正是它
跨页的意义）。把延续元素默认挂在 `-layers` 上，会让任何「页长足够溢出」的 V13b 用例假红——而 CI 现在
恰好用 `-page-secs 4`（不满足 `pageMs > 4000`）才侥幸没红。这是**条件掩盖的缺陷**，不是正确行为。

因此：`-continuation` 默认关；开启时前置不满足直接 `log.Fatal`（页太短不许静默降级）。

## 4. 门禁清单（V19.x）

| 代号 | 判据 | 拦的回归 |
|---|---|---|
| V19.0 | 清单 ≥ 2 页 | 包结构退化成单页 |
| V19.1 | 延续段 `elementId` 存在且 == 层 `elementId` | 链接键丢失（播放器无法关联同一元素） |
| V19.2 | `offset ≥ 0` 且 `startMs == -offset` | 写成正起点 = 次页从头重播 |
| V19.3 | 延续段不在首屏 | 无源头的孤儿延续段 |
| V19.4 | 前一页存在配对源段（同 id/effect/duration/Props，`startMs = 页长 - offset`） | 源段被截断、Props 被预拆分（旧方案残留）、duration 漂移 |
| V19.5 | 页缝两侧求值差 ≤ 1e-6 | 任何导致页缝可见跳变的数据错误 |
| V19.6 | 页缝处进度 ∈ (0,1) | 夹具没真正跨页（判据形同虚设） |
| V19.7 | 至少一条延续段 | 夹具退回导致门禁空绿 |
