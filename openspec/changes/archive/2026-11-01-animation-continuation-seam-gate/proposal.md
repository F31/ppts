# 提案：跨页延续的页缝门禁（V19）

## 为什么做

`animation-cross-scene-continuation`（G8）已归档，但归档时对质量门禁的描述与实现有偏差，且夹具的接入
方式埋了一个假红风险。两者都属于「门禁看起来在守，其实没守住」的同一类问题：

1. **描述超前于实现**。归档进 `html-share-quality` 的条目叫「页取样门禁覆盖跨页延续」，写的是「在页缝处
   抽本页末帧与次页首帧，断言位置/不透明度连续」。实际落地的是求值器级单测（`web/animation-check.mjs`
   与 `shared/shots-check.mjs` 里的数值连续断言），**没有**任何门禁对真实成品包做页缝断言。
2. **夹具实际没进 CI**。`share-baseline` 的延续夹具当时挂在 `-layers` 上，且要求 `pageMs > 4000`；
   CI 造 V13b/V17 夹具用的是 `-page-secs 4`（恰好 4000），条件不成立 → **CI 里一条延续段都没有**。
   上一轮提交说明里「覆盖浏览器门禁（V17/V18）」因此是不成立的陈述。
3. **而且一旦页变长就会假红**。V13b 的判据是「页末帧 == 参照页图（终态）」，而延续元素在页尾必然处于
   中途态。把延续元素默认注入 `-layers`，等于给 V13b 埋了一颗「换个页长就红」的雷。

结论：需要一条**真正对成品包生效**的页缝门禁，并且把延续夹具改成显式 opt-in。

## 做什么

- `share-baseline` 增 `-continuation`（默认关）。开启时按编译器同构在相邻两页注入源段 + 负起点延续段；
  未满足前置（`-layers>0`、`-pages>=2`、页长 > offset）直接报错，不静默跳过。
- 新增 `scripts/review/seam-gate.mjs`（V19）：读**成品包**的 `manifest.json`，用与播放器/渲染器同一份
  `shared/motion.ts`，断言：
  - 延续段的 `elementId` 存在且等于所在层；
  - `continuationOffsetMs ≥ 0` 且 `startMs = -continuationOffsetMs`；
  - 前一页存在配对源段（同 `elementId` / `effect` / `durationMs` / `Props`，`startMs = 前一页页长 - offset`）；
  - 页缝两侧求值（前一页页尾 vs 次页 0 点）的 `opacity` / 位移 / 缩放差 ≤ 1e-6；
  - 页缝处元素确实处于中途态（否则说明这条 clip 没跨过页缝，夹具形同虚设）；
  - **包里一条延续段都没有 → 判红**（防夹具坏了门禁空绿）。
- CI 在浏览器门禁之后增两步：造 `-continuation` 包 + 跑 V19。

## 不做什么

- 不改 V13/V13b/V18 的判据与取样假设（延续元素不进入页末帧比对）。
- 不做像素级页缝比对：两侧求值在数学上应逐位相等，用求值器判据更严格、无截图抖动，且不依赖浏览器。
  像素比对本可作为补充，但它需要「同一元素跨两页的可见区域对齐」，成本高、假红来源多，收益不抵。
- 不改已归档的 G8 历史文档的结论，只在其 proposal 追加「实施结果（归档补记）」指明被取代的描述。
