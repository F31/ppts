# 设计：绑定预填的落点、分档与置信

## 1. 架构落点（已核实，不是推断）

绑定需要两侧输入：**元素文本**与**段落文本**。

- 段落文本来自讲稿分段（`segments[].text`），在 `animation.Revision` / `PageContext` 一侧可得。
- 元素文本只存在于 `project.Shape.Text`。**`render.Element` 只有 `{ID, Kind, Bounds}`，
  没有文本字段**（`internal/render/compile.go:35`）；`app.PageElements`
  （`internal/app/animation_geometry.go:105`）是唯一的「形状 → 元素」换算点，它拿得到
  `*project.Page`，但产出已经丢掉了文本。

结论：**绑定器 MUST 落在 `PageElements` 之上、编译之前**，输入是 `*project.Page` +
分段列表，输出是每条要绑定的元素的 `withSegment:<id>`。落在编译之后就只能拿到 ID 与几何，
规则里字面、数量词、序数三条全部失效。

这也是为什么绑定不能做成「渲染期特性」：渲染侧本来就没有文本。

## 2. 分档：先判版面有没有结构信号

同一套规则在结构化版面 0.972、纯文字页 0.533。硬套会得到一个「大概能填一半」的平均值，
掩盖掉可用与不可用的差别。因此预填 MUST 先做分档：

| 信号 | 检测方式（纯几何 + 文本形态，不调模型） | 命中后的规则 |
|---|---|---|
| 编号标记 | 页内存在 `01`–`99` 形态的短文本块，且 ≥3 个 | 序数规则（「第 N 条」→ 第 N 块）、数量词规则（「五个部分」→ 5 个编号块） |
| 卡片/分组 | 存在互相包含或上下紧邻（≤60px）且横向重合 ≥0.6 的元素簇 | 同块带出 |
| 方位指代可用 | 页内元素分布覆盖 ≥2 个方向区域且各区域非空 | 方位规则（「右边那张图」） |
| 无上述信号 | — | 只走字面 + 标题先验，并标记为**低置信预填** |

低置信预填 MUST 仍产出（否则纯文字页得到空轨道），但 MUST 在编辑器里以不同样式呈现，
让用户知道这批该多看一眼。

### 实现修正（落地时发现，回写进设计）

上表三条信号在真实讲义上的判别力**并不相等**，实现时按实测收紧了定档逻辑：

- 「方位覆盖 ≥2 个方向区域」几乎恒真：任何有元素的页面都会同时占住「左」和「上」
  两个半区，横竖都过 2 的门槛。把它放在 `or` 里，分档就永远返回「结构化」，
  纯文字页拿不到低置信标注——规格形同虚设。
  处理：方向覆盖仍然检测、仍然输出（`Result.Signals` 与 `DirectionCoverage`），
  但**不单独定档**；定档只看编号标记与卡片簇。
- 「上下紧邻 ≤60px」在兄弟规则里允许负 gap（同卡片内轻微重叠是常态），
  但在**分档**里要求 `0 ≤ gap ≤ 60`：同一行左右并排的两个文本框 gap 恒为负，
  放行的话任何一行并排文字都会被判成卡片簇，这条信号也就跟方向覆盖一样失效了。
  两个判据用途不同，不共用一个宽松口径。

分档不改绑定结果，只决定呈现形态，因此这次收紧不影响 2.6 的金标数字
（金标只算召回/精确，与 Band 无关）。

## 3. 置信度而不是硬阈值

现有阈值 0.12 是看分布定的，样本量不足以交叉验证。所以：

- 阈值继续用于「绑不绑」的判决（保持与实验一致，便于复现 0.972/0.962）；
- 但每条绑定 MUST 同时输出**连续置信度**与**来源**，编辑器按置信度升序呈现，
  用户先看最可疑的。

理由与「来源标注」相同：把复核成本从 O(全部) 降到 O(最可疑的那批)。

## 4. 对齐必须是单调 DP

`dp[i][j]` = 前 i 个元素只用到前 j 段时的最大相似度和。三种转移：段 j 空着 / 元素 i 不绑 /
元素 i 绑段 j。`bind` 分支不推进 j，所以一段可以连续带出多个元素。

不单调会怎样：逐个取最大值会把四行条目全绑到第一段（它们共享「本期」这类高频词），而且真实
讲解不会「讲到第三行又退回第一段」。这条约束不来自数据，来自「讲解是线性的」这一事实。

## 5. 确定性

预填 MUST 是纯函数：同一 `(project.Page, segments)` MUST 产出同一结果。MUST NOT 依赖随机数、
当前时间、网络调用或 map 遍历顺序。否则「重跑一次结果不同」会让用户对预填失去信任，
而信任一旦丢掉，预填就等于没有。

## 6. 与既有触发器语义的关系

预填只写 `withSegment:<segmentId>`，不写 `atTime:`。理由：分段时长会随讲稿修订变化，
绝对毫秒在改稿后就错了；相对引用由编译期解析（`resolveTrigger`），改稿后自动跟着走。

分段 id 不存在时的行为沿用既有实现（`DiagSegmentUnresolved`，起点退化为 0 并记诊断），
预填不另造一套降级逻辑。

## 7. 验收口径

单测数字不能代表成片。本变更的验收 MUST 包含：

1. **金标复现**：在 `sample-customer-deck.pptx` 的 1/2/4/8/10 页 + `q8-script.json` 上，
   Go 实现的召回（内容元素）与精确 MUST NOT 低于 0.972 / 0.962。低于即视为移植走样。
2. **字节不变**：无来源标注的既有规格，序列化与 `planHash` MUST 与引入前一致。
3. **带配音样片**：出 30s 级带音轨样片，逐段核对「讲到第 N 段时第 N 条才出现」，
   沿用 Q7 已有判据（开口前 400ms 内区域变化为 0）。静音样片测不了这件事。

## 8. 已知未定（不写进规格）

- 眉标/小标要不要被「同块带出」带进（`p1-s5` 一处口径分歧）；
- 图注要不要单独淡入（`p3-caption` 一处口径分歧）。

两处都需要第三份样本才敢定，本变更按现状（带出、白名单退掉图注）落地，不新增规则。

## 9. 入口与产物形态（实现时定的，回写进设计）

### 9.1 触发点是显式参数，不是默认行为

`GET /api/projects/{p}/slides/{s}/animation?default=true&prefill=true`。没有 `prefill=true`
时响应与产物和引入前**逐字节相同**（含 `prefill` 字段本身都不出现）。

为什么不默认开：预填会把整页从「按顺序错落淡入」换成「讲到哪条出现哪条」——产物形态
完全变了。默认规格是编辑器打开时的起点，静默换形态等于替用户做了一次不可见的编辑。

### 9.2 `Bindings` 的 nil 与空切片必须区分

`DefaultOptions.Bindings == nil` = 这次没做预填，走既有顺序分配；非 nil（哪怕零条）
= 做了预填，绑定说了算。合并成「有绑定就覆盖、没绑定就兜底」会让「一条都没绑上」与
「没做预填」产出同一份东西，前端和用户都无从区分。

### 9.3 没被绑定的元素保持静态

有绑定信息时不拿 `onEnter` 兜底。理由是预填的意义就是「出现时机由讲解决定」：
给未绑定元素一个页首淡入，等于插进来一个讲解没提过的出场，正是 Q7 判据 V5.4 要判红的行为。
代价是容器（卡片底、分隔线）从页首就在——那恰好是对的，它们本来就该在那里。

### 9.4 分段为空：跳过预填，但保留默认规格

没有讲稿就没有 `withSegment` 可锚，预填必须跳过，且 MUST 在响应里说清楚
（`prefill.applied=false, reason="no_segments"`）。这时产物退回既有的预设默认规格
（顺序错落 + `onEnter`），并且这些 clip 的 `triggerSource` 为空——它们不是预填产物，
不存在「用 `onEnter` 假装绑上了」。

这条是对规格里「MUST NOT 以 `onEnter` 兜底猜测」的口径澄清：禁止的是**冒充绑定**，
不是禁止「没有绑定信息时出一版默认编排」。后者是 M1 就有的能力，清空它只会让没有
讲稿的页面连预览都没有。

### 9.5 绑上了却没有轨道：预设的能力边界

真实样本上 53 条绑定只出 45 条轨道。差的 8 条绑在无文字容器上（来源 `structural`，
「容器跟着装着的内容走」），而预设的 `Clips` 不给这类元素挂动效。绑定成立、模板不存在。

不补一个兜底 clip：预设没定义过的元素用什么动效，是设计决定，不该由预填临时发明。
但它必须被数字钉住（`TestPrefillPipelineOnRealDeck`），否则「绑定数」会被当成「产物数」
的证据——这两个数在真实页上差 15%。


## 10. 编辑器的复核形态（实现时定的，回写进设计）

复核层落在 `web/src/animationPrefill.ts`（纯函数，`node --experimental-strip-types` 直接跑用例），
界面是 `AnimationEditor` 里的「预填复核」区块。下面五条是实现时定下来的语义。

### 10.1 排序改成「复核优先级」，不是纯置信度升序（偏差）

规格与 §3 写的都是「按置信度升序呈现」，落地时发现这条**在当前数据上不成立**：

`bind.Binding.Score` 的定义是字面相似度，非字面规则（计数 / 序数 / 方位 / 同块带出 /
标题先验 / 结构推断）恒为 0，代码里是刻意的——"硬塞一个数进去只会让人误以为可以排序"
（`bind.go` 的 `Binding.Score` 注释）。七条规则里六条的置信度都是 0，升序排出来是一堆
并列的 0，等于没排。

于是改成两级，理由都能落到具体行为上：

1. `sibling`（同块带出）最先：它是唯一会「一次带出一整片」的规则，锚点错一处就错一片。
2. 其余无字面依据的规则按固定顺序（先验 → 结构 → 计数 → 序数 → 方位），
   有字面依据的 `text` 按相似度升序，人工确认的 `manual` 最后。

同层按元素 id 兜底，保证同一份规格每次渲染顺序一致——复核表跳动会让人点错行。

呈现上把「无依据」与「0 分」分开：前者显示 `—` 并说明"该规则没有字面依据"，
后者才是真的低相似度。混成一个数就是让用户去核对一个并不存在的结论。

### 10.2 「撤销」撤销的是绑定，不是动效

撤销 = 触发器改回 `onEnter` + 清掉来源与置信度 + `startMs` 归零，**clip 本体保留**。

删掉 clip 的写法有两个问题：元素会失去入场，而界面里没有"加一条 clip"的入口，撤销就成了一次
不可逆的破坏；另外 `startMs` 不归零会让时间轴上的色块停在 `withSegment` 时代的错落位置
（280ms），而它实际上从页首开始——界面在说谎。

清掉标注之后落库结果是 `manual`：服务端 `ReconcileTriggerSources` 看到「旧来源是规则名 +
trigger 变了」，判定人已接手。这既满足"不保留原规则名"，也保住了「人撤销过」与「从来没人绑过」
的区别（后者才是空标注）。契约钉在 `TestReconcileRevokedPrefillBecomesManual`。

### 10.3 预填入口只在没有已保存规格时可用

预填产出的是「这一页的起点」，不是对现有绑定的合并。对已有规格跑一遍会整体替换人工确认过的
绑定，规格里的「人工权威」不允许。因此按钮在 `saved !== null` 时禁用，并把原因写在按钮下面。

代价是「已经存过一版顺序淡入、想改成按讲稿绑定」的用户没有入口。这是真实的限制，
但不给入口比给一个会静默覆盖的入口好——后者是"看起来能用、实际毁数据"。

### 10.4 换风格不丢绑定

换预设会整份重新生成。不搬绑定的话，用户刚复核完的几十条绑定、刚撤销完的判定，会因为
「换个风格」全部退回按顺序淡入——而用户点的只是"怎么出现"，不是"什么时候出现"。

`carryBindings` 只搬入场 clip（`onEnter` / `withSegment`）的 trigger 与标注，不搬 `atTime`
（那是时间轴上的显式定位，不属于绑定结论），也不搬 `startMs`（段内错落该按新预设的节奏）。
新预设里没有的元素自然丢失绑定——动效模板都不存在，绑定过去也无处落脚。

### 10.5 低置信标识只在生成当次可见（已知边界）

`band` 是**一次生成**的事实，不是规格字段。保存后再打开面板，只剩每条 clip 的来源与置信度，
低置信标识不再出现。要让它长期可见，得把分档写进规格（schema 变更）或每次打开重跑分类器
（等于第二套判断）。本变更不做，如实记在这里：重开面板时编辑器不声称任何分档结论。

## 11. 验收怎么做的（5.1 的像素证据）

规格里「讲到第 N 段时第 N 条才出现」是**时间关系**。单测能证明绑定写成了
`withSegment:<id>`，证明不了观众听到第 N 段开口时画面上到底有没有东西冒出来——
后者要成片、要音轨、要两边的时钟是同一个。所以 5.1 单独造了一条样片链路：

```bash
bash scripts/fidelity/prefill_sample.sh        # 约 4 分钟，产物在 tmp/prefill-sample
```

链路四段，每段都走产品代码：

| 段 | 用的东西 | 说明 |
|---|---|---|
| 配音 | `narrate.py`（edge-tts 逐段合成） | 段边界 = 拼接点，误差只剩编码器一帧；本样片复用 `tmp/q7` 的音频（5 页 35.5s） |
| 轨道 | `plan -prefill` → `animation/bind` + `animdefault.SpecFromElements` | 手写 bind 只能证明「按段起播能对齐」，这里要证的是**预填算出来的绑定**能对齐 |
| 成片 | `cmd/renderer`（Remotion 后端） | 底板与层图由服务端 staging 生成，见下面的坑 |
| 判据 | `check_speech_gate.py` | V20.1 开口前 400ms 无变化 / V20.2 不早于开口 / V20.3 不晚于开口 + 900ms |

### 11.1 为了验收新开的一个入口（`SpecFromElements`）

`animdefault` 原先只接受 `*project.Page`，而保真样片手里是 `elements.json`
（几何、类别、文本都有，没有 `project.Page`）。如果为样片另写一份「差不多的」
轨道生成，验的就是复制品，不是产品。于是把「元素清单」提为导出入口：

```go
func SpecFromElements(elems []Element, opt DefaultOptions) (*Revision, Report, error)
func DefaultSpecReport(page *project.Page, opt DefaultOptions) (*Revision, Report, error) // 包装
```

一致性由 `TestSpecFromElementsMatchesDefaultSpec` 逐字节钉住——两条入口只允许是同一条逻辑，
否则样片验到的东西与用户拿到的会悄悄分叉，而两边都不报错。

### 11.2 实测（2026-11-01）

18 条绑定（5 页），逐条：

- **preMax 全为 0.0**：开口前 400ms 的观察窗里，元素包围盒相对窗口首帧的平均绝对差是 0，
  即「开口前区域变化为 0」。编码噪声在 0.5–1.3，阈值 2.0。
- **delay 13–467ms**：13ms 是半帧（标题这类 0 错落元素落在一帧网格内）；
  180–467ms 是段内错落与 500ms 级淡入/生长的显形延迟，全部在 900ms 预算内。
- 18 通过 / 0 不过。

**负对照**：把每段的开口后移 400ms 再判，**16/18 被判成提前（0.89）**。
合格线定 80% 并列出漏网项（`p2-chart` pre=0.7、`p2-bar1` pre=1.1）：这两条是 500ms 级慢动画，
在「假开口」那一刻只走了 60–80%，灰度差还没越过阈值。收紧阈值能抓它们，但正常判据会开始误报——
量法在这里有精度上限，写出来比假装 100% 更有用。

### 11.3 一个必须记住的坑：别绕过 staging

第一版直接调 `renderer/render.mjs` 渲这份计划，18 条里 **11 条测不到出现**（onset=None）。
原因不是预填，是**底板**：计划里每层只说「从整页底图的这个框里裁一块」，底图原位置上的本体还在；
不生成底板，淡入的层只是把同一块图又叠了一遍，像素差恒为 0。底板由 Go 侧
（`RemotionBackend.stagePages`）生成，所以样片必须走 `cmd/renderer`。
这件事只有像素法能发现——单测、求值器、人工看片都会说「没问题」。

### 11.4 这个验收覆盖不到什么

- **真人讲稿**：样片用的是 TTS 合成的朗读，节奏均匀、没有停顿修正。真人讲稿下
  段内会有重读、插话，绑定的「讲到才出现」会更松。6.1 的重测要回答的正是这个。
- **只有一份样片**：5 页、18 条绑定。绑定器的召回归属 2.6 的金标（71 元素），
  不归这里；这里只回答「绑定成立时，画面是否守时」。
- **不进 CI**：需要 TTS 网络、Chrome、完整版 ffmpeg（Remotion 自带的那份没有 rawvideo 输出）。
  CI 能守的是轨道形状（`TestPrefillPipelineOnRealDeck`）与渲染器求值（seam-check）。
