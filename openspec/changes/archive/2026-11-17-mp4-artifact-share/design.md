# Design: mp4 成品分享

## 为什么放在 `html-share-distribution` 而不是新建能力

链接锚点、匿名有效性、口令 cookie、安全头与作者侧管理早已在这条能力里定义。
mp4 与 `html_bundle` 共用同一张链接表、同一套 token / 撤销 / 口令语义，差别只在
匿名端的交付形态。另起能力会把同一张表的约束抄两份，后续改撤销或口令时必然漂移。
能力标识保留 `html-share-distribution`：改名会让已归档变更的引用失效，收益只是命名好看。

## ADR-1：媒体流不走预签名 URL

分享链接的承诺是「撤销立即生效」。预签名 URL 一旦签发就只认签名与过期时间，
无法在撤销链接后立即失效。因此 `/s/{token}/media` 每次请求都回查链接行，
再按链接快照上的 `object_key` 取对象；对象键与租户前缀也在此校验。

代价是每次播放请求多一次链接查询，但视频请求量远低于静态切片，且撤销正确性
优先于这点读放大。

## ADR-2：只允许两个匿名落点

视频链接只认 `/s/{token}/`（入口页）与 `/s/{token}/media`（媒体流）。
不把 token 变成「可从对象存储取任意路径」的许可证；包内条目路径继续只属于
`html_bundle`。未知路径一律 404，与链接不存在同码。

## ADR-3：播放次数按「播放起点」记，不按请求数

Range 续传、拖动和浏览器预取都会产生多个请求。若逐请求记 `artifact_share.play`，
一次观看会被放大成几十次。判据固定为「无 Range 头，或 Range 起点为 0」，
只在播放起点写一条审计。

`resource_id` 用成品 ID 而不是链接 ID：成品库卡片一次 SQL 就能按成品聚合；
逐链接统计需要另建事件索引，且当前产品只承诺卡片播放次数。

## ADR-4：视频不提供逐链接进度统计

`artifact_share.view_event` 的四个进度桶由 share player 上报，视频播放页没有这层
埋点。`stats` 端点对 mp4 返回 400：返回空漏斗会让作者误读成「没人看完」，
比明确说「该格式没有分链接统计」更糟。

## 安全与缓存

入口页与媒体响应 `Cache-Control: private, no-store`；撤销后旧浏览器不能从缓存
重新打开。CSP 沿用 `/s/` 的统一收紧头，`media-src 'self'` 允许同源媒体。
播放审计沿用匿名埋点纪律：不记 token、IP、User-Agent。
