# 提案：页内镜头切片（Page.Shots）——先证明「一页多镜」缺的是底图，不是数据模型

## 为什么做

设计方案 §19.2 的 G3 是「Scene 与 Page 解耦」，现状写的是「页 = 场景（1:1）」，目标是三种形态：一页多镜、多页合一镜、插入过场卡。它在批次二排第一、优先级 P0。

但按字面去做「引入 Scene 模型」，会把**四件事同时解耦**，而它们现在是同一个 `Page`：

| 职责 | 现在的落点 | 证据 |
|---|---|---|
| 内容单元 | 一张底图（`BaseImage`，有动画时换 `PlateImage`） | `internal/render/ir.go:63-92` |
| 时间单元 | `DurationMs`：clip 的上界、focus 的区间、转场的参照 | `internal/render/compile.go:167`、`ir.go:80-91` |
| 渲染单元 | 一个 MP4 分段 | `internal/render/service.go:630`（`segment_%03d.mp4`） |
| 交互单元 | 页变即释放并重建全部层 | `web/src/sharePlayer/main.ts:388-400` |

这四件事牵动的下游各不相同：分段是片段缓存与页级并行的粒度（`animation-render-perf` 刚标定完 49.3s P95）；清单有游标必须首尾相接的硬校验（`internal/share/manifest.go:199-226`）；动画规格的 `Track.clips` 明文要求「页内相对时间」（`openspec/specs/animation-spec/spec.md:24`）；V13/V13b 的取样点都按页取。

一次动四件，风险不在于改不完，而在于**改完之后观感可能没变**——而这正是本项目已经踩过的坑（ADR-9：「保存成功、成片不变」）。

所以本变更先把缺口缩到最小，并验证一件事：**「一页多镜」的硬缺口到底在哪。**

答案在代码里已经很清楚：

- 一页内**多次元素运动**：已支持。`Page.Layers` 是数组，每个 `Layer` 有多个 `Motion`，时间是页内相对毫秒，focus 还能逐条压暗。设计文档举的例子（先出标题、再逐条出要点、最后收拢）今天就能做，不需要 Scene。
- 一页内**换底图**：不支持。`Page` 只有一个 `BaseImage`/`PlateImage`，且 `service.go` 按页切段。

也就是说，G3 里真正做不出来的只有「同一页里画面本身换了」这一类——典型是「全图 → 局部特写」「A 画面 → B 画面」。其余两种形态（多页合一镜、过场卡）在今天都有便宜替代：前者是相邻页 + 无转场，后者是单页 + 页间转场。

## 目标

在 `render.Page` 上增加**按时间切片的多底图**，不改任何既有的时间语义：

```go
type Page struct {
    // ... 现有字段不变
    Shots []Shot `json:"shots,omitempty"` // 空 = 今天的行为，字节级不变
}

type Shot struct {
    Index      int    `json:"index"`
    Image      string `json:"image"`      // 该镜头使用的底图
    PlateImage string `json:"plateImage,omitempty"`
    StartMs    int64  `json:"startMs"`    // 页内相对
    DurationMs int64  `json:"durationMs"`
}
```

配套：

1. **清单**：`SlideEntry.Shots`（可空，字段同构）。校验三条——首尾相接、总长等于页时长（±1 帧）、`shots` 非空时页级 `image` MUST 等于首个镜头的图（否则「第一个镜头」有两个说法）。
2. **播放器**：页内按 `us` 选当前镜头，底图 `src` 在镜头边界切换；层不重建（层的 clips 仍是页内相对时间，与镜头无关）。
3. **渲染端**：`Timeline.tsx` 同一页内按 `tMs` 选图，不做转场（镜头切换是硬切，淡入留给页间转场）。
4. **门禁**：V13b 的取样点在页尾，取到的是最后一个镜头；新增一条判据——多镜头页在**每个镜头的中点**取样，与对应镜头的源图比对（复用 `settled-gate.py` 的三条阈值）。

## 非目标

- **不做跨页时间基准**（G8 元素延续）。那要求 clip 的时间从「页内相对」改成「场景内相对」，会同时改 `animation-spec` 的 MUST、播放器的 `pageDurationMs` 归一与分段缓存键。它与本变更是两个量级，必须分开做、分开验。
- **不做相机（G7）**。平移/缩放是镜头属性，等 Shots 落地后挂在 Shot 上才有意义；现在挂上去没有消费者。
- **不改分段边界**。仍是一页一段，一页多镜不参与页级并行——记在非目标里，是因为有人会顺手改，然后片段缓存的键（含前一页）就会失效。
- **不做「多页合一镜」**。需要合并底图与时间轴，收益是省一次转场，成本是重排字幕与讲稿对齐。
- **不做「插入过场卡」**。单页 + 页间转场已经能表达，没有新缺口。

## 与既有变更的关系

- 依赖 `animation-track-editor`（已归档）定下的「页内相对时间」约定：本变更**不改**它，Shot 的 `startMs` 也是页内相对。这是本变更能与 G8 分开做的唯一理由。
- 与 `render-plan` 的「每页 MUST 携带 transition」不冲突：转场仍在页级，镜头切换不是转场。
- 与 `html-share-quality` 有一处需要复核：V13b 的前提是「终态帧 == 源页图」。多镜头页的「源页」是哪一张，必须写清——按本提案，是**最后一个镜头的图**，并在门禁里把取样点从「页尾前 250ms」改为「最后一个镜头中点」。

## 验收（可执行，先写判据再写代码）

1. **向后兼容**：现有 2 页夹具包一字不改重跑，V13 逐页最差与 V13b 三项指标与今天同量级（0.9968 / 0.99994 / 平均差 0.002），且包字节里不出现 `shots` 字段。
2. **新能力**：造一份 2 页样例，第 1 页含两个镜头（0–2000ms 全图、2000–4000ms 局部图）。探针在 1990ms 与 2010ms 各读一次当前 `image.src`，必须分别是两张不同的图——**这是本变更唯一能证明「功能真的存在」的判据**，其余都是它成立之后的顺手检查。
3. **清单校验**：shots 留空洞、重叠、总长与页时长差 >1 帧，三种都要在打包时失败并指出页码与毫秒。
4. **两端一致**：多镜头页在镜头中点，播放器 DOM 与该镜头源图的 SSIM ≥0.995（沿用 V13b 阈值），渲染端同帧 SSIM ≥0.95（沿用 V13 阈值）。

## 已定（2026-10-31，三条都选了）

1. **切换用 120ms 叠化**。与页间 `fade` 同一套语义（挂后一镜开头、`easeOutCubic`），实现只复用不发明。代价是切点前后约 7 帧是混合态，门禁取样必须避开——细则见 `design.md` 第 3 节。
2. **一页最多 4 个镜头**（写入校验，超了打包失败）。超过 4 个就不是切镜，是把一整段剪贴进一页。
3. **特写图由渲染侧产 2x**。现状是 LibreOffice 整页栅格化、只有 `DPI` 参数、产物 150 DPI，没有区域能力；做法是对有特写的页用 300 DPI 重渲一次再按 `Crop` 裁切，成本是「每张有特写的页多一次 soffice」，不是全片翻倍。这一组排在最后，因为它只影响清晰度，前四组做完功能就已经可用（届时先用现有页图裁切，会糊，已知）。

## 仍然没定的

- 特写镜头内是否允许元素动画。`design.md` 第 4 节按「不允许」写（层坐标是整页坐标，放大后必然错位，而错位不报错），若将来要把层也按 `Crop` 重映射，那是另一个变更。
