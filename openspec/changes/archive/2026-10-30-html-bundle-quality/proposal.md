# 成品包质量门禁（M6-4）

## 为什么

M6-1 让成品包**能播**，M6-2 让 DOM 与 MP4 **同帧一致**，M6-3 让成品**能分享**。三件事都有对应的验证，但验证的形态各不相同：M6-2 有 `dom-ssim.py`，M6-3 有一批 Go 用例，而「包本身有没有坏」只靠人打开看。

这留下四个无声的失效模式，共同特征是**没有人在导出时发现**：

| 失效 | 怎么发生 | 谁会发现 |
|---|---|---|
| 包里出现外链 | 播放器或模板被引入一个 CDN 字体/jsDelivr，本地开着网看不出差别 | 断网的客户 |
| 体积悄悄翻倍 | 某次改动让页图从 JPEG 转 PNG，或层图不再合并 | 发邮件时被拒的人 |
| 某个资源 404 | 清单里写了一个打包器没写出的文件名 | 打开看到白屏的客户 |
| 降级路径崩了 | 无 WAAPI / 禁 JS / reduced-motion 三条路径平时没人走 | 旧 Safari 或企业内网用户 |

`dom-ssim.py` 只覆盖第一项的一半（它比的是画面，而外链、404、降级都不一定改变同一时刻的画面）。本变更把 V14/V16/V17 做成可执行门禁，并把 V15 的体积口径量化。

## 目标

1. **V14 自包含性**：包里所有 `src` / `href` / `url()` 解析后必须落在包内，外部引用数 = 0。打包时自检（不产出坏包）+ 门禁脚本（不放过旧包）两处同规则。
2. **V16 可播放性**：无头浏览器真实加载 → 清单引用的每个资源都能取到 → 音频 `duration` 与清单一致 → seek 到末尾后 `play()` 能走到 `ended` → 全程无 console error、无资源加载失败。
3. **V17 降级矩阵**：禁 JS / 无 WAAPI / `reduced-motion` / 低内存四种条件各有自动化用例，且「可读」有可判据（不是"没报错"）。
4. **V15 体积**：给出构成明细（页图 / 层图 / 音频 / 播放器 / 清单）与按片长推算的预算判定。
5. 四项都能在 CI 与本机一条命令跑完，不引新依赖。

## 非目标

- **不做 V18 埋点**（首帧曝光、25/50/75/100% 进度、来源上报）：需要先定「哪些算一次观看」「隐私模式下关到什么程度」，属产品口径。
- **不做字体子集 / WebP / AAC 转码**（V15 的后半段）：字体要有 OFL 资产与许可声明，WebP 要确认浏览器矩阵，AAC 要引编码器。当前包不内嵌字体（用系统字体栈），所以「字体子集覆盖率」这条判据在本实现下不成立——这一点会写进门禁报告，而不是假装验过。
- **不改播放器的时间语义**（M6-2 已定：音频是权威时钟）。
- **不做移动端真机矩阵**：无头 Chrome 覆盖不到 iOS Safari 的自动播放策略。
- **不把门禁接进 CI 的必跑集**：需要 docker + 渲染镜像，仍是手动/发布前跑（与 `dom-ssim.py` 一致）。

## 与既有权衡的关系

- **V13 已完成**（M6-2 的 `scripts/review/dom-ssim.py`，逐页最差 0.99357）。本变更不重复实现，只在门禁文档里把它与 V14/V16/V17 并列，形成完整的 V13–V17 执行清单。
- **降级语义沿用 M6-2 的决定**：`reduced-motion` 去掉位移缩放、保留 opacity、**时长不变**。本变更只补「禁 JS」与「低内存」两条，并给四条都写用例。
- **体积基线沿用 M6-2 实测**（5 页 / 30 秒无音轨 669 KB）。本变更补的是「有音轨时」的构成与预算公式。
