# 设计：导出接线与逐页动画编辑（M3）

## ADR-21 动画通道的失败止于「降级」，不进入 `classifyEncodeError`

**决策**：`renderMP4` 里动画通道的调用被包在一个独立的 `tryAnimation` 里，它只返回
`(segments, degraded, err)` 三态：

| 返回值 | 含义 | 后续 |
|---|---|---|
| `segments` 非空、`err == nil` | 正常 | 走拼接 |
| `segments` 为空、`err != nil` | 服务不可达 / 全片失败 | 记录降级，**继续走静态路径** |
| `segments` 部分、`degraded` 非空 | 个别页失败 | 拼接时该页换静态段，成片标注页码 |

**理由**：`classifyEncodeError` 的语义是「静态编码失败，用户该重试或该报错」。动画是增强层，
把它的错误塞进同一个分类器，等于让「渲染服务抖一下」变成「导出失败」——正是 §8.8 明令禁止的。

**代价**：降级是静默的，用户可能不知道自己拿到的是静态版。所以必须有一条可观测的出口：
`animation_degrade_total{stage}`（§11.3）+ 成品行上的 `degraded` 标记，前端据此提示。

## ADR-22 拼接优先 `-c:v copy`，失败才整片重编码

**决策**：分为三条路径，按代价从低到高：

1. **无字幕**：`-f concat -safe 0 -i list.txt -c:v copy`。不重编码，5 分钟片秒级完成。
2. **有字幕**：无法 copy（`-vf` 与 copy 互斥）→ 解码后 `-vf ass=...` 重编码全片。
3. **copy 失败**（分段参数不一致、时间基不连续）：回退到路径 2 的重编码，并记录原因。

**为什么能 copy**：分段由同一后端、同一 `renderProfile`（分辨率 / fps / 编码参数）产出；
单页降级段也由**同一套编码预设**生成（libx264 / yuv420p / 同 fps / 同尺寸），而不是随便找个
ffmpeg 默认参数转一张图——否则 copy 会在某个分段上静默产出坏片。

**输入选择**：`-map 0:v:0` 只取视频流。分段来自渲染服务时无音轨；降级段由 `Encode` 生成，
带一条 `anullsrc` 静音轨——不显式 `-map` 会把这条静音轨也拼进去，最后整片「有声音但全是静音」。

**已知边界**：concat demuxer 不校验每段时长是否等于计划时长。若某段偏短/偏长，成片会整体漂移，
且 ffprobe 的总时长仍可能落在容差内。因此拼接前逐段 ffprobe，累计偏差超 100ms 即把**该页**
改为静态段（静态段时长由我们控制，能精确补齐）。

## ADR-23 单页降级的替换单元是「静态段」，不是「跳过该页」

**决策**：单页失败时，用该页的静态图编码成一段与动画段同参数的 mp4（时长 = 该页计划时长），
替换该段后继续拼接。

**理由**：跳过该页会让成片比时间轴短，音频与字幕整体前移——用户拿到的是「音画不同步」，
比多一张静态图糟得多。替换则保持时间轴逐页对齐这一不变量。

**代价**：该页没有任何动画（用户能看到「这页突然不劲了」），所以必须能告知是哪一页。

## ADR-24 分段按清单下载：`GET /v1/render/{id}/artifacts/{name}`

**决策**：给渲染服务补一个产物下载端点；客户端 `DownloadArtifact` 流式写入本地文件，
显式比对 `Content-Length`。

**为什么必须补**：M2 的契约只有 `GET /v1/render/{id}` 返回 `artifacts`（一串文件名），
没有任何取字节的途径。M3 一接线就撞上：分段名字拿到了，内容留在渲染容器的
`/work` 里，而那个目录 `read_only: true` + `tmpfs`，外部无法挂载读取。

**可见性只有一份**：可下载集合 = `JobStatus.Artifacts`。工作目录里的其它文件
（终态后才写入的残留、清理脚本产物）一律 404。清单里有而盘上没了，同样 404——
对调用方来说这与 TTL 到期没有区别，都该降级而不是重试到底。

**为什么不信 `Content-Length` 之外的东西**：截断的分段能过 `ffprobe`（它只看头），
也能过 concat（按时间基切），最终表现成「某一页黑屏」。所以在下载阶段就比对字节数，
失败即删掉半成品——半个 mp4 留在目录里会被下一轮拼接当成有效分段。

## 未决：底图投递（2.3 的前置）

渲染服务只从自己的 `-assets-dir` 读 `baseImage`（ADR-14），而页面 PNG 在对象存储里。
两者之间目前**没有通路**：渲染容器 `network_mode: none`，compose 里 `/assets` 挂载
仍是注释状态（`deploy/renderer/compose.yml`）。

两条候选路线，需要按部署形态拍板，而不是在代码里猜：

| | 做法 | 成立条件 | 代价 |
|---|---|---|---|
| a | 共享卷 + 路径映射 | 单机部署、对象存储是本地盘 | S3 后端不成立；路径成为部署契约 |
| b | `PUT /v1/assets/{path}`，导出侧推页图 | 任意后端 | 每次导出多一次上传；资产需要 GC |

本变更的 2.2 因此**只接受调用方已解析好的 `BaseImage`**，不在编排层偷偷做投递。
这样 2.3 可以用「资产根里已有页图」跑通链路，而投递机制的选型摆在明面上。

**2.3 的收敛方式**：把这条通路收成单一的接缝 `app.AnimationRequestBuilder`
（输入：快照 + 时间轴 pages + 已读入的页图；输出：`AnimationRequest`）。
适配器未注入 = 不探测、走静态。这样选型从「阻塞 M3」变成「插一个实现了
`Publish` 语义的函数」——a 方案是拷贝到共享卷，b 方案是 `PUT /v1/assets`，两者都落在这一个函数里。

**另一个同源前置（2.0b，本轮才发现）**：`AnimationPage.Elements` 需要元素的 EMU 框，
而导出路径只有页图与时间轴。几何在 `project.reader.go` 的 `Bounds` 里已经拿得到，
但解析阶段没有把它持久化（`PageEntry` 只有 `slideId/index/key`）。两条路——
解析期落 elements 产物（一次成本），或导出期重解析源 PPTX（零存储、每次多一次解析）。
没定之前，动画段只能编出整页静态画面，与静态版等价，所以不做。

两者都落在同一个接缝上，所以 M3 的接线可以先完成并验证，生产行为在适配器注入前保持静态。

## 拼装顺序

```
spec ─compile→ IR ─submit→ renderer ─segment_NNN.mp4→ ┬─ 逐段 ffprobe + 偏差校验
                                                      ├─ 失败页 → 静态段替换
                                                      └─ concat → 混音 → 烧字幕 → 产物
```

## 开关与零副作用

| 开关 | 作用域 | 默认 | 关闭时的行为 |
|---|---|---|---|
| `animation.enabled` | 租户 | false | 导出界面不出现动画选项；`renderMP4` 走原路径 |

**零副作用的定义**：开关关闭时，`ExportSnapshot` 的序列化结果必须与今天逐字节一致
（否则 snapshotHash 变、历史产物全部 miss、幂等键失效）。动画相关字段只能是
`omitempty` 且默认零值——这是本变更最容易踩的隐形回归，需要一条快照哈希的回归用例。

落地后补的三条实现约束（都不是显而易见的那部分）：

1. **字节只有一个来源**：`app.SnapshotBytes` 同时被 Connect 入口、REST 入口与导出步骤使用。
   三处各写一遍 `json.Marshal` 的话，只要有一处加了规整，存进任务的载荷与算出的步骤键
   就会对不上，表现成「幂等重试又创建了一个任务」。
2. **空动画选项归一到无动画**：`&AnimationOptions{}` 与 `nil` 同键。两者都不渲染动画、
   产物同源；不归一就会让同一份静态视频在成品库里出现两份。
3. **"字段放末尾"是个错误的心智模型**：真正的约束是「零值必须被省略」。实测把 nil 指针
   字段插到 `fps` 与 `burnSubtitles` 之间，字节不变；只去掉 `omitempty`，字节立刻变
   （`"animation":null`）。用例守的是后者。

## 风险

| 风险 | 缓解 |
|---|---|
| 分段与静态段参数不一致 → copy 出坏片 | 降级段复用同一编码预设；copy 失败自动重编码 |
| 渲染服务版本漂移 | 调用前 `/healthz` 比对 `schemaVersion`，不符则不调用（§11.5） |
| 动画通道拖长导出时长 | 单页 60s 超时 + 全片上限；超时即降级，不重试到底 |
| 开关关闭仍有行为差异 | snapshotHash 快照用例（见上）；另一条：关闭时渲染服务请求计数必须为 0 |
| 降级静默，用户与运维都不知道「哪几页没动」 | `Degraded`/`Drifted` 逐页留痕 + 成片后一条 warn（成品行暂无字段，见 tasks 2.4） |
| 逐页编辑器改动破坏讲稿编辑 | 复用 `scriptState` 的草案/冲突模式，不新建状态机 |
