# 提案：镜头相机（Shot.Camera）——在已落地的页内镜头上叠加平移/缩放运动

## 为什么做

设计方案 §19 批次三的 G7 是「相机/镜头」：平移、缩放聚焦、跟随。已归档的
`animation-page-shots` 在 proposal 里**显式 defer 了 G7**，理由原文是：

> 不做相机（G7）。平移/缩放是镜头属性，等 Shots 落地后挂在 Shot 上才有意义；现在挂上去没有消费者。

`animation-page-shots`（G3-5）现已合并：`render.Shot` / `share.SlideShot` / 浏览器 `Shot`
三处都有 `crop` 静态特写，播放器 `syncShot` 已能按镜切换底图。G7 的「消费者」已经存在——
**现在挂相机上去，镜头会从「静态特写」变成「可运动的特写」**。这正是 deferral 当时等的条件。

§19（1556 行）给相机的实现映射是：`camera` 关键帧 → 画布变换 → 外层容器 `transform` +
`overflow:hidden`。本提案据此落地。

## 目标

在「页内镜头切片」之上，给镜头增加**镜内相机运动**（Ken Burns 式的平移/缩放），使「全图 →
特写」之后还能在特写上缓慢推近/平移，观感从「切一下」升级为「镜头在动」。

三条设计取舍（在 `design.md` 落死）：

1. **相机增强特写（crop），不独立作用于整页**。v1 的相机镜头 MUST 同时声明 `crop`——
   相机在特写图内部做平移/缩放。这样做有两重用意：(a) 特写图已走 300 DPI（`animation-page-shots`
   的 2x 路径），相机放大不会立刻糊；(b) 绕开了「相机只变换底图、而层是独立 DOM 不跟随」的错位——
   有 `crop` 的镜头本就隐藏层（`main.ts:380`），相机镜头沿用这条规则。
2. **坐标用镜头图局部归一化**（`x/y` ∈ [0,1] 视口中心，`scale` ≥ 1 相对「图覆盖舞台」）。
   归一化是分辨率无关的，同一份 IR 直接喂给浏览器与合成器两个后端，符合 `render-plan`
   的「IR 只含可插值数值」原则；也避免再走一遍 EMU→画布换算。
3. **无相机 = 当前行为**。相机是可选字段，缺省时画面 MUST 与引入本提案前逐像素一致。

## 范围

### IN
- `Shot` 增加可选 `camera` 关键帧序列（IR / manifest / 浏览器三处对齐）。
- IR 编译：`compileShots` 把相机关键帧**原样透传**（归一化，无需 EMU 换算）。
- 播放器：在 `syncShot` 里按镜内时间插值相机变换，应用到镜头图元素；舞台 `overflow:hidden` 裁剪。
- 校验：相机 `scale ≥ 1`（否则缩放后镜头图盖不住舞台、边缘露白）；门禁 V 系列与 `bundle-gate` /
  `shots-check.mjs` 容忍新增可选字段。

### OUT（本变更不做，留给后续独立 change）
- **G8 跨场景元素延续**：要把 clip 时间从「页内相对」改成「场景内相对」，改 `animation-spec`
  的 MUST、播放器 `pageDurationMs` 归一与分段缓存键，两个量级的大重构，必须独立成 change。
- **相机作用于整页镜头 + 层跟随**：v1 相机只增强特写（crop）。整页镜头上的相机需要层也跟着
  变换（层是独立 DOM，不随底图 transform），属另一项工作。
- **「跟随」运动（follow 一个移动的元素）**：需要逐帧的元素世界坐标，当前 IR 不携带，留给后续。
- **帧渲染器（MP4）侧的相机合成**：IR 会携带相机关键帧，但 v1 只在 HTML 播放器实现；
  帧渲染器未实现相机时退化为静态特写（不阻断导出）。帧渲染器侧的相机是后续 change。

## 验证纪律

合并门禁：`go build ./...` / `go vet ./...` / `go test ./...`（含相机插值的 Go 单测）、
`tsc -b` / `vite build`（含 `internal/share/assets/app.css` 同步重建），以及播放器相机变换的
纯函数单测（与 Go 侧同语义）。门禁 V 系列（V13/V13b/V16/V17/V18）关于镜头切换与层重建的判据
**不受影响**——相机是镜内运动，不触发切镜、不重建层。
