# html-share-quality Specification

## Purpose
定义「HTML 成品包」在交付前必须通过的质量判据：自包含（V14）、体积预算（V15）、真实浏览器可播放（V16）、四条降级路径可用（V17）、画面与源页一致（V13b）、两端画得一样（V13）。目标是让「包有没有坏」变成一条可执行的命令，而不是靠人打开看一眼——外链、体积翻倍、资源 404、降级失效、画面画错、两端分叉这六类问题在导出时都不会报警，只会在客户打开时暴露。

## Requirements

### Requirement: 外部引用数为零

成品包 MUST 自包含。包内所有文本资源（`index.html`、`app.css`、`app.js`、`manifest.js`、`manifest.json`、`subtitles.js`、`timeline.json`）中出现的 `src=`、`href=`、`url(...)`、`@import` 目标，MUST 全部解析为包内相对路径。MUST NOT 出现 `http://`、`https://`、协议相对 `//host`、`file:` 绝对路径或包外绝对路径。

打包时 MUST 自检并在违规时失败（不产出坏包）；门禁 MUST 对**产物目录**再扫一次。

#### Scenario: 打包时拒绝外链

- **WHEN** 某条模板或播放器产物中出现 `https://cdn.example.com/font.woff2`
- **THEN** 打包 MUST 失败并指出违规条目与片段，MUST NOT 生成该包

#### Scenario: 门禁扫描产物

- **WHEN** 对一个已知自包含的包运行 `bundle-gate.py --skip-browser`（只跑 V14/V15）
- **THEN** 外部引用数 MUST 为 0；若被人为往 `index.html` 里插入一个 CDN `<script src>`，扫描 MUST 报出该条

#### Scenario: 协议相对 URL 也算外链

- **WHEN** 出现 `src="//cdn.example.com/a.js"`
- **THEN** MUST 判定为外部引用（`//` 会被浏览器解析成当前协议下的外部主机）

### Requirement: 可播放性由真实浏览器验证

门禁 MUST 用无头浏览器加载成品包并验证：播放器挂载成功、清单引用的每个页图/层图/音频/字幕资源都能取到（无 404、无解码失败）、音频时长与清单 `artifact.durationUs` 之差 ≤ 0.25 秒、seek 到末尾后 `play()` 能触发 `ended`、全程无 console error 与资源加载失败。

验证 MUST NOT 修改被验的包；需要注入探针时 MUST 在临时副本上进行，并在前后比对原包哈希。

门禁 MUST 在每次 push 与 PR 的 CI 中执行。浏览器 MUST 由门禁自行解析（`PPT_CHROME` 优先，其次平台常见路径，最后才是渲染镜像），MUST NOT 要求先构建渲染镜像才能运行。环境里确实没有可用浏览器时，门禁 MUST 以退出码 2 失败并说明缺什么，MUST NOT 静默跳过、MUST NOT 记为通过——「没跑」与「跑了通过」在报告里必须是两件事。

#### Scenario: 样例包必须带图层

- **WHEN** 用不带 `-layers` 的包跑门禁
- **THEN** 降级判据 MUST 失败，MUST NOT 悄悄通过——四条判据全落在 `.ppts-layer` 上，
  没有图层的包既验不出降级

#### Scenario: 正常包通过

- **WHEN** 对一份 5 页 / 30 秒 / 含混音轨的包运行门禁
- **THEN** 报告 `mounted=true`、`resources.failed=[]`、`ended=true`、`consoleErrors=[]`，判定通过

#### Scenario: 资源缺失必须失败

- **WHEN** 副本中删除清单引用的某张层图
- **THEN** 门禁 MUST 失败并把该路径列入 `resources.failed`，MUST NOT 因为「画面看起来还行」而通过

#### Scenario: 探针不能靠内联脚本

- **WHEN** 需要注入检测脚本
- **THEN** MUST 以同目录外部 `.js` 文件引入（产物 CSP 为 `script-src 'self' file:`，内联会被拒绝）

#### Scenario: 环境里没有浏览器

- **WHEN** 运行环境既没有 Chrome，也没有可用的渲染镜像
- **THEN** 门禁 MUST 以退出码 2 结束，并说明「设置 `PPT_CHROME` 或提供镜像」
- **AND** MUST NOT 输出「PASS」——没有执行过的判据不得计为通过

#### Scenario: 样例包不带图层

- **WHEN** 用一份所有页都 `layers` 为空的包跑门禁
- **THEN** 「默认态存在位移」「无 WAAPI 时层为终态可见」「reduced-motion 时长不变」等判据 MUST 失败
- **AND** 报告 MUST NOT 因为「本来就没有层」而把这些判据判为通过

### Requirement: 降级矩阵逐条可执行

以下四种条件 MUST 各有自动化用例，且判据为「页面可读」而不是「没有抛错」：

| 条件 | 判据 |
|---|---|
| 禁 JS | `noscript` 内页图数量 ≥ 页数、每张 `naturalWidth > 0`、讲稿文本非空 |
| 无 WAAPI | 层元素 `transform` 为 `none`、`opacity` 为 `1`（终态可见） |
| `prefers-reduced-motion: reduce` | 层 `opacity` 仍随时间变化、无位移/缩放、动画时长与默认态一致 |
| 低内存（`deviceMemory < 4`） | 不创建层元素，页面仍渲染当前页与字幕 |

#### Scenario: 禁用 JavaScript 仍可读

- **WHEN** 以禁用脚本的方式打开成品包
- **THEN** 页面 MUST 呈现标题、逐页静态图与对应讲稿文本，MUST NOT 只显示一句「需要启用 JavaScript」

#### Scenario: reduced-motion 不改时长

- **WHEN** 浏览器声明 `prefers-reduced-motion: reduce`
- **THEN** 位移与缩放 MUST 被去掉，`opacity` MUST 保留，动画总时长 MUST 与默认态相同（缩短会造成音画错位）

### Requirement: 体积构成可测量

打包器 MUST 能给出成品包按类别（页图、层图、音频、播放器、字幕、清单）的字节数与动画页数。门禁 MUST 按 `3 MiB + 0.55 MiB/分钟` 判定预算，超预算时 MUST 告警并列出构成明细，MUST NOT 静默通过。

门禁报告 MUST 明确标注未实现项（字体子集、WebP、AAC），MUST NOT 对未实现项给出「通过」。

#### Scenario: 报告可定位超标项

- **WHEN** 包体积超预算
- **THEN** 报告 MUST 给出各类别字节数与占比，使人能判断是音频大、页图大还是层图未合并

#### Scenario: 未实现项不得伪装通过

- **WHEN** 包内没有内嵌字体（当前实现的常态）
- **THEN** 「字体子集覆盖率」MUST 标注为 `not_applicable`，MUST NOT 记为 `pass`

### Requirement: 门禁报告的引擎可追溯

门禁输出（人类可读与 `--json` 两种）MUST 记录本次判定所用的引擎（`native` / `docker`）与浏览器路径或镜像名。同一份包在不同浏览器上判出的结果不同时，读报告的人 MUST 能立刻看出是哪一次、哪个浏览器判的。

#### Scenario: 两条引擎路径

- **WHEN** 同一份包分别用本机 Chrome 与渲染镜像跑门禁
- **THEN** 两次报告 MUST 各自写明引擎与浏览器版本/镜像名，判据条目与阈值 MUST 完全一致

### Requirement: 终态帧与源页一致

成品包在每一页的取样时刻画出来的那一帧，MUST 与**这一帧该有的参照图**一致。参照图不是随手取的一张：无页内镜头时是源页图；有页内镜头时，末镜 `crop` 为空取源页图（此刻层仍可见，镜头图只是底板），`crop` 非空取包内那张镜头图（此刻层被隐藏，画面就是它）。

判据 MUST 同时满足三条：SSIM ≥ 0.995、平均差 ≤ 0.5、差 >32 的像素占比 ≤ 0.05%。三条不是三个宽松近似，而是同一条等式的三种投影：平均差抓整体色偏，结构性差异占比抓局部错位，SSIM 抓纹理与边缘。判据 MUST NOT 依赖渲染服务或成片——只需要一个浏览器。

取样 MUST 落在该页最后一个镜头内、且避开叠化窗口：取「末镜起点 + `crossFadeMs` + 1 帧」与「页尾前 250ms」中更靠后的一个，并夹在末镜之内。理由是末镜可能比 250ms 还短（页尾前 250ms 会落到上一镜），而中点又可能落在叠化里（120ms 叠化 + 100ms 镜头）。门禁 MUST 把实际落点读回来与请求比对：偏差 >50ms 即判失败，而不是拿一张拍错时刻的图去比。

参照图与舞台尺寸不同时（特写图是原页的一块，宽高比通常与画布不同），参照图 MUST 先缩放到舞台尺寸，并 MUST 换一组阈值（SSIM ≥ 0.99、平均差 ≤ 1.0、结构差异仍 ≤ 0.05%），MUST 在报告里标注该页是「参照图缩放」。实测该情形下正例 0.9972 / 0.49，右移 40px 掉到 0.9497 / 3.66，拿整页图当参照掉到 0.6900——三档拉得开，不是随手放宽。

末镜换了整页图、而这一页又带元素动画时，画面是「镜头图 + 层」，包里没有可比的无层参照图：这类页 MUST 报 skip 并写明原因，MUST NOT 拿残图去比、MUST NOT 计入通过。skip 不影响退出码，但 MUST 在报告里出现——静默通过的页会让人以为它被验过。

#### Scenario: 正常的包

- **WHEN** 用 `share-baseline -width 1280 -height 720 -layers 2 -pages-out` 造包并跑门禁
- **THEN** 每页 SSIM ≈ 0.9999、平均差 ≈ 0.002、结构性差异 0.000%，门禁通过

#### Scenario: 末帧是特写

- **WHEN** 用 `-shots 2` 造包（末镜 `crop` 非空），层在该镜内被隐藏
- **THEN** 取样落在末镜内且避开叠化，参照物是包内镜头图，SSIM ≈ 0.99994

#### Scenario: 特写图比舞台小

- **WHEN** 末镜图是 640×360，舞台是 1280×720
- **THEN** 参照图 MUST 缩放到 1280×720 后比对，报告 MUST 标注「参照图缩放」，阈值换成 0.99 / 1.0 / 0.05%

#### Scenario: 图层框错位

- **WHEN** 把清单里某个图层的 `box.x` 右移 40px（层图随之错位，页图上露出未覆盖的空洞）
- **THEN** 该页结构性差异 0.52% > 0.05%，门禁失败并指出是哪一页、哪条指标

#### Scenario: 底板颜色偏了

- **WHEN** 把包内底板 PNG 的每个通道 +10
- **THEN** SSIM 0.960 < 0.995 且平均差 9.6 > 0.5，门禁失败

#### Scenario: 定位失效

- **WHEN** 播放器的定位接口被改坏，实际落点与请求相差 >50ms
- **THEN** 该页判失败，报文指出是定位问题；MUST NOT 继续拿错帧比对

#### Scenario: 末镜换图且该页有元素动画

- **WHEN** 末镜的 `image` 不是页级图、`crop` 为空、该页 `layers` 非空
- **THEN** 该页 MUST 报 skip 并说明「画面 = 镜头图 + 层，包里没有可比的无层参照图」，退出码不受影响

### Requirement: 比对范围与尺寸前提

比对范围 MUST 是播放器的舞台（`.ppts-stage`）矩形，MUST NOT 假定「截图就等于画面」——播放器有圆角、边框与控制条。

截图前 MUST 摘掉封面按钮与字幕条。它们各有自己的守卫（V16 验封面能被点掉、字幕由播放时钟的判据守），留在画面里会把判据淹没在外壳噪音中（实测平均差 28 对 0.002）。

舞台 MUST 定成**源页自己的尺寸**，判据 MUST NOT 掺入重采样：实测同一份包 1:1 为 0.99994、0.667 倍为 0.969——放宽阈值会让「画错了」和「只是缩放了」混为一谈。

播放器卡片的 1280 宽度上限是**网页嵌用的策略**，不是画面的性质：层位置按画布百分比落位，去掉上限只是让同一页按原生尺寸再画一遍。因此截图前 MUST 去掉这道上限，并 MUST 把实测舞台与目标尺寸比对（差 ≥0.5px 即失败）。

舞台与参照物对不上时，门禁 MUST 以退出码 2 结束并报出实测值与期望值，MUST NOT 缩放后照常判、MUST NOT 报成画面不合格——后者会让人去查渲染，而问题在材料上。

#### Scenario: 1920 的页不再需要缩到 1280

- **WHEN** 包与源页都是 1920×1080
- **THEN** 舞台 MUST 为 1920×1080，终态帧与源页的平均差 ≈ 0.0007（不是 0.667 倍缩放后的 0.969）

#### Scenario: 包与页图不同尺寸

- **WHEN** 拿 1920×1080 的包去比 1280×720 的页图
- **THEN** 门禁 MUST 以退出码 2 结束并说明「包与页图不是同一尺寸」，MUST NOT 报成画面不合格

#### Scenario: 舞台矩形

- **WHEN** 包与源页均为 1280×720
- **THEN** 门禁取到的舞台矩形 MUST 是 1280×720（不是 492×344），比对 MUST 在这块矩形内进行

### Requirement: 两端同帧一致（V13）可在没有渲染镜像的环境里验证

成品包在某一时刻画出来的画面，MUST 与成片同一时刻的解码帧一致。取样 MUST 同时包含**动画进行中**的时刻（第一段 clip 的中点）与页首、页尾；只看末帧会在动画早已结束的静态页上拿到 0.99，什么都没验。

页内声明了镜头切片时，取样 MUST 另含**每个切点之后**的时刻，取 `startMs + crossFadeMs + 1 帧`。不取切点本身：混合窗口只有 120ms，两端时钟差 20ms 就会让同一时刻的颜色不同，那个差会被记成「两端不一致」，其实只是取样时刻不同。

判定 MUST 用逐页最差帧：一页里任一取样点不达标即判该页失败，MUST NOT 用全片平均盖过单页的失败。

这条判据 MUST 只依赖「一个浏览器 + ffmpeg」，MUST NOT 要求渲染镜像或 docker。为此它 MUST 能从**成品包自身**造出可复现的分段（逐帧截 DOM → 编码），并把「夹具能证明什么」写清楚：它证明截图落点、抽帧、解码与阈值这条管线，**不证明**包与真实渲染一致。

门禁 MUST 在材料不齐时以退出码 2 结束（缺分段、时间轴与包不是同一画布、舞台取不到），MUST NOT 拿缩放或错帧照常判。

#### Scenario: 夹具正例

- **WHEN** 用 `make-fixture.mjs` 造 2 页 / 2 秒的分段（`--shots 2`），再跑 `dom-ssim.py`
- **THEN** 逐页最差帧 MUST ≥ 0.95（实测 0.99646–0.99772，退化为编码损失），退出码 0

#### Scenario: 成片错位

- **WHEN** 把某一页的分段整体左移 40px 后重跑
- **THEN** 该页 MUST 判失败（实测 0.932），其余页不受影响，退出码 1

#### Scenario: 材料不齐

- **WHEN** 缺一页分段，或时间轴画布与包的画布不一致
- **THEN** 门禁 MUST 以退出码 2 结束并在开浏览器之前报出原因

#### Scenario: 切点两侧的取样

- **WHEN** 页时长 2000ms、第二镜 `startMs=1000, crossFadeMs=120`、fps=30
- **THEN** 该页的取样点 MUST 含 1153ms（切点后一帧），且该页最差帧不得低于阈值

### Requirement: 播放器产物由源码生成

成品包里的播放器（`internal/share/assets/app.js`、`app.css`）MUST 由 `web/src/sharePlayer/` 与 `shared/` 重新生成，MUST NOT 手工修改，也 MUST NOT 落后于源码。

CI MUST 在每次 push 时重新生成并与入库产物逐字节比对，不一致即失败。理由不是洁癖：`go:embed` 打的是入库的那份字节，产物落后一天，用户下载到的就是一天前的播放器——而这件事在本地看不出来，因为开发时跑的是 dev server。

#### Scenario: 源码改了但没重新生成

- **WHEN** 修改 `shared/motion.ts` 后没有重新生成 `internal/share/assets/app.js` 就提交
- **THEN** CI 的 `share player build (drift check)` MUST 失败
- **AND** 失败信息 MUST 指向 `git diff` 的具体文件，而不是只报「有差异」

#### Scenario: 产物与源码同步

- **WHEN** 重新生成后再提交
- **THEN** 同一检查 MUST 通过；成品包内的播放器行为与源码一致

### Requirement: 播放器铺满可用宽度

成品包在浏览器里打开时，播放器 MUST 铺满可用宽度，上限 1280px；MUST NOT 因为打包器插入的容器成为弹性项而按内容收缩。

这条写进规格的原因是它**已经错过一次**：`#ppts-share-root` 让 `.ppts-share` 的 `width:100%` 等于内容宽度，1920 宽的窗口里只画出 492px 的卡片。样式表里写的是 `max-width:1280px`，从样式看不出问题，从截图也看不出「小是从哪儿来的」——只有量一下舞台矩形才知道。

#### Scenario: 1920 宽窗口

- **WHEN** 视口为 1920×1080，播放器正常加载
- **THEN** 舞台宽度 MUST 为 1280（受上限约束），MUST NOT 小于 1000

#### Scenario: 窄窗口

- **WHEN** 视口宽 800
- **THEN** 舞台宽度 MUST 跟随可用宽度（约 752），MUST NOT 出现横向滚动

### Requirement: 页内切图在正确时刻发生（V18）

声明了页内镜头的包，MUST 在清单写明的时刻真的换图。对每一页里每个 `k>0` 的镜头，判据 MUST 覆盖切点前后各一帧（主图分别是第 `k-1`、`k` 镜那张图，且不透明度 ≥0.95）、叠化中点（两张图在场，淡入的那张不透明度在 0.05–0.95 之间），以及两条跨点约束：

- 同一页的几次取样之间，层节点的身份 MUST 不变（该页有层时才检）——重建会让元素重新入场，而 `clips` 是页内相对时间，重建一次整页动画就重播一遍。
- 每个取样点上层的可见性 MUST 与「这一镜是不是特写」一致：`crop` 非空的镜头里层 MUST NOT 显示，整页镜里 MUST 显示。

它与 V13b 的分工 MUST 写清：V13b 只看末镜那一帧，把「切镜」整个删掉、只留末镜图，V13b 照样过——而「一页多镜」存在的全部证据就是中间那次切换。

#### Scenario: 正常的两镜页

- **WHEN** 页时长 4000ms，两镜各 2000ms，第二镜 `crossFadeMs=120`、`crop` 非空
- **THEN** 1967ms 主图是首镜图、2060ms 两张图在场且淡入的那张 0.88、2153ms 主图是特写图；层节点身份三次一致；特写镜内层不可见

#### Scenario: 主图取哪一张

- **WHEN** 叠化进行到一半，底层是旧镜（不透明度 1）、顶层是新镜（0.88）
- **THEN** 「主图」MUST 取不透明度最高的那张（旧镜），`fade` 点 MUST 单独按「淡入的那张」判；MUST NOT 用同一个「最高」规则去判淡入，否则会把「根本没淡入」判成通过

#### Scenario: 落点没取准

- **WHEN** 总时长 40 分钟、播放器没有微秒定位接口，滑杆一步就是 2.4 秒
- **THEN** 落点偏差 >5ms MUST 判失败，报文 MUST 写明定位走的是滑杆还是微秒接口；MUST NOT 把「没取准」记成「切错了」

#### Scenario: 播放器不认镜头（降级形态）

- **WHEN** 清单带 `shots`，但包里的播放器是引入镜头之前的版本（只认 `slide.image`）
- **THEN** 切点后的取样 MUST 失败并指出主图是首镜图，退出码 1；这条正是 V13b 抓不到的那一类

#### Scenario: 层被重建

- **WHEN** 切镜时错误地调用了 `rebuildLayers`
- **THEN** 同页两次取样的层节点身份不一致，门禁失败并说明「切镜只该换图，不该让元素重新入场」

#### Scenario: 包里没有页内镜头

- **WHEN** 对一个不含 `shots` 的包跑本门禁
- **THEN** MUST 以退出码 2 结束并说明「没有页内镜头，无从判断切图」

### Requirement: 相机镜头的清晰度继承自特写路径

声明了 `camera` 的镜头 MUST 同时声明 `crop`（见 `html-share-bundle` 与 `render-plan` 的约束），
因此 MUST 复用「页内镜头切片」的 2x 重渲路径：有 `crop` 的页整页 300 DPI 重渲并裁出特写，相机
在其上运动。该特写的边缘梯度能量 MUST 满足与 300 DPI 直接裁切参照 ≥ 95% 的同款判据
（`animation-page-shots` 的 5.3）。

本需求 v1 MUST NOT 改变 300 DPI 触发逻辑。已知代价：相机 `scale` 远大于 1（特写上再大幅推近）
时，特写源自有限的 300 DPI 裁切放大倍率，极端放大仍可能糊——此为「清晰度 vs 体积」的已知权衡，
不在本需求范围。

#### Scenario: 相机镜头复用 2x 特写

- **WHEN** 某镜头同时声明 `camera` 与 `crop`
- **THEN** 其 `image` MUST 来自 300 DPI 重渲裁切的特写，边缘梯度能量 MUST ≥ 300 DPI 直接裁切
  参照的 95%

#### Scenario: 不引入额外 DPI 触发

- **WHEN** 导出带相机的包
- **THEN** 300 DPI 重渲触发规则 MUST 与引入本需求前一致（仅由 `crop` 触发），MUST NOT 因
  `camera` 单独改变重渲范围
