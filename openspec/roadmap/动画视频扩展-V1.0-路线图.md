**2026-11-04 指一个「没有动效的形状」此前等于没指。** 焦点有两种表达：柱子和非图层形状走**矩形遮罩**（整页盖纱、矩形留孔），形状是图层时走**压暗其它层**。分叉点是`buildFocusSpans` 收到的 `layerIDs` ——而两条路一直把「文档里有几个元素」当成「这一版会出几个图层」。底板只把**有轨道**的元素从整页图里挖掉做成层，其余仍烘在底板上，所以指一段没配动效的标题时：它被算成「是图层」→ 不给矩形 → 压暗一个不存在的层 → **画面逐像素不变**，而焦点记一条、诊断为零。改成 `layerElementIDs(rev, elements)`：有轨道**且**有几何才算层（与编译器的 `anchor_missing` 同判据），导出与预览共用。真渲染验收：造一页「标题块 + 对照块」，形状框照标题块给，`rev=nil`，`render.mjs` 真渲 6s——**修前整页最大差 0（等于什么都没画）**，修后标题块内 alpha **+0.003**、对照块 **+0.450**（正好一层 45% 白）。回归：组装器两条（无轨道→矩形 / 有轨道→压暗）、预览侧一条（`PageFocusSpans` 拿同一个判据，防两条路对同一个目标给出两种表达）、`layerElementIDs` 五态表（nil 规格 / 整页轨道 / 有轨道无几何 / 去重）。柱子的矩形路径不受影响：1920/1280/960 三档与预览仍逐位差 0。

**2026-11-04 焦点判据的「几何」那半句一直没实现；低电量设备则压根看不到焦点。** 两件事，一件是缺陷，一件是口径。**缺陷**：`layerElementIDs` 的注释写着「有轨道**且**有几何才算层」，实现里只有 `el.ID != ""`——几何那半句没写。表现与上一条同病：元素被认成层 → 不给矩形 → 去压暗一个不存在的层 → **画面逐像素不变**，而焦点记录、清单、诊断全绿。这次不再靠「手搭一张表证明判据按我理解的样子写」，而是**拿编译器当裁判**：同一份输入交给 `CompilePage`，`layerElementIDs` 认的层集必须与 `plan.Pages[0].Layers` 的 elementId 集逐项相同（`TestLayerElementIDsMatchesCompiler`）。第一次跑就红——`{ID:"ghost"}`（无框）与零面积框都被认成层，而编译器按 `anchor_missing` 拒掉它们；`PageElements` 只过滤了 `Bounds == nil`、**没过零面积**，所以这条在真实数据里可达。判据补齐为 `Bounds != nil && W>0 && H>0`（逐条对齐 `toBox`），变异回「只判 ID」后三条同时红。已知残余：完全落在画布外的元素，`toBox` 钳制后无面积而不成层，这里仍会认——判死它需要本页画布**宽**，而焦点侧只有高（`PageFocusSpans` 的入参），那种元素在成片里本来就看不见。**G8 那项核实后不用改**：跨页延续只在**已有层**上追加延续段（`injectContinuations` 用 `indexOfLayerByElementID` 找，找不到就记 `continuation_target_missing`），从不造层，所以判据天然覆盖它；已钉成 `TestCompileContinuationDoesNotSynthesizeLayer`（次页有几何无轨道 → 层集仍只有 other）。**口径**：`navigator.deviceMemory < 4` 时播放器整页不建舞台，焦点遮罩跟着一起没了——成片和高端机在指，低端机全亮，两端都不报错。降级的本意是省**合成层与图片解码**，而遮罩只是每组一个 div 加一条合成器跑的 opacity；按用户口径改为「只省元素层、遮罩照建」，判据收成一个 `pickStageLayers(layers, focus, lowPower)` 放在动画模块里（散在 `main.ts` 的两个 if 里时 CI 测不到）。真浏览器验收（`Page.addScriptToEvaluateOnNewDocument` 注入 `navigator.deviceMemory`，打开同一份「只有焦点、零图层」的包，`__PPT_SEEK_US__` 定位到 2000ms）：`mem=8` → 遮罩 1 个、opacity **0.45**；`mem=2` → **0.45**（反向验证：把 `pickStageLayers` 退回「低电量直接 null」、重建后同一条命令读到 **0 个遮罩**）。「有层无焦点」的另一份包：`mem=8` layers **2**、`mem=2` layers **0**——省的是层，不是提示。回归：`animation-check.mjs` 新增 `pickStageLayers` 六态（63 项）。

**2026-11-04 焦点判据收成一份，画布外的目标不再「指到画面外」。** 上一条留了一个残余：完全落在画布外的元素，编译器钳制后不成层，而焦点侧仍认它成层——判死它需要本页画布**宽**，而 `PageFocusSpans` 只收了高。这次把画布贯通到整条焦点链路（`PageFocusSpans` / `buildFocusSpans` / `focusSpanFor` / `toCanvasRect` 全部收 `design.Canvas`），并把层判据**整体搬进渲染包**：`render.LayerElementIDs` 复用 `toBox` 拆出来的 `boxOf`（同一条换算与钳制），app 侧只剩一个薄入口、不再有任何判断。两份实现合一之后，「app 认成层、编译器不出层」在结构上不再可能发生。`toCanvasRect` 同时补上交集判断：整块落在画布外时报 `focus_target_missing` 且不产遮罩——此前会产出一个原点超界的 rect，合成器把它钳在边缘，画面上是一块盖住左上角的白纱（比不指更糟，而所有报告都是绿的）；部分越界仍可用（不裁宽，超出那一截本来就被屏幕裁掉，与渲染器裁层的结果在成片里逐像素一致）。验证：真实 deck 三档画布（1920/1280/960）的 rect 与保真链仍**逐位差 0**、预览与导出逐位相同（`tmp/focuscheck` 实跑）；两组变异各自红——删掉交集判断后「画布外」用例产出 `Rect` 并失败，去掉 `boxOf` 的面积判断后五态表与对拍同时红。**顺带修一个从没被真实响应走过的分支**：预览把 `X-Preview-Focus-Skip-Reason` 填成渲染诊断码 `focus_target_missing`，而前端按简称 `target_missing` 比对——精确文案那一支永远落进兜底，而用例喂的正是简称，两边一起错、测试全绿。现在两个名字都认，用例改用真实码。

**2026-11-04 焦点过渡：两端口径写的是「同一个函数」，但网页版只在这个函数上取了两个点。** 前几轮反复讲「`focusMask`/`focusDim` 是共享模块、网页版与成片同一份」，这句话在**端点**上成立，在**过渡区间里不成立**：网页版把结果编译成 WAAPI 关键帧，`[起点, 起点+fade]` 两个点之间由浏览器**线性**插值，而成片逐帧求的是 `easeOutCubic`。真浏览器先量到形状（`tmp/lowpower-probe.mjs`，焦点 1000ms 开始、240ms 过渡）：`mem=8` 下遮罩 opacity 在 1060/1120/1180/1240ms 依次是 **0.1125 / 0.225 / 0.3375 / 0.45**——一条完美的直线，而同一时刻成片是 **0.260 / 0.394 / 0.443 / 0.45**，中点上差 0.169（满纱 0.45 的三分之一还多）。图层让位同病：换人 240ms 的中点，成片里让位方已压到 0.61、接手方已亮到 0.94，网页版两个都还停在 0.775——看起来像「谁也没被指到」。两端都不报错，只有并排播放才看得出。修法：把一段焦点过渡的采样收成一个纯函数 `pushFadeSamples`（8ms 步长，含两端），`compileKeyframes`（只给**被焦点指过**的层插，其余层 dim 恒 0、插了白涨关键帧）与新的 `focusMaskKeyframes`（从 `buildFocusMasks` 里抽出来的纯函数）共用。验收：真浏览器复测同一份包读到 **0.26 / 0.394 / 0.4425 / 0.45**；像素级反证——把步长改回「只取端点」重建，同一时刻截图与修复版逐像素比，孔外红块的绿/蓝通道 **+33**（18k+ 采样点），按 `Δ=(a₂−a₁)(255−base)` 反推 alpha 差 **0.169**，与解析值一致。CI 判据两条（`animation-check.mjs` 65 项）：把关键帧按 WAAPI 的方式线性插值还原，与 `focusMask` / `focusOpacity(focusDim)` 逐毫秒（含放手窗口）比对，最大差必须 ≤ 0.002；变异回「只取端点」两条同时红（最大差 0.1732）。顺带修掉探针自己的一个假就绪：`!im.getAttribute('src')` 被当成「已加载」，于是截到的是深灰占位图——那一次对比成了「一黑一白」，与被测行为无关。

**2026-11-04 上一版把过渡补成曲线了，但「每个遮罩节点认领哪一段」还是靠矩形，而一页可以有两段同原点的焦点。** 播放器的形态是「一段焦点一个遮罩节点」，节点之间必须互斥（同一时刻只有一段在讲）。认领条件此前是 `focusMask` 返回的矩形与自己的矩形 **x/y 相同**——两段的原点完全可以一样：先讲整张卡片、再回来讲卡片上的标题块（这是最常见的编法），同列上下堆叠的两个形状也一样。后果有两种，都不报错：其一，第二段生效时第一段的节点仍在认领，孔变成两块矩形的**并集**（指着标题却把整张卡片一起留白），孔外白纱从 0.45 叠成 **0.6975**；其二更隐蔽——`focusMaskKeyframes` 的关键帧只覆盖「本段自己的淡入/放手 + 页末」，页末那一刻归属已换成下一段、alpha 归零，于是这一段从 hold 起点到页末**被线性插值一路淡掉**：真浏览器量到 1000ms 起、3000ms 换段的那一页，第一段的遮罩在 2000ms 只剩 **0.2557**、2900ms 只剩 **0.0256**（应为 0.45），观感是「讲第一根柱子时白纱自己慢慢淡掉」。修法两处：`focusMask` 返回值加 `index`（当前生效那一段在入参数组里的下标），`focusMaskKeyframes` 改收**下标**而不是 span 对象、认领改成 `m.index === index`——矩形、元素 id、`startMs` 都不具备唯一性，下标是唯一没有歧义的归属；关键帧补上「下一段开口前 1ms 仍保持」与「开口那一刻归零」两个点，跳变才能被分段线性表示。验收（真浏览器，`tmp/lowpower-probe.mjs` 读每个节点的实际 opacity）：同一份两段同原点的包，4000/5000/5990ms 处第一个节点从 **0.174 / 0.312 / 0.449** 变为 **0 / 0 / 0**（成片只有一个遮罩，那一刻该为 0）；换段不放手的那一份，第一个节点在 2000/2900ms 从 **0.2557 / 0.0256** 回到 **0.45 / 0.45**（2990ms 仍 0.45，到 3000ms 才归零），3200ms 处第二个节点 0.448（240ms 淡入走了 200ms）。像素级反证：把认领改回「按矩形」重建，同一时刻截图与修复版逐像素比，**18434 个采样点**受影响、最常见 Δ=(−15,−48,−47)，按 `Δ=(a₂−a₁)(255−base)` 反解出两份白纱分别是 **0.697 / 0.45**，与解析值一致。CI 判据三条（`animation-check.mjs` 67 项）：同原点的两段互不认领、三段的「节点叠加后 1−Π(1−αᵢ) 逐毫秒等于 `focusMask` 的 alpha」、`shared/motion-check.mjs` 钉住 `index` 契约；两组变异各自红——按矩形认领（最大差 0.2475@6000ms）、只补归零点不补保持点（0.4496@4499ms）。单段焦点的包回归不变（2000/5990ms 均为 0.45）。

**2026-11-04 焦点「保持」判的是**声明**，不是画面上真有没有东西接管。** 规则是「下一段也指东西时不给终点，让它接管；否则句末放手」，注释里把两条都写清了：句间每句都放手会让整页每隔一句闪一下全亮，而不放手又会让画面一直指着已经讲完的对象。实现里的判据是 `next.Focus != nil && next.Focus.ShapeID != ""`——**声明**。可声明了不等于画面上真会亮：目标在解析产物里找不到、起点不在本页内、或被「焦点互斥」去重时，那一段被跳过、只留一条 `focus_target_missing`，没有任何东西来接管。于是上一段被填成 `EndMs=0`（保持到下一段 = 保持到页末），遮罩一直压在已经讲完的对象上，而旁白这时在讲别的事——正是规则点名要避免的那种错，从「目标缺失」这个口子进来。修法：解析与终点分两趟，第一趟记下每段**声明**了什么目标、**有没有真的产出**焦点（`focusOutcome{key, resolved, span}`），第二趟按「下一段真的会亮 → 保持；下一段讲的是同一个对象（被互斥去重）→ 也保持；否则句末放手」定终点。第二条不能省：同一件事连着讲两句时中间闪一下全亮才是错的，变异验证时把它去掉立刻红（`EndMs` 从 0 变 1000）。验收分两层——单测钉住三种排法（末段目标缺失、中间段缺失后面还有一段、下一段指同一个对象必须保持）；集成测（`TestBundleFocusEndMsReachesManifest`）把 spans 送进编译器与 `BundleAnimations`，断言清单里 `endMs=1000` 真的写出来了——`omitempty` 让 0（保持）与丢失在 JSON 上长得一样，只有断言具体值才拦得住。真浏览器对照（同一份包、只差清单里有没有 `endMs`）：有 → 500/900ms 0.45、1120ms **0.056**（240ms 放手走了 200ms）、1300ms 起 **0**；没有 → 1300/2500ms 仍是 **0.45**，一直压到页末。两组变异各自红：退回「按声明判」（0 而不是 1000）、漏掉「同一个对象」那一支（1000 而不是 0）。

**2026-11-04 矩形焦点换段会硬闪一帧全亮：孔是「换」的，不是「过渡」的。** 图层型焦点的换人是一段交叉淡化（`focusDim` 里 `out[上一段]=p`、`out[当前段]=1−p`，两件事同时发生），而矩形焦点同一时刻只有一块遮罩：新段开口那一刻旧的那块直接归零，新的一块从 0 淡入。真浏览器量到（两段矩形焦点、3000ms 换段）：2999ms 压暗 **0.45**、3000ms **两个遮罩同时 0**、3060ms 0.26、3120ms 0.394、3240ms 才回到 0.45——一句话一次白闪，整页像被闪了一下。成片同病（同一个函数）。修法：`focusMask` 改成 **`focusMasks`，返回一组**。换段那 `fade` 毫秒里两块同时存在——旧孔的 alpha 乘上「新段淡入进度」的补数，新孔按曲线张开；合成压暗量 `1−Π(1−αᵢ)` 从 0.45 平滑走到 0.399 再回到 0.45，全程连续。调用方跟着改：成片 `Timeline.tsx` 由「一块」改成 `masks.map`；播放器 `focusMaskKeyframes` 从「在 `next.startMs` 补归零点」改成「把下一段的淡入窗口整段采样」——上一轮的保持点补丁是给旧语义打的，新语义下旧节点不是归零而是收拢，仍要加密采样否则会被 WAAPI 拉成一条弦。验收：真浏览器（同一份两段包）2900/3000/3060/3120/3240ms 两块依次 **0.45→0.45→0.19+0.26→0.056+0.394→0.45**，合成 0.45/0.45/0.401/0.428/0.45，再没有一帧归零；成片用 `renderer/still.mjs` 真渲染同一份计划（两段矩形焦点、4000ms 换段），孔外墨点按 `v=b(1−a)+255a` 反解：3967/4000/4033/4067/4133/4233ms 依次 **0.45 / 0.45 / 0.40 / 0.40 / 0.427 / 0.45**；把 `focusMasks` 里「旧孔收拢」那一段注释掉重渲，4000ms 回到 **0.0**、4033ms **0.159**，整帧平均差 3.01、5.5% 像素受影响——这就是那次白闪。CI 判据：`shared/motion-check` 新增「换段用交叉淡化，整页压暗量全程连续、不归零」（逐毫秒断言相邻差 < 0.01 且最低点 > 0.38）；两端口径的用例从「比 `focusMask` 的 alpha」改成「比合成量」。单段焦点的包回归不变（900ms 0.45、1120ms 0.056、1300ms 0）。

Q7 的由来：5.5 的两位评审都给「可用」，但评审人指出「这种动画需要结合讲解内容来进行呈现，
目前只能说是有动画效果」。这条不落在 6 项里任何一项上——所以 5.5 的通过只能证明**渲染器把
「有动画」做对了**，不能证明**动效配合讲解**。两个结论差着一个量级，别混用。

- **一个里程碑一个变更**：变更名用能力语义（`animation-render-mvp`），不用「实现某某」。
- **能力路径稳定**：`animation-spec`、`html-share-bundle` 已建立；后续沿用同一路径追加 requirement，不新建近似能力。
- **归档动作**：变更任务全绿 → `openspec archive <name>` → 主 spec 吸收 delta；不手工编辑 `openspec/specs/`。
- **提交纪律**：一个变更 = 一个 commit（必要时按 PR1/PR2 拆分），提交信息带变更名与里程碑号。

## 7. 浏览器侧验收补记（M3 之后）

4.1–4.5 是脚本驱动的：请求路径、断言都由脚本写死，因此「UI 自己拼的路径对不对」
不在覆盖范围里。补一次浏览器验收（headless Chrome + CDP，1440×1000）后暴露两件事：

| 现象 | 根因 | 处置 |
|---|---|---|
| 点「创建导出任务」立刻 `HTTP 404` | `createArtifactExport` 发 `/projects/{id}/exports`，后端注册的是 `/api/projects/{projectId}/exports`。POST 没有 SPA 兜底（SPA 只兜 GET），故是硬 404：**从 UI 导出 MP4 / HTML 成品包一直失败**（自 M6-1 起） | 前端补前缀；同 bug 的 `createHTMLBundleExport` 已无人调用，直接删除；`api-contract-check` 增加「前端 REST 路径必须在 Go 路由表里」的不变量（Go `{param}` 与 `${...}` 都归一成 `*`） |
| 降级后「没有任何提示」 | 提示 `form-warn` 渲染在对话框底部，而对话框常高于视口 —— DOM 里有、屏幕上没有 | 出现时 `scrollIntoView({ block: 'center' })`；验收断言从「元素存在」改为「矩形在视口内」（`warnVisible`） |

复现这套时序（要造降级，必须让「选项已拿到可用」与「导出时不可用」分离）：

1. 渲染服务健康时打开导出对话框 → 选 MP4 → 勾「动画视频」（此时选项为 `1/3 页配了动效`）
2. 停渲染容器，等 >10s（`defaultProbeTTL`；失败也缓存，免得每次请求都打过去）
3. 点「创建导出任务」→ 编辑器：对话框不关、琥珀色提示在原位；列表页：对话框关闭、`.floating-notice.warn`

两处的任务都 `JOB_STATE_SUCCEEDED`，服务端日志可见 `POST /api/projects/{id}/exports 201` ——
「降级不等于失败」这句话在界面上才是成立的。
