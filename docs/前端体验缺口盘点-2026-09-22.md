# 前端体验缺口盘点（2026-09-22）

> 本文是**盘点清单**，不含设计或实现方案，也没有改动任何代码。用途是给后续立项提供证据基线。
> 结论按「已复核」与「扫描所得（未逐条复核）」分别标注，请以此区分可信度。

## 0. 方法与口径（先说清哪些统计不可信）

本轮踩到三个会导致**误报**的口径问题，记在这里，避免下次重复：

1. **`\b` 定界对 CSS 类名无效**：`grep -rn "\btopbar\b"` 会命中 `app-topbar` / `console-topbar`（`-` 也是词边界）。
   正确做法：从 `className=` 字面量里切出类名 token 再与 CSS 选择器做集合比较。
2. **i18n 静态引用计数会漏掉动态 key**：`GatewaySettings.tsx:314/337` 用
   `` t(`gateway.service${serviceKeySuffix[...]}`) `` 这类模板拼接，`gatewayState.ts` 的后缀映射表才是真正的引用来源。
   若只统计 `t('字面量')`，会把这批词条误报为死文案。
3. **「定义了但没引用」≠「死样式」**：`.running` / `.ok` / `.failed` / `.selected` 等是
   `className={`state-tag ${state}`}` 动态拼出来的，集合比较会全部误报。

前置健康度：i18n 中英键数 **1101 / 1101，零差异**；全仓 `gofmt -l .` 为空（M13 已收口）。

## 2. 加载态与空态 —— 已复核

- `AuditPanel.tsx:92-93`：`{state.events.length === 0 && !state.error ? <p>{t('audit.empty')}</p> : ...}`
  ——**没有 `loading` 判定**（`loading` 仅用于禁用刷新按钮，见 76-77 行）。首次加载瞬间会显示「暂无审计事件」，
  与"确实没有事件"同貌。属**闪现**级别，严重度低于第 1 节。

## 7. i18n —— 需人工分诊

- 中英键数 1101 / 1101，**零差异**（健康）。
- 以「该 key 是否在 `.ts/.tsx` 中以**任何字符串字面量**出现」为口径，有 **108 个词条零出现**。
  其中 `gateway.service*`、`gateway.health*`、`members.gender.*` 已确认是动态拼接（口径 2 的误报）；
  其余约 93 个**需人工分诊**是"死文案"还是"尚未接线的能力"（按项目既定原则：未接线的能力保留不删，
  死文案应清理，两者必须分开判断，不能一把删）。
