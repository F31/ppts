## 0. 方法与口径（先说清哪些统计不可信）

本轮踩到三个会导致**误报**的口径问题，记在这里，避免下次重复：

1. **`\b` 定界对 CSS 类名无效**：`grep -rn "\btopbar\b"` 会命中 `app-topbar` / `console-topbar`（`-` 也是词边界）。
   正确做法：从 `className=` 字面量里切出类名 token 再与 CSS 选择器做集合比较。
2. **i18n 静态引用计数会漏掉动态 key**：`GatewaySettings.tsx:314/337` 用
   `` t(`gateway.service${serviceKeySuffix[...]}`) `` 这类模板拼接，`gatewayState.ts` 的后缀映射表才是真正的引用来源。
   若只统计 `t('字面量')`，会把这批词条误报为死文案。
3. **「定义了但没引用」≠「死样式」**：`.running` / `.ok` / `.failed` / `.selected` 等是
   `className={`state-tag ${state}`}` 动态拼出来的，集合比较会全部误报。
4. **【2026-09-22 追加】行尾会让 `git diff` 整文件伪报**：`styles.css` 的 HEAD blob 行尾为 `mixed`，
   工作区被规范成 LF 后 `git diff` 出现 1958 行伪 diff（实际只删了几十行）。
   自检：`git ls-files --eol <path>` 看 `i/ w/`，或 `git diff --ignore-cr-at-eol --stat` 是否为空。
   详见第 8 节记录 ② 的「行尾陷阱」。

前置健康度：i18n 中英键数 **1101 / 1101，零差异**；全仓 `gofmt -l .` 为空（M13 已收口）。
（该 1101 为**盘点时快照**；经第 1–9 项实施后现为 **1111 / 1111**，仍零差异。）

### 已实施记录 ②：第 5–9 项（2026-09-22，commit `3f822ff`）

- **⑤ ProjectEditor 六处静默探测**：没有在六处各写一套 UI，而是抽出一套共享机制——
  `type ProbeId`（`revisions`/`project`/`narration`/`thumbnails`/`scriptSources`/`voiceModels`/

  把正常空态渲染成错误。
  界面按渲染位置分两组：**顶部失败带**（`.load-failure .load-failure-stack` + `role="alert"` +

  实现细节：`await` 之后的失败上报统一包在 `if (!cancelled)` 内（`reportProbe` 本身不接收 `cancelled`）；
  在 async IIFE 内同理。（**附带**：`notesError` / `voiceSaveError` 两处顺带补了 `role="alert"`。）
