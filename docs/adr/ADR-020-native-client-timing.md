# ADR-020：G4 原生客户端的启动时机与最小范围

- 状态：已采纳（2026-11-01）——G4 整体推迟，改为「触发制 + 窄起步」；开发计划 §4.5 的 12/14 窗口作废
- 关联：V4.0 §16、§11.5（sidecar）、§11.10（隐私模式）；ADR-001–013 中的 Tauri 选型、ADR-015；开发计划 §4.5、G0-4/G0-5/G0-8
- 编号说明：承接 ADR-019，ppts 内续编为 020

## 背景

开发计划把 G4 排在 12/14–01/15（3–5 周，9 个子任务），并把真机门禁欠账（G0-5 移动音频、G0-8 配音 PPTX）挂在 G4 一并执行。到 2026-11-01 为止，G2 未关闭、G3 未开始，而 G4 的代码前置几乎为零。继续按日历启动，等于用"排期到了"替代"条件够了"。

本文回答一个问题：**现在启动 G4 能得到什么，代价是什么，什么条件下才值得。**

## 事实盘点（2026-11-01 实测，可复核）

| 项 | 现状 | 复核命令 / 证据 |
|---|---|---|
| sidecar 协议 | Go 侧已实现 4 个方法：`handshake`、`get_capabilities`、`ping`、`export_bundle`；**没有解析/讲稿/媒体编排** | `internal/sidecar/sidecar.go:94-97` |
| Rust 桥接 | 不存在。仓库内 `Cargo.toml`/`Cargo.lock` 数量为 0，`apps/` 目录为 0 | `git ls-files \| grep -c -E 'Cargo\.(toml\|lock)'` |
| 前端平台抽象 | `web/src` 中 `__TAURI__`/`@tauri-apps` 引用为 0；92 个 ts/tsx、约 21229 行，单包结构 | `git grep -l '__TAURI__\|@tauri-apps' -- 'web/src/*.ts' 'web/src/*.tsx'` |
| 桌面发行链路 | 只有 4 个 Linux 单元文件（api/worker 的 systemd + 配置模板 + install.sh），无 Windows/macOS 签名、无 Updater | `git ls-files packaging` |
| 桌面本地渲染 | G0-2 已决定「渲染只进 worker 容器，桌面 L3 作为能力包」，L3 属 G5；worker 镜像约 820MB（含 LibreOffice/poppler/ffmpeg） | 开发计划 G0-2；`README.zh-CN.md:138` |
| 隐私模式（ADR-015） | 未实现；本地打包能力在，但缺页面图时降级为"沿用上一帧"，首屏无图则无画面 | `internal/share/bundle.go:439-470` |
| 真机门禁 | G0-5（锁屏/耳机/来电）、G0-8（客户端自动播音）均为 ⏸，且依赖 Windows/PowerPoint 与 Android/iOS 真机 | 开发计划 §4.1 进度表 |

由此得到一个不舒服但必须承认的结论：**G4 承诺的价值里，桌面端唯一不可替代的那一项（源文件不出域），恰好依赖被推到 G5 的本地渲染能力。** 在 G4 阶段做出来的隐私模式，能本地解析、能在本地打包播放，但页面仍是"云端渲染好的图"或空白占位——用户看到的是"不出域"和"能看"二选一。

## 决策

### 1. G4 不按日历启动，改为触发制

整体（含移动端）不在 12/14 启动。触发条件**全部满足**后才立项：

| 编号 | 条件 | 判定方式 |
|---|---|---|
| T1 | 真机门禁通过：G0-5 锁屏播放/耳机/来电恢复、G0-8 PowerPoint 自动播音且切页不串音 | 录屏 + 设备与 PowerPoint 版本登记 |
| T2 | G2、G3 关闭 | 里程碑检查表 + `go test`/CI 全绿 |
| T3 | 桌面价值有真实需求证据：≥3 家目标客户，或 ≥30% 意向客户，明确提出「源文件不得离开内网」或「离线演示」 | 访谈记录/工单/招标文件，不接受"觉得应该有" |
| T4 | 有 1 名可长期维护 Rust/Tauri 的人（不是"按需支援"） | 人力承诺；无此人则本项目不具备可持续性 |

T3 是分水岭：**没有它，桌面端只是把浏览器包一层**，多出来的只有图标、文件关联和一套签名分发成本。

### 2. 触发后按 G4-lite 起步（时间盒 2 周）

不一次性做 9 个子任务，只做能验证"桌面到底有没有用"的那条最短路径：

- **平台**：只做 Windows x64；macOS arm64 后置（公证流程是独立工作量）。
- **sidecar**：只新增 `parse`（本地读 PPTX → 页/备注/文本，走 `internal/project` 的纯 Go 读路径，不依赖 LibreOffice），复用已有 `export_bundle`。
- **链路**：打开本地 PPTX → 本地解析 → 生成讲稿 → 云端配音 → 本地打包播放。
- **明确不做**：本地渲染/离线视频导出（G5）、Updater（先内测分发）、OIDC 回调（复用 Web 登录）、同步冲突（先只读打开，编辑回 Web）、移动端全部。
- **判定**：2 周内跑通上述链路则继续；跑不通或明显超出，回退到 Web，并把结论写回本文。

不做 `G4-1` 的四包拆分（`ui/editor/platform/api-client`）。拆包只有在确定要做多端时才是投资，否则是纯成本；G4-lite 只需要抽一层 `api-client`。

### 3. 未触发期间的两件低成本事（各 ≤2 天，不占 G4 预算）

1. **PWA manifest + 离线首页**：解决"像应用一样打开"这类真实但浅层的诉求，避免用户为了一个图标去等一个原生客户端。
2. **`api-client` 抽层**：Web 自身受益（测试与调用边界清晰），且是 G4-lite 的既定前置。

两件都不引入新运行时、不改 CI。PWA 不替代桌面：它解决不了"源文件不出域"，也解决不了移动端后台播放。

## 影响

- 开发计划 §4.5 的 G4 窗口作废，任务编号保留（触发后按 G4-lite 裁剪执行）。
- `ADR-015`（桌面隐私模式）状态从"未实现（G4 未启动）"改为"未实现（G4 顺延，见 ADR-020）"；隐私模式的完整闭环仍以 G5 本地能力包为前提，这一点不因本决策改变。
- 不新增依赖，CI 与构建矩阵不变。
- **风险**：若市场突然要求桌面交付，2 周时间盒可能不够。缓解方式是时间盒 + 明确回退，而不是提前铺开 3–5 周。

## 备选方案

- **A：按原窗口全量启动（3–5 周，9 项）**——前置欠账未清（T1）、无 Rust 维护者（T4）、隐私模式因缺本地渲染而半残。3–5 周后大概率交付一个"能开、但导出仍要上云"的客户端，维护面却永久增加。不采用。
- **B：先做纯 WebView 壳（约 1 周）**——只换来图标与文件关联，却要立刻承担 Windows 签名/macOS 公证，以及"壳里的 Web 与浏览器里的 Web 行为不一致"的长期排查成本。同样的诉求用 PWA 更便宜。不采用；若确有"必须有安装包"的商务要求，单独评估，不走 G4。
- **C：直接放弃原生客户端**——移动端离线播放/锁屏朗读（G4-4/4-5）没有任何替代路径，把这条路彻底关掉是不可逆的。不采用，保留触发制。

## 复核

- 复核节点：2026-12-01（按日历回看一次）、G3 关闭时（触发条件 T2 达成点）。
- 触发核验清单（按序执行，全部为是才启动）：
  1. G0-5/G0-8 有录屏与版本登记；
  2. G2/G3 里程碑关闭；
  3. T3 的需求证据已归档（客户数/占比、原话摘录）；
  4. T4 的维护人已书面确认投入。

## 验收

- 本文进入 `docs/adr/` 并在索引表登记；ADR-015 状态同步更新。
- 未触发期间不产生 `Cargo.toml`、不新增 `apps/` 目录——仓库形态本身就是"G4 未启动"的证据。
- 触发后 G4-lite 的验收以"本地 PPTX 全链路可跑 + 2 周时间盒"为准，不以子任务数量为准。
