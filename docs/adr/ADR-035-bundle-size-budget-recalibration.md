# ADR-035：V15 体积预算按真实实测重订，并按实际编码分档、超即阻断

- 状态：**已实现**（2026-11-08）
- 关联：`internal/share/measure.go`（预算模型与档位推断）、`cmd/share-verify`（报告与退出码）、
  `scripts/review/bundle-gate.py`（V15 判据）、ADR-028（字体子集）、ADR-032（音频 AAC）、
  ADR-034（页图 WebP）、`openspec/specs/html-share-quality`（「体积构成可测量」条款）

## 背景

V15 的预算公式 `3 MiB + 0.5625 MiB/分钟` 是 2026-10 定的，两个数都是估的：基数按
「播放器 + 20 页图 + 清单」估，增量按「AAC 64kbps 单声道 ≈ 0.48 MiB/min 再留 15%」估。
当时页图还是 JPEG q82、字体未裁、音频可能落 WAV，所以往宽了给是有道理的。

三项手段落地后，这个「宽」变成了失效：

| 环节 | 手段 | 效果 |
| --- | --- | --- |
| 字体 | 按片中字符二次子集（ADR-028） | 字体类约 87 KB |
| 音频 | 混音轨 AAC 64k 单声道（ADR-032） | 14.4 MB WAV / 5min → 2.4 MB |
| 页图 | WebP q75（ADR-034） | 页图类 1.18 → 0.48 MB |

真实素材（14 页 / 2 分 20 秒）实测 **1.62 MiB**，旧预算 **4.31 MiB**——余量 2.7 倍。
也就是说这份包再膨胀到 3.5 MiB（页图翻倍、或音频存两份），门禁仍然全绿。
一个不会失败的判据不是「宽松」，是**不存在**。

同时仓库内部还有一处自相矛盾：路线图 M6-4 表里写「V15 体积｜是（过闸）｜超预算即 CI 红」，
而 `bundle-gate.py` 里 V15 是 `blocking=False`（WARN），`share-verify -budget` 又有自己的
硬失败路径。三个地方三种口径，谁也不知道超预算到底会不会拦。

## 决策

### 1. 预算改为四项，单价全部来自实测

```
预算 = 0.35 MiB
     + 页数 × 每页单价
     + 层数 × 每层单价
     + 分钟数 × 每分钟单价（仅当包内有音频）
```

时长只**在有音频时**计价：纯图文包（无旁白）的体积不随时长增长，按分钟给预算等于白送，
真正的回归会藏进这段白送的余量里。

### 2. 单价按实际编码分档

同一份 30 页 / 5 分钟素材，装 ffmpeg 与不装差一个数量级：15.12 MiB（WAV/JPEG）
vs 3.72 MiB（AAC/WebP）。一套阈值判两种产出，降级环境会永久红，然后被人 `--skip`
绕过——那比阈值宽更糟。所以预算跟着包内**实际编码**走：

| 档位 | 每页 | 每层 | 每分钟音频 |
| --- | ---: | ---: | ---: |
| `webp` + `aac/mp3/opus` | 0.06 MiB | 0.12 MiB | 0.55 MiB |
| `jpeg` + `aac/mp3/opus` | 0.13 MiB | 0.26 MiB | 0.55 MiB |
| `png` / 未转码 + `wav` | 0.35 MiB | 0.70 MiB | 3.00 MiB |

档位从包内条目扩展名推断：页图取**多数**（WebP 逐页退回 JPEG 是允许的，少量退回不该
把整包降到 JPEG 档），音频取**字节最多**的那个（混音轨是大头，分段备份不能把它带偏）。
推断不出时给最宽档——宁可宽，也不要因为推断失败把正常包判红。

### 3. 超预算即阻断

`bundle-gate.py` 的 V15 由 WARN 改为 FAIL。理由：既然两种产出各有各的尺子，
超尺子就是真回归，没有「门禁替产品做决定」的余地了。`share-verify -budget` 的
语义不变（exit 3）。

顺手修了一处一直在误导人的实现细节：门禁原先用 `go run ./cmd/share-verify`，
而 `go run` 会把子进程退出码统一成 1，于是超预算（3）、缺字（4）全被当成
「包结构不自洽」。改成先 `go build` 到临时文件再执行，拿真实退出码。

### 4. 层图与镜头图归一类

`classifyEntry` 原先只认 `-layer-`，`-shot-`（页内多镜头）落进了页图类。预算的每页
单价是按页数给的，多镜头包的「页图」字节里混着镜头图，口径就对不上。现改为两者
都归 `KindLayers`。

## 实测依据

素材：`internal/animation/animdefault/testdata/sample-customer-deck.pptx`（14 页真实商务模板，
白底 + 中文标题正文 + 图标卡片，无照片），经 WSL LibreOffice → PDF → `pdftoppm -r 200`
→ 长边缩到 1600（对齐 `EncodePage.MaxPageLongEdge`），与产品渲染链同源。

| 项 | 实测 | 采用单价 | 余量 |
| --- | --- | ---: | ---: |
| 固定开销 | 播放器 27.7 KB + 清单/字幕/杂项 20 KB + 字体 87 KB ≈ 134 KB | 0.35 MiB | 2.7× |
| 页图 WebP q75 | 均值 35.3 KB、最大 42.6 KB | 0.06 MiB/页 | 1.7× |
| 页图 JPEG q82 | 均值 86.2 KB、最大 106.7 KB | 0.13 MiB/页 | 1.5× |
| 音频 AAC 64k 单声道 | 0.467 MiB/min | 0.55 MiB/min | 1.18× |
| 音频 WAV 48k | 2.75 MiB/min | 3.00 MiB/min | 1.09× |

对照结果：

| 场景 | 实测 | 旧预算 | 新预算 | 新预算/实测 |
| --- | ---: | ---: | ---: | ---: |
| 14 页 / 2 分 20 秒，webp+aac | 1.62 MiB | 4.31 MiB | 2.47 MiB | 1.53× |
| 20 页 / 5 分钟，webp+aac（推算） | — | 5.81 MiB | 4.30 MiB | 与方案 §20.6 的 4.2 MB 目标同量级 |
| 30 页 / 5 分钟，jpeg+wav（实测降级包） | 15.12 MiB | 5.81 MiB（必红） | 19.25 MiB | 1.27× |

## 后果与风险

- **层图单价没有真实样本**。share 侧只原样写入上层裁好的 PNG，手头没有带元素动画的
  真实导出包；夹具里的层图是合成的纯色块（0.8 KB/层），毫无参考价值。暂按页图单价
  的 2 倍占位（透明 PNG 比同尺寸 WebP 大）。首次真实动画导出后必须复核：那时若红，
  **先量层图再改单价**，不要直接放宽阈值。
- **样本只有一份真实 deck**（白底商务模板，无照片）。满版照片或深色渐变页的 WebP
  体积会明显高于均值；0.06 MiB/页的 1.7× 余量是为此留的，但样本量不足以断言覆盖
  P95。累到 3 份以上真实素材后应重算一次分布。
- **预算不约束单文件形态**（ADR-033）：单文件天然是解压后 × 1.33 + noscript 页图，
  拿 zip 预算卡它只会天天红。这条不变。

## 重新评估条件

- 层图首次有真实动画导出样本；
- 真实素材累到 3 份以上，页图分布（P95）与均值偏离超过 30%；
- 播放器脚本体积翻倍（新增能力），固定开销 0.35 MiB 不再覆盖；
- 出现新的成品形态（如竖屏、多语言音轨）导致体积模型多一个维度。
