# PPT智能语音讲解平台 — 控制台UI设计评审

> 评审对象：登录页/控制台首页/导航结构设计（基于已完成的后端方案）
> 参照对象：Linear、Vercel Dashboard、Notion、Slack、Stripe Dashboard、Figma/Canva，以及此前已调研过的同类竞品（Synthesia、HeyGen、Murf）自身的控制台设计
> 结论：整体信息架构方向正确（首页做概览而非直接进列表、角色概念已经前置），但存在几处会在后续实现中越改越贵的结构性问题，建议在正式开工前调整；同时**核心工作台（配音编辑器）完全没有设计**，这是当前方案最大的空白。

---

## 〇、总体判断

这份设计把大部分精力放在了"账号、导航、后台管理"这类SaaS通用外壳上，这部分完成度不错；但对照产品的实际价值主张——AI生成讲解、逐页校对讲稿、试听调整——**真正承载核心价值的"配音工作台"页面完全没有着墨**，只在用户旅程里一句带过"选择音色、AI 模式、逐页编辑讲稿"。类比同类产品：Synthesia、HeyGen、Descript、CapCut这类工具，用户95%的时间停留在编辑器里，账号/后台只是不到5%的边角场景。这个优先级在设计阶段就应该体现，而不是把"外壳"做完再回头补核心页面。

以下按具体页面/模块给出发现和建议。

---

## 一、登录页

### 1.1 【结构性问题】用租户ID作为登录输入项，是反模式

设计里开发登录表单要求用户手动输入"租户ID"和"用户ID"，这是把内部数据库主键暴露给了最终用户。对照业界主流SaaS的登录发现模式——Slack是"输入工作区URL或邮箱，系统自动识别所属工作区"，Notion/Linear/Vercel都是"输入邮箱 → 系统检测该邮箱所属组织 → 引导到对应组织的登录方式（密码/SSO）"，用户从来不需要知道或输入一个UUID。

即便当前阶段的"开发身份登录"允许暴露内部字段做联调是可以理解的临时妥协，也应该**从一开始就把"开发登录"和"正式登录"在交互上做出明确视觉区分**（比如开发模式整体套一个警示色的"DEV MODE"横幅），避免这个临时表单的交互习惯被沿用到正式生产登录流程的设计里，也避免团队内部演示或给客户看demo时不小心展示了写着`00000000-0000-0000-0000-000000000000`和`dev-user`的登录页——这会直接削弱产品"企业级"的观感。

### 1.2 【功能缺口】只有"企业OIDC"和"开发身份"两条路径，没有个人/中小客户的自助注册路径

回顾产品定位里明确列出的目标客户——企业内训、在线课程教师、销售、个人讲师——**并不是所有客户都是有IT部门配置OIDC的企业客户**。当前设计里，一个想直接试用的个人教师或自由职业讲师，除了走"开发身份登录"（这条路径根本不该对真实客户开放）之外没有其他入口。参考HeyGen、Murf这类同类产品，它们的注册入口都是邮箱/Google OAuth自助注册，企业SSO是后续针对企业客户才追加的选项，而不是唯二选项。

**建议**：登录页至少预留第三条路径的位置——"邮箱注册/登录"（哪怕第一版先接一个最简单的魔法链接或邮箱验证码），企业OIDC和自助注册应该是互补关系，不是二选一。

### 1.3 【建议补充】租户发现应该在用户输入之后自动完成，而不是让用户选择登录方式

更贴近业界实践的流程是："输入邮箱" → 后端判断这个邮箱所属租户是否配置了OIDC → 自动跳转到对应方式，而不是让用户自己去判断"我该点企业账号登录还是开发登录"。当前设计把这个判断丢给了用户，对一个刚接触产品、不了解内部架构的人是不必要的认知负担。

## 二、控制台首页（Dashboard）

### 2.1 【方向认可，但权重需要调整】首页做概览是对的，但不能让"继续我上次的工作"被埋没

"不直接进PPT列表、先展示运营概览"这个判断参照Vercel/Linear是站得住脚的——但要注意一个关键区别：**Stripe这类财务/运营监控型工具适合首页铺满统计卡片，因为用户打开它的目的就是看数据；而这是一个工作流工具（工具的主线是"上传→编辑→生成→导出"），用户打开它的目的绝大多数时候是"回到我正在做的那份PPT"**。如果首页被"PPT资源数/已配音PPT数/存储占用"这类统计卡片占满了首屏，"最近PPT资源"和"快捷操作:上传PPT"反而被挤到下面，会让高频操作多绕一层。

**建议**：把"最近PPT资源"和"快捷操作"提到首屏视觉权重最高的位置（参考Vercel项目面板：最近部署记录是主体，统计信息只是顶部一排小巧的chip），统计卡片可以做得更紧凑，甚至折叠进一个可展开的区域，而不是六个等大的卡片平铺在最显眼的位置。

### 2.2 【明确缺口】没有设计"零数据"状态（Empty State）

一个全新租户第一次登录，PPT资源数=0、任务数=0、存储=0，这时候如果还是渲染六张写着"0"的统计卡片，会显得很冷清、也没有引导下一步动作。Linear、Notion、Vercel这类产品都为"首次进入"单独设计了引导页——一个清晰的插画/图标 + 一句话说明 + 唯一的主按钮"上传第一份PPT"，而不是把常规态的Dashboard原样渲染一份全零的版本。

**建议**：明确区分"零数据首次态"和"常规态"两套首页设计，前者只有一个清晰的CTA，不要用统计卡片的空壳去填充页面。

### 2.3 【安全/成熟度问题】系统提醒直接暴露内部实现细节，会削弱产品可信度

"系统提醒"里列的"模型网关未配置""TTS使用fake供应商"，这两条如果照字面意思渲染给用户看，"fake供应商"这种明显是内部调试用的命名，一旦出现在界面上，会让人怀疑产品是不是没做完——这和之前给客户讲解的方案里强调的"企业级信任"定位是矛盾的。

**建议**：
1. 这类系统健康提醒应该**只对Owner/Admin角色可见**，Editor/Reviewer/Viewer不应该看到"模型网关"这类基础设施术语；
2. 面向用户的文案需要重新表述，比如把"TTS使用fake供应商"改写成"语音合成服务尚未配置，请联系管理员完成设置"，不能把内部枚举值直接抛给界面。

## 三、导航结构

### 3.1 【结构性问题，建议尽早调整】"PPT资源"和"已配音PPT"不应该拆成两个平级导航项

这是本次评审里最建议优先处理的一点，因为**它和后端的数据模型是矛盾的**。回顾此前的技术方案，一份PPT对应的是"SourceRevision + 多个讲解任务/版本"的关系——一份PPT在有了配音之后，它还是同一份PPT，只是多了一个讲解版本，而不是变成了另一个物种、搬到了另一个列表里。

如果导航上把"PPT资源"和"已配音PPT"做成两个独立的顶层列表，用户上传一份PPT配完音之后，会产生"我刚才那份PPT去哪了，是消失了还是要去另一个菜单里找"的困惑，而且这个模型后续要支持"一份PPT同时存在多个语言/音色的配音版本"时会更难扩展——两个列表要如何显示"这份PPT在已配音列表里出现了3次（3个语言版本）"？

**建议**：参照Figma/Canva的做法，合并成一个统一的"项目"列表，通过状态筛选（全部/未配音/生成中/已完成）或者每一项右侧的状态标签（"已配音 ×2"）来区分处理进度，而不是物理拆成两个页面。这个调整现在做成本最低，一旦前端页面和路由已经按两个独立列表写完，后续合并的返工成本会高很多。

### 3.2 【功能缺口】任务中心的实时性没有被当作核心体验设计

方案里任务中心只是导航里的一项，取消/重试/进度流式刷新被放进了"后续再做"。但对这类产品，"生成进度能不能实时看到"直接决定用户体验好不好——参考Runway、ElevenLabs、Descript这类生成式工具，进度条实时刷新、完成后有明确的通知（站内提醒/桌面通知），是这一类产品的体验及格线，不是加分项。

**建议**：把"任务状态的实时更新"（哪怕只是轮询，不追求一步到位做WebSocket）纳入第一版范围，而不是完全推到后续，否则第一版做出来的"任务中心"体验会明显低于用户对同类产品已经建立的预期。

### 3.3 【建议补充】租户切换器不应该完全藏进个人信息弹窗

方案把"切换租户"标注成"后续"功能，放在个人信息弹窗的二级菜单里。如果未来会支持一个用户属于多个租户（比如代运营多个企业客户的服务商角色），租户切换器通常是紧贴在品牌logo旁边的顶层导航元素（参照Slack/Notion/Vercel左上角的workspace切换器），而不是藏在右上角个人菜单的第二层——用户对"我现在在哪个租户下操作"这件事的感知优先级应该很高，因为操作错租户在多租户系统里是真实的误操作风险。

**建议**：即便第一版还不支持真正的多租户切换，也建议在UI上预留这个位置（哪怕先做成禁用状态或只显示当前租户名），避免后续要在导航结构里"插队"加一个新的顶层元素。

### 3.4 【建议补充】增加全局命令面板（Cmd+K）

Linear、Notion、Vercel、GitHub这类产品现在都标配一个全局快捷搜索/命令面板，用户可以直接敲名字跳转到某份PPT、某个设置页，而不必逐层点导航。对这个产品来说，"PPT资源"这类内容本身就有很强的按名称查找的需求，命令面板的投入产出比很高，建议列入第一版之后的下一个迭代，而不是长期不考虑。

## 四、系统设置

### 4.1 【安全/权限问题】设置项没有按角色区分可见性

方案已经定义了Owner/Admin/Editor/Reviewer/Viewer五种角色，但"系统设置"下的用户管理/模型配置/发音词典/审计日志/存储与额度是平铺的一个`settingsTab`状态，没有说明不同角色能看到哪些tab。用户管理和审计日志理应只对Owner/Admin可见，如果一个Editor角色的用户点进系统设置能看到审计日志和用户管理，这既是权限设计的漏洞，也会让"角色"这个概念显得没有被真正落实。

**建议**：设置页的tab列表应该根据当前用户角色动态过滤，这个逻辑现在定，比后续每个tab单独打补丁要省事得多。

### 4.2 【建议补充】区分"个人设置"和"租户/工作区设置"两个层级

当前把"用户管理""模型配置"这类影响整个租户的设置，和未来可能出现的"个人通知偏好""界面语言"这类只影响单个用户的设置，都归到同一个"系统设置"里，容易越堆越乱。建议从命名和分组上就区分开——例如"工作区设置"（租户级，Owner/Admin可管理）和"个人设置"（用户级，人人可管理），这也是Notion/Slack这类多租户产品的标准做法。

---

## 五、最大的缺口：配音工作台完全没有设计

这是本次评审最想强调的一点。回顾用户旅程描述："点击配音 → 进入配音工作台 → 选择音色、AI 模式、逐页编辑讲稿 → 生成配音"——这几句话背后，是整个产品里唯一真正体现AI能力、唯一用户会长时间停留、唯一决定"这个产品好不好用"的页面，但目前的设计文档里，它只有一句话，而登录页、导航、系统设置这些通用外壳反而被展开得很细。

参考同类产品（Descript、CapCut、Synthesia自身编辑器、剪映）的共同结构，配音工作台通常是三栏布局：

| 区域 | 内容 |
|---|---|
| 左栏：页面缩略图轨道 | 逐页缩略图，标注每页的讲稿状态（未生成/AI草稿/已锁定/校验失败），点击跳转 |
| 中栏：当前页画布 + 讲稿编辑区 | 当前页大图预览 + 对应的讲稿文本编辑框，支持原文朗读/润色/AI生成三种模式切换、停顿强调标记 |
| 右栏：属性面板 | 音色选择、语速、目标时长、来源锚点（AI生成内容点击可跳转回原文依据）|
| 底部：时间轴/试听条 | 播放当前页音频、显示时长、跨页拖拽调整节奏 |

**建议**：在继续细化账号/导航这类外壳页面之前，优先把配音工作台的具体交互稿产出，这是决定产品体验上限的页面，也是目前设计资源投入最不成比例的地方。

## 六、优先级汇总

| 发现 | 优先级 | 建议处理时机 |
|---|---|---|
| 配音工作台完全没有设计 | **P0** | 立即，先于继续细化账号/设置类页面 |
| "PPT资源"与"已配音PPT"拆分成两个列表，与后端数据模型矛盾 | **P0** | 前端路由/页面开工前调整，越晚改成本越高 |
| 系统设置未按角色区分可见性 | **P0** | 第一版实现时就应纳入，不要留到后续补权限 |
| 系统提醒暴露内部实现细节（"fake供应商"等） | P1 | 第一版文案/可见性范围调整 |
| 登录页用租户ID作为输入项，缺少自助注册路径 | P1 | 正式登录页（区别于开发登录）设计时处理 |
| 任务中心实时进度被放入"后续" | P1 | 建议提前到第一版范围 |
| 首页零数据状态未设计 | P1 | 与Dashboard一并设计 |
| 首屏统计卡片权重高于"继续工作"入口 | P2 | 视觉稿阶段调整 |
| 缺少租户切换器的UI预留位置 | P2 | 至少预留位置，避免后续插队 |
| 缺少全局命令面板 | P2 | 第一版之后的迭代 |
| 设置未区分"个人"与"工作区"层级 | P2 | 设置页扩展时处理 |

**一句话总结**：这份设计把"SaaS通用外壳"搭得比较扎实，也提前想到了角色和多租户这些正确的问题，但两处结构性决策（PPT资源与已配音PPT拆分、系统提醒暴露内部术语）如果现在不调整，后续会越改越贵；而最需要投入设计精力的配音工作台，恰恰是目前留白最多的地方，建议下一轮设计优先补齐这一页。
