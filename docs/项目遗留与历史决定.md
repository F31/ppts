### 5.1 口径（第一版高估了孤儿数，第二版才准）

`t()` 在 `i18n/index.tsx:66` 只有一条路径 —— `messages?.[key] ?? key`，无类型约束。所以「key 是否被引用」
可以纯静态判定，但要正确处理三类**动态拼接**：

1. 模板字符串：`` t(`gateway.service${suffix}`) ``（`GatewaySettings.tsx:314/337`）、`` `members.gender.${g}` ``；
2. 字符串拼接：`'prefix.' + x`；
3. 映射表间接：`t(item.labelKey)` / `t(roleKey[role])` / `t(jobStateKey[job.state])` / `t(artifactFormatKey[...])`
   —— 取值的字面量写在**别处**（如 `gatewayState.ts` 的两张映射表、各页面的 `*Key` 映射对象）。

**第一版口径的缺陷**：把「任意字面量是某 key 的前缀」都算动态引用，于是 `"editor"` 这种词把 76 条
`editor.*` 全判成"疑似动态"，孤儿数被压到 32（假阴性）。**收窄后**只认①模板字符串切掉 `${...}` 后的静态段、
②紧邻 `+` 的字面量，结果才稳定：**1113 键 → 1005 条精确引用 + 9 条真实动态 + 99 条真孤儿**。

- 那 9 条真实动态即 `gateway.health*`(5) + `gateway.service*`(4)，由 `gatewayState.ts:61/70` 的
  `healthKeySuffix` / `serviceKeySuffix` 生成 —— **是假阳性，未删**。
- ⚠️ **盲区已检查**：源码确实存在上述第 3 类间接调用，但其取值最终都落在字符串字面量或模板拼接上，
  两种口径已覆盖，不存在"只经变量传递、字面量无处可寻"的 key。

（旧记录里"约 92 / 93 条"是**口径收窄前的快照，已作废**。以 99 条为准。）

### 5.4 两个额外发现（超出分诊范围，仅记录未动手）

**① `web/src/scriptState.ts` 整个文件是死代码。** `scriptControlsFor()` / `stateFromScriptStatus()` /
`ScriptUiState` / `ScriptControls` 全仓无任何调用方 —— `grep scriptState` 只命中 `ScriptEditor.tsx:44` 的**同名

所以删那 5 条 100% 安全。另注：`stateFromScriptStatus` 只可能返回 `'missing'` 或 `'ai_clean'`
（`if (!status) return 'missing'; return 'ai_clean';`）—— `'edited'/'confirmed'/'locked'` 永不返回，
与免确认编辑（§7）之后状态模型被简化的历史一致。**未删该文件**（超出 i18n 分诊范围），需要时单独立项。

**② `editor.simulatedVoiceNote` 疑似 A26 回归。** 该文案描述"本租户没有可用语音合成服务，当前使用开发用

删文案不改变这件事（本来就零引用），保留它是为了留住这个提醒的载体。**建议核实后端是否仍返回 simulated**：
是 → 接回提示（A26 要求）；否 → 可一并删除。

### 5.5 门禁（`npm run i18n:check`，2026-09-22 落地）

**为什么需要**：i18n key 是 JSON 里的普通字符串，而 `t()` 的签名是 `t(key: string)`
（`src/i18n/index.tsx`），两边对应关系**不在类型系统里** —— 一条死文案对 `tsc -b`
既不是错误也不是警告。§5.1 那次探针是一次性的，而「改名 key / 删面板 / 先写文案」
这三类单向操作会继续沉淀。

**落地物**
- `web/i18n-check.mjs` —— 照 `contrast.mjs` 的范式（零依赖、node 直跑、退出码即结论）。
- `web/i18n-orphans.baseline.json` —— 存量允许项，**每条带 reason**（即 §5.3 的 17 条）。
- `web/package.json` 加 `npm run i18n:check`，**刻意未挂进 `build`**。

**设计取舍（都倾向宽松）**

| 决定 | 理由 |
|---|---|
| **不剥离注释**：注释里的 key 也算「被引用」 | 宁可漏报（死文案多留一轮），不可误报 —— 误报会阻塞构建，最后逼人绕过门禁 |
| 动向前缀 = 自动检测 ∪ 基线人工声明 | 自动兜常见写法；写法复杂到静态看不出来时人工兜底 |
| 报告显式列出动向前缀及「覆盖 N 条」 | 前缀会**掩盖**真实孤儿，列出后人可核（`members.gender.` 即属多余：该族 4 条另有 `Login.tsx:251-254` 的显式引用） |
| 只报「新增孤儿」，**不判断该删还是该留** | 分诊判据是「后端有没有对应端点」，机器判不了（§5.2/§5.3 的边界全是这类判断） |

**门禁自身也做了测试**（故意制造故障确认会拦）：正例 `EXIT=0`；往 `zh.json` 加一条零引用
key → 报「新增 1 条」+「中英不对等」且 `EXIT=1`；基线塞入「已在使用」/「已删除」条目 →
分别报「已接线/被引用」与「已从 json 删除」；`--update-baseline` 幂等（清理探针条目后
与备份逐字节一致）。

**尚未升级为构建前置**：那一步会改变 CI 阻塞语义（白名单一旦漏登记合法动态 key 即成阻塞项），
属独立决策。当前定位是「清理时有现成工具、不阻塞任何人」。

### 5.6 门禁首跑即暴露的真缺陷：5 条「被引用但不存在」的 key

## 13. 校验规则的实现细节（M11 / M15 / M16 / M1）

**M11 归一化做法**（先量后改的产物）：

- 抽数字**前先把日期区间挖成等长空白** —— 否则 `2026-09-13` 会被拆成 `2026` / `09` / `13` 噪声。
- 日期容空格；只认年月(日)，**不认单独年份**。
- 千分位 / 前导零 / 小数尾随零 / 全角数字统一。
- **单位等价表**：识别正则**由表生成**，且**长单位优先** —— 否则 `sec` 会被 `s` 咬住。
- **计数前缀**：`x8` / `×8` 折成裸数量（**对称**归一，故 `x86` / `x64` 仍判违规）。
- 实测符合预期从 **2/10 → 9/10**。

**M15 `ValidateRules` 启动期自检的 6 类**：

1. 空 token；2. token 含空白；3. 等价组只有 1 项；4. **同 token 落两组**
（`unitCanonical` 后写覆盖先写 → 归一化结果取决于**声明顺序**，是最隐蔽的一类）；
5. 仅大小写重复；6. 子表全空。

**M16 量词族**：`measureGroups` 个/项/条/则/款/种/类 同族；页、次、位/名、台、块… 各自成族
（**允许单元素组**，不为凑数硬拉近似词）。量词族名**不进** `FormatEntities`
（该函数按字符串去重，同一数量带不同量词会产生两条实体）；
`FormatMeasureHint()` 与校验器同源并进 `draftInstructions`。

**M1 的 `draftInstructions(mode, kind, snap)` 分流规则**：原始素材 →「把要点整理成口播稿」；
仅 `inputExisting` →「润色当前讲稿」。

## 15. 工具坑细节：行尾（EOL）伪 diff

`styles.css` 实际只改几十行，`git diff` 却报 **1958 行**。

**诊断**：`git ls-files --eol <path>` → `i/mixed w/lf`
（HEAD blob 行尾混乱 + `core.autocrlf` 把工作区规范成 LF）。

**处置**（必须与内容改动**分离提交**，否则污染 blame）：

```bash
cp <file> <file>.bak                                    # 1. 备份已编辑内容
git show HEAD:<path> | tr -d '\r' > <path>              # 2. 用 HEAD 内容 + 强制 LF 覆盖
git add <path> && git commit -m "chore: 行尾规范为 LF"    # 3. 单独提交
git diff --ignore-cr-at-eol --stat                      # 4. 应输出空 = 零内容变化（取证）
cp <file>.bak <file>                                    # 5. 恢复内容改动
```

仓库现状：395 个受控文件中 394 个是 LF；`theme.css` 是 crlf（一致、无噪声）。
