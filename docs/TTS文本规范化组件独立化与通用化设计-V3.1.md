# 中文 TTS 文本规范化组件独立化与通用化设计 V3.1

状态：设计提案，分阶段实现。

V3.1 将中文 TTS 文本规范化从 PPTS 内部规则集合，升级为可独立发布、可测试、可组合的通用组件。PPTS 是首个集成方，但核心组件不依赖 PPTS 的租户、数据库、HTTP、环境变量或 TTS 供应商。

## 目标

- 将中文及中英混排文本转换为适合 TTS 的朗读文本和结构化控制事件。
- 在原文区间上识别候选、裁决冲突并一次构建输出。
- 默认不让规则处理本次执行生成的文本。
- 提供可解释的来源映射，不把比例估计标记为精确对应。
- 支持版本化配置、规则快照、差异对比和回滚。
- 支持 PPTS 继续使用旧路径，并逐步迁移到新契约。

## 非目标

- 不做 TTS 合成、VAD 或强制对齐。
- 不做租户、权限、数据库、管理后台实现。
- 不提供任意脚本 DSL。
- 不保证所有歧义表达自动转换。

## 核心执行模型

```text
输入校验
  → 保护区间归一化
  → 在原文上识别语义候选
  → 按显式保护和公开优先级裁决
  → 一次构建最终输出
  → 生成改写记录、来源映射和诊断
```

所有规则默认读取相同原文视图。规则产出的文本不再进入后续规则识别流程。

## 组件边界

核心组件负责：

- 输入输出类型。
- 配置编译与规则校验。
- 保护区间和候选冲突裁决。
- 文本输出构建。
- 来源映射和诊断。

PPTS 适配层负责：

- 从数据库加载词典和上下文规则。
- 合并租户、平台和默认配置。
- 规则快照缓存与热更新。
- 将结构化停顿映射到供应商能力。
- 讲稿一致性、指标、审计和 UI。

## 规则类型

- 字面词典：品牌、缩写、专有名词等确切替换。
- 模式模板：正则捕获组重排和固定模板替换，不调用语义函数。
- 代码语义规则：数字、日期、金额、单位等需要解析和验证的转换。

## 来源映射

V3.1 区分：

- `identity`：原样复制，可逐 rune 对应。
- `replacement`：整块替换，仅保证区间来源关系。
- `insertion`：插入内容，记录关联边界或规则原因。
- `deletion`：删除区间，记录输出侧边界。

点位投影可作为兼容能力提供，但不能声明为精确字符映射。

## 实施阶段

1. 保留现有 `Engine.Run`，新增 V3.1 并行契约入口。
2. 实现保护区间、非级联候选裁决和来源映射基础能力。
3. 将内置类别规则逐步迁移到候选规则模型。
4. 增加语料、反例、歧义例、组合例和映射测试。
5. PPTS 适配层双轨比较旧新输出。
6. 独立 module 发布 `v0.x`，稳定后进入 `v1.0` 兼容承诺。
