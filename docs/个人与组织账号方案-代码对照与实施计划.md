## 二、可复用 vs 需新增

**直接复用（零改动）**
- `folders` / `tags` / `project_tags` 表 + RLS（PG）/ 应用层隔离（SQLite）
- `projects.folder_id`（可空外键 + `ON DELETE SET NULL`）
- 「未分类」隐式分组（`folder_id IS NULL`）
- 原生 HTTP CRUD：`GET/POST/PUT/DELETE /folders`、`/tags`、`PUT /projects/{pid}/folder`、`PUT/DELETE /projects/{pid}/tags/{tagId}`、`GET /projects/organization`
- 前端：左栏分组树筛选、URL 参数化、内联创建、行内打标签/移动分组

**需新增**
1. `tenants.type`（迁移 + 回填策略）
2. 注册 `account_type` / `org_name` + 校验 + 个人默认名
3. 当前租户信息端点（暴露 `type` 给前端）
4. 前端注册单选卡片 + 组织名输入
5. 前端按 tenant 类型隐藏成员/协作入口
6. 「禁止移除最后一个 owner」守卫
7. （可选）创建项目指定 `folder_id`；服务端 `tag_ids`/`folder_id` 过滤

## 三、实施计划（按依赖排序）

### S1 — 数据迁移：`tenants.type`
- 迁移（PG `0034` + SQLite `0002`）：
  ```sql
  ALTER TABLE tenants ADD COLUMN type TEXT NOT NULL DEFAULT 'personal'
    CHECK (type IN ('personal','organization'));
  ```
- **回填决策（重要）**：现有租户不能一律 `personal`（否则多成员组织会被误隐藏成员管理）。建议按成员数回填：
  ```sql
  UPDATE tenants SET type='organization'
  WHERE id IN (SELECT tenant_id FROM tenant_members GROUP BY tenant_id HAVING count(*)>1);
  -- 其余保持默认 personal
  ```
- 验收：`go test ./internal/...` 全绿；跨租户查询仍返回 0 行（RLS 未变）。

### S2 — 注册分叉（`/auth/register`）
- 请求体新增 `account_type`（`personal|organization`）、`org_name`（组织必填）。
- 校验顺序（与方案 3.4 一致）：非法/缺失 `type` → 400；组织缺名/超长/非法字符 → 400；个人携带 `org_name` → 忽略。
- 个人默认名：`{email@前} 的空间`（替代当前直接写 email）。
- 复用同一事务（不动事务边界）。
- **前后端共享校验规则**：Go 侧定义常量，前端从构建期常量或同规则实现（避免"前端过了后端拒了"）。
- 验收单测：个人成功 / 组织成功 / 组织缺名 400 / 组织名超长·非法 400 / 个人带 org_name 被忽略且成功。

### S3 — 当前租户信息端点（前端门控依赖）
- 新增 `GET /tenant`（authed）→ `{ id, name, type, role }`（role 复用 `membership.GetRole`）。
- 前端 `AuthenticatedApp` 已有 `listMembers` 调用来推导 role，可合并为一次 `/tenant` 调用。
- 验收：个人 tenant 返回 `type=personal`。

### S4 — 前端按 tenant 类型门控
- `AppShell` 的 `settingsMenus`：`members` 项增加 `tenantType==='personal'` 时隐藏（或 `need` 之外加类型条件）。
- 项目「分享」入口（`ShareDialog` 的协作者 Tab）在个人 tenant 下隐藏。
- 验收：个人账号登录后设置页无「成员管理」、无「邀请协作者」；组织账号正常。

### S5 — 注册页 UI
- 邮箱/密码后增加单选卡片：「个人使用（默认）」/「创建组织」。
- 选组织 → 展开「组织名称」输入，前端校验通过前禁用注册按钮（行内错误）。
- 验收：个人直接可提交；组织未填名时按钮禁用。

### S6 — 最后 owner 保护
- 在移除成员 / 降级角色路径加守卫：若目标是该 tenant 唯一 owner → 拒绝（400/409，明确文案）。
- 落点：`TenantService.RemoveMember` / `SetMemberRole`（`internal/api/tenant.go`），或 `membership.Store` 层。
- 验收：唯一 owner 无法被移除/降级；存在两个 owner 时可移除其一。

### S7（可选）— 创建即指定分组 / 服务端筛选
- 方案要 `ProjectService.Create` 带 `folder_id`。**两条路径**：
  - **推荐（最小改动）**：保持两步（`Create` → `MoveProject`），前端创建后立即调用移动；无需改 proto。
  - 备选：给原生 `POST /projects` 加 `folderId` 字段（若已有原生创建端点）。
- 服务端 `tag_ids`/`folder_id` 过滤：当前**客户端过滤**在项目数量大时不够（全量拉取）。若接受个人/小团队规模可延后；要扩展则给 `GET /projects/page`（原生）加查询参数，避免改 proto。

## 四、需要你确认的 3 个决策点

1. **`tenants.type` 回填**：按成员数（>1 → organization）回填，还是全部默认 personal？（推荐前者，避免误隐藏现有组织的成员管理）
