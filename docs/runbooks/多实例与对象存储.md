# 多实例部署与对象存储（S3）说明

> 适用：需要水平扩展 API/worker、或将对象存储迁移到 S3/OSS 的部署。

## 1. 单体 vs 多实例

| 能力 | 单体（现状默认） | 多实例要求 |
|---|---|---|
| 数据库 | PostgreSQL（RLS + 迁移） | 同一 PG；迁移**只能一个实例**执行（见 §3） |
| 对象存储 | `local`（`PPTS_OBJECT_ROOT`） | **必须 S3/兼容对象存储**（local 无法跨节点共享） |
| 认证会话 | 无状态 JWT（HttpOnly Cookie） | 开箱可用；改密/登出吊销走 `users.token_version`（每请求一次 PK 查询） |
| 认证限流 | 进程内内存限流 | **需共享存储**（见 §4）；否则每实例独立计数，实际额度 × 实例数 |
| 任务调度 | worker 双连接（scheduler + 业务）+ SKIP LOCKED | 开箱可用；多 worker 并发领取安全 |
| 指标 | 每实例 `/metrics` | 由抓取端按实例聚合（Prometheus 多 target） |

## 2. 对象存储切到 S3

```ini
PPTS_OBJECT_BACKEND=s3
PPTS_OBJECT_SECRET=<签名密钥，32B base64>
# S3 兼容配置（AWS/MinIO/阿里 OSS 等）
PPTS_S3_ENDPOINT=https://s3.example.com
PPTS_S3_REGION=cn-north-1
PPTS_S3_BUCKET=ppts
PPTS_S3_ACCESS_KEY=***
PPTS_S3_SECRET_KEY=***
PPTS_S3_FORCE_PATH_STYLE=true   # MinIO/多数自建 S3 需要
```

- 代码路径：`internal/integrations/objectstore/storefactory`（按 `PPTS_OBJECT_BACKEND` 构建）。
- 按租户策略可路由到不同 bucket/region：`tenants.policy.storage_backend/storage_region`
  （`internal/tenant/policy.go` 的 `ObjectStoreBackend`/`StorageRegion`）。
- 迁移既有 `local` 对象：用 `mc mirror` / `aws s3 sync` 把 `PPTS_OBJECT_ROOT` 的内容按
  `<tenant>/<project>/...` 的目录结构同步到 bucket 根；键不变，切后端后签名 URL 自动改写。
- 签名 URL：S3 后端由对象存储原生预签名；`local` 由 `/ppts/object/{key}` 令牌端点服务。

## 3. 迁移编排（多实例）

`ppts migrate` 目前**没有 advisory lock**，并发执行可能竞态。发布流水线必须保证：

1. 迁移作为**独立、单次、串行**步骤，先于任何新版本实例启动：
   ```bash
   PPTS_MIGRATE_DATABASE_URL="$PPTS_DATABASE_URL" ppts migrate   # 需 superuser DSN
   ```
2. 迁移成功后再滚动重启 `ppts-api` / `ppts-worker`。
3. 回滚只回滚二进制，不回滚迁移（迁移应保持向后兼容，只做附加列/表）。

## 4. 限流共享存储（多实例必读）

当前认证限流（注册/登录/忘记密码/重发）与登录失败锁定是**单进程内存实现**
（`internal/api/ratelimit.go`）。多实例下各实例独立计数，攻击者可通过并发打到不同实例
规避。生产多实例建议以下之一：

- 前置 WAF / API 网关做 IP 级限流（推荐，改动最小）；
- 或将 `fixedWindowLimiter`/`failureGuard` 替换为 Redis 实现（保留同接口语义）。

> 接口已收敛在 `authLimits`，替换实现不影响 handler。

## 5. 指标与告警

- `GET /metrics` 为 Prometheus 文本格式（由进程内 expvar 渲染，见 `internal/observability/prom.go`）。
- 可选 `PPTS_METRICS_TOKEN`：配置后需 `Authorization: Bearer <token>`。
- 建议告警：
  - `ppts_worker_jobs_total{state="failed"}` 增长；
  - `ppts_auth_events_total{event="login_locked"}` / `{event="login_failure"}` 突增（撞库）；
  - `ppts_auth_events_total{event="register_rate_limited"}` 突增（注册滥用）；
  - `ppts_worker_queue_oldest_wait_seconds` 持续升高（积压）。

## 6. 运营商后台

- 配置 `PPTS_OPERATOR_USER_IDS` 后，这些用户登录即在前端看到「运营后台」入口。
- 端点：`GET /admin/tenants`、`POST /admin/tenants/{id}/suspend|resume`。
- 挂起后该租户所有成员请求被认证中间件拒绝（`TenantStatus` 检查）。
- 运营商身份是**按用户 ID 的环境变量白名单**；后续可演进为独立 `is_operator` 字段/管理租户。
