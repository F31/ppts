# 5.5 观感评审：口径、评分表与已知盲区

> 这份表解决的是一个很具体的问题：**机器判据（ADR-18）能证明"像素没丢"，但证明不了"看起来对不对"**。
> 末帧逐像素比的是墨量与差值，字形被换成另一种近似字体、字重被换掉、颜色偏了 3 个色阶——
> 这些在平均差 0.5～1.2 的范围里都能过，只有人眼能一眼看出。

## 零、先跑机器检查（ADR-19）

人眼之前先过一遍机器能判的部分，免得把「分辨率/色偏」这类客观问题带进主观打分：

```bash
# 0) 计划级度量：§19.6 的元素数（≤9）与节奏密度（clip/秒 ≤3），不通过直接非零退出
python3 scripts/review/perception-metrics.py <job>/plan.json

# 1) 用 Studio 同一个 composition 渲染单帧（替代 npm run studio，无头环境也能跑）
PPTS_CHROME="/path/to/chrome" node renderer/still.mjs \
    --plan <job>/plan.json --frame 165 --out /tmp/f.png

# 2) 稳定帧：应当与源页逐像素相同
python3 scripts/review/still-check.py --still /tmp/f.png --page <job>/pages/p000.png --settled

# 3) 动效进行中：与源页的差异必须只落在该元素框内
python3 scripts/review/still-check.py --still /tmp/f10.png --page <job>/pages/p000.png \
    --confined-to 116,288,1320,130
```

2026-10-29 实测（5 页样片）：5 页稳定帧**逐像素相同**（平均差 0.000、差 >32 像素 0），
其中包含深色页 `#0E1B2E`——只在浅色底上看不出色偏的实现会在这里暴露。
这一步过了，第 6 项「色彩与对比」基本只剩主观偏好；没过就别急着打分。

## 一、谁评、怎么评

1. 用播放器按 **100% 缩放**（不要全屏拉伸）看一遍成片，再按联系表逐格核对。
2. 同一份片子至少 **两人独立打分**，先各自填表、再对表；同一项分差 ≥2 分时回看对应秒数定夺。
3. 打分只对"能定位到具体秒数/具体元素"的问题扣分。说不出位置的"感觉不好"，记在备注里，不计分。
4. 生成联系表：`scripts/review/storyboard.sh <成片.mp4>`（约 10 秒，输出一张 PNG）。

## 二、评分表（每项 1–5 分，3 分为"可用"）

| # | 项目 | 判据 | 5 分 | 3 分 | 1 分 |
|---|---|---|---|---|---|
| 1 | 字形完整 | 汉字、全角标点、箭头、希腊字母、圈号逐个可见 | 全部正常，含生僻字 | 个别标点挤压 | 出现 □ / 缺笔画 / 整段缺字 |
| 2 | 文字清晰 | 100% 缩放下小字号仍可读 | 边缘干净 | 轻微振铃 | 糊成一团 / 有块状伪影 |
| 3 | 元素完整 | 每个元素都出现，且没被同页其它元素盖掉 | 全在、层级正确 | 遮挡 1 处，静态可辨 | 元素整块消失或晚出 |
| 4 | 残影与转场 | t=0 纯白；起播时无静态副本残留 | 干净 | 一帧可察觉 | 明显拖影 |
| 5 | 时序与节拍 | 起播点、停留、退出与声明值偏差 | ≤1 帧 | 2–3 帧 | >3 帧或顺序错 |
| 6 | 色彩与对比 | 与源页同区域比，底色/文字色不偏 | 看不出差 | 并排能看出 | 反色 / 明显偏色 |

> 第 1、3 项是**回归项**：2026-10-29 修的两处静默丢内容（子集字体丢空格、图层顺序吃子元素）
> 正是这两项的最低分情形。任何一次渲染改动后，这两项应重新打一遍。

## 三、已知盲区（不要记成缺陷）

- **部分重叠的兄弟元素**会互相带出（`tasks.md` 5.9）：单张栅格推不出逐元素 alpha，属模型限制。
- **参考片不在仓库内**：`tasks.md` 5.5 原文要"对照参考片、按视觉基线 §19 口径"。参考片与 §19
  正文都在仓库外的方案文档里，本表因此只覆盖渲染器自己负责的部分（§19.1 里渲染引擎 ~5% +
  运动质感 15%）；资产、版式、镜头的相似度不在本表范围内，也不该由渲染器背。
- **透明/半透明元素**在残影检查里会被误判：ADR-6 的对照法仅对不透明底板成立。

## 四、记录格式

```
日期 / 评审人 / 成片文件名（含 sha256 前 8 位）
1 字形完整  5  2 文字清晰  4  3 元素完整  5
4 残影转场  4  5 时序节拍  5  6 色彩对比  4
扣分定位：12.4s 第三张卡片右下角文字边缘轻微振铃（H.264 噪声，可接受）
结论：可用 / 需返工（附最小复现计划）
```

## 五、下一版要补的第 7 项：「该动的时候才动」

现有 6 项问的都是「动得好不好」——字形对不对、边缘干不干净、元素全不全、残影有没有、
时刻准不准、颜色偏没偏。**没有一项在问「这时候该不该动」**。

这不是遗漏，是这份评分表的**输入限制**：6 项评的是 `film_B_tier_30s.mp4`，它没有音轨
（`mp4a` / `soun` 各出现 0 次），起播点来自样例生成器的元素序号（`120 + i*180`），
trigger 全是 `onEnter`。没有讲解，就没有「该动」的判据，也就没法评「动效是否跟着讲解走」。
2026-10-30 的评审人正是这么说的：「这种动画需要结合讲解内容来进行呈现，目前只能说是有动画效果」。

补法（依赖带配音的样片，段落时间轴由 TTS 给出）：

| 判据 | 通过 | 扣分 |
|---|---|---|
| 不提前 | 元素不早于它所在段落的开口 | 早于段落开口 = 剧透，记 1 分情形 |
| 不滞后 | 段落开口后 3 帧内出现 | 讲到了还没出，超过 3 帧扣 |
| 有层次 | 同段多元素仍有 stagger（不同时蹦出） | 同段全部同时出现 = 无节奏 |
| 不空转 | 讲解没提到的元素不出，或页末弱化出现 | 全页元素在页首一次性铺满 = 动画退化为装饰 |
| **不空等** | **任意时刻画面上本页内容不足一半的状态 ≤1.5s** | **空着超过 1.5s = 观众认为「还没加载完」** |
| **不静** | **讲着话时画面连续不变的时长 ≤3.5s** | **一句话过去了、画面还停在上一句 = 讲解与画面对不上** |

前四项都成立才算「动效贴合讲解」。这条与 §19.1 里「运动质感 15%」对齐——那一档权重评的
本来就不只是「动得干净」，还有「动得是时候」。

**第五项是 2026-10-30 补的，它是前四项的结构性缺口。** 前四项全部在问「元素什么时候动」，
没有一项在问「这一刻画面上有多少东西」。实测：`film_C_narrated.mp4` 在前四项上 14/14 全过
（最大偏差 47ms），但页 1 从 5.99s 到 14.94s 是一个**空框**（卡片底板 6s 就淡入，四条要点
陆续到 14.9s），页 3 右半页空 3.6s。这些都是「元素全准时、画面却空着」。

评审人在 5.5 / 5.6 两轮说的「效果不佳」「需返工」，指的很可能就是这一层——而表上没有
地方填。**量表的维度决定能收到什么反馈**：四个时间判据，收上来的只能是关于时间的意见，
即使评审人真正不满的是画面完整度。

**第六项（同日晚些补）是第五项的另一半。** D 片按第五项改完（四条要点一起出、卡片常驻、
页 3 主视觉提前），18 项全过——但页 1 在第 1.4s 就铺满，**之后约 10 秒画面一动不动**，
而旁白还在逐条念。「空」和「静」是两种病：前者是元素没出现，后者是全出现了却再没有变化。
前五条都不问这件事，于是可以把最优解推向「所有内容页首铺满」——那是另一种更闷的片子。

阈值 3.5s 的来处：本片 13 段讲解最长一句 3.24s。画面可以「一句一变」，
但不能「一句话过去了还停在上一句」。实测 D 片最长 10.80s、E 片 3.10s。

机器侧对应 `verify.py` 的 V7.1（内容覆盖）、V7.2（空框悬挂）、V8.1（讲着话时画面静止）。

### 这里没有第 7 条：「图有没有画对」

同日又发现第 2 页的柱状图在说谎：174s 被画成 943s 的 72%（实际 18%），
948s 与 943s 画得一样高。数据说的是「长片最贵」，图上看着「都差不多」。
那一刻 20 条判据全过。

但这条**不进评分表**，因为它和前面六条的方向相反：六条都是「人看得出来、机器看不出来」，
所以一条条补成机器判据；这一条是**人看不出来**——除非手里同时有数据表，否则没人能说
「这根柱子本该画多高」。机器能查（`V9.1`：柱高/数值的最大差 ≤1.08 倍，旧图 3.92 倍），
人只能查「有没有轴、刻度、基线」这类表面特征。

结论：**能自动化的那一半已经自动化了，剩下的那一半本来也不该问人。**
给没有图表的片子打这一项的 1/3/5 分毫无意义，所以评分表停在六条。

### 这里也没有第 8 条：「图上的数，讲稿念全了吗」

柱子画对之后（柱高与 174/131/943/948 成比例），22 条判据全过。再把图和讲稿并排数一遍：
**四根柱子，讲稿只念了前两根**。后两根正是「长片线性放大、并发只多 5 秒」这句结论的证据，
不念，图就只是背景。V9 问的是「柱子和它自己标的数对不对得上」，没有一条问过
「这些数讲稿讲没讲」。

这条也不进评分表，而且比第 7 条更不可能靠人：坐着听 30 秒，讲稿是通顺的；
要发现漏讲，得暂停、数柱子、倒回去对讲稿——那已经不是打分了。机器一次就能查（`V10.1`）。

所以评分表停在六条不是「还没补完」，是**剩下一维本来就不该问人**：
V9 和 V10 都需要一个外部参照（作图数据 / 讲稿文本），而评审现场只有片子本身。

### 这里还没有第 9 条：「讲早了没有」

G 片 23 项全过之后，把页 2 的焦点时刻和 TTS 的词时刻并排放：`bar2`/`bar3` 的注意力
从段首就压着，而「九百四十三」要 1.4 秒后才念到——数字念到了，只是提前给了答案。
`V11.1` 量这个差（早 ≤120ms / 晚 ≤350ms），参照物是逐词边界。

这条同样不进评分表，理由更硬：**人听不出来**。观众只会觉得「有点赶」或「哪里怪」，
说不出是哪一根柱子提前亮了 1.4 秒；而且它需要一份逐词时间轴，评审现场没有。

到这里，机器判据和人工评分的分工已经稳定：**人判「看起来对不对」，机器判「对不对得上」**。
前六条是人看一眼就有的整体印象；V9/V10/V11 都是「对账」——拿画面去对数据、对讲稿、
对词表。对账不需要审美，需要的是两列数并排放，而这正是人最不擅长、机器最擅长的。

### 5.1 分值（2026-10-30 补，此前缺失）

上面那张表只有「通过 / 扣分」两列，**没有分值定义**——1 分和 5 分各意味着什么没人写过。
所以第一次回收来的记录是四个「1」、定位与备注全空、结论「需返工」，既不能证明片子坏，
也无法据以返工（见 `review-packet.md` §八）。补上锚点，并把 §一第 3 条做成硬约束：

| 分 | 含义 | 前置条件 |
|---|---|---|
| **5** | 该判据在整条片上成立，没有例外 | — |
| **3** | 成立，但有 1–2 处例外 | **必须**能指到「秒数 + 元素」 |
| **1** | 该判据整体不成立（不是「有几处不好」，是「这条没做到」） | **必须**能指到秒数 + 元素，并说明处数 |

规则：
- **低于 5 而不填定位的，该项记 5，问题移进备注**（备注不计分）。这条是 §一第 3 条在
  第 7 项上的落地，`scripts/review/q7.html` 已把它做成导出前校验，不再是口头约定。
- **「1」不是「最差的那一档观感」**，是「这条判据没做到」。用 1 分等于说「整条片都在剧透 /
  整体没有节奏」，与「有几处延迟」是两件事——后者是 3 分。
- **结论取「需返工」必须有 1 分或 ≥2 项 3 分**。四项全 5 或一项 3 分仍是「可用」；
  只有「可用 / 需返工」，没有中间态。全 3 分按 `q7.html` 的算式落在「需返工」（均值 3.0），
  那是刻意的：四项都「有例外」意味着通篇不稳。

### 5.2 评的条件（达不到就别打分）

第 7 项与 §二 那 6 项不同：那 6 项看画面就够了，这 4 项全是「元素相对**语音**」的时间关系。
所以有两个硬条件，以及两条「先量再评」的前置检查：

| 条件 | 达不到会怎样 |
|---|---|
| **有声音**（不是静音、不是只放画面） | 没有参照点，四个判据都无从判。评审页会提示音量状态 |
| **能逐帧**（`q7.html` 的 `←/→`，或播放器逐帧） | 判据写「3 帧（≈100ms）」，原生播放器看不出来，只能凭观感估 |

评之前先跑这两条，它们**排除「片子没问题但看起来像有问题」**：

```bash
python3 scripts/fidelity/verify.py --rerun     # 一条命令：重跑三个测量 + 14 项对账
```

`verify.py` 不是把三个脚本串起来，是**对账**：V1 制品、V2 音画、V3 覆盖、V4 工具盲区、
V5 四条判据、V6 新鲜度（报告比成片旧直接作废）。`--self-test` 往合成数据里注入 16 种故障，
断言每种都能红——门禁自己也要有回归，否则它会重演「看起来通过了」。

单独跑某一项时：

```bash
python3 scripts/fidelity/check_appearance.py   # 元素真正出现在什么时候（整页范围）
python3 scripts/fidelity/check_av_sync.py      # 音轨相对旁白原件偏了多少
```

`check_appearance.py` 存在的原因就是 `check_alignment.py` 只看段落开口前 400ms——
更早出现的元素在它眼里是「一直都在」，于是报「不提前」。`check_av_sync.py` 存在的原因是
所有视频侧测量的参照点都是文本时间轴，音频整体偏移量不到。

**评分与实测冲突时的收口**：两者相反（例如四个 1 分、实测四项全成立）时，
**不改写评分人的结论，也不用评分去否定实测**，写进 `review-packet.md` 的「记录 + 复核」两节，
状态记「待复核」，等一条「秒数 + 元素」。理由很实际：没有定位的「需返工」，会让人去返
一个不存在的工。

**状态（2026-10-30 更新）**：当前验收样片是 `tmp/q7/film_L_narrated.mp4`（35.53s，带配音，
15 段，元素按 `withSegment` 绑到讲解段落，页 2 的焦点在**句首**就落到这一句讲的对象上，
段内换人才按「念到那个数」定时刻，讲完一句就放手）。D→E→F→G→H→K→L 七版：前四版只改
编排与版式，H 版重打了一遍 TTS（35.530s → 35.530s，逐段一致），K 版修压暗的两个语义
缺陷（没有终点、第一根元素从第 3 个焦点起不再退后），L 版改 V11 的参照词口径
（第一个焦点对齐句首，不再一律等数字）。机器侧 **26 项全过**：17 个绑定元素在段落开口前
区域变化全为 0，扣除设计错落后最大起播延迟 53ms（1.6 帧），V11.1 三处「讲着它却不指它」
（页 2 的 4.7s / 5.1s / 7.6s 四根柱子同亮）已清零，V13.1 全片没有「两个元素同时满墨」的帧。
复跑方法见 `scripts/fidelity/README.md` 的「带配音的样片」一节，人工评审用
`python3 scripts/review/serve.py --root tmp/q7 --page scripts/review/q7.html --film film_L_narrated.mp4 --port 8089`
（评审目录里放的是哪一版，就用哪一版的名字）。

仍**未定**的是 Q7 第 1 件事：绑定从哪里来。这一版是手写 `q7-script.json`，证明的是
「`withSegment` 这条路通、渲染端按时出画」，**不证明**绑定能自动生成。
所以 5.5 的「可用」只能引用为「渲染器把『有动画』做对了」；本样片的通过只能引用为
「绑定到段落之后，元素确实跟着讲解出现」。两句都不等于「动效整体配合讲解」——
最后那句还要等绑定的生成策略定案。
