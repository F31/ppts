# 出片保真检查（ADR-18）

回答一个问题：**渲染出来的视频，内容比源页少了什么没有？**

仓库里原先的样片是用色块占位的，画面里一个字形都没有。它适合验时间轴、转场、残影，
但对「文字丢没丢」完全不敏感 —— ADR-15 的空格缺陷和 ADR-17 的图层顺序缺陷都是
换成带真实文字的样片之后才暴露的。这套脚本就是那份样片的来源。

## 四步跑完

```bash
# 1) 造底图：字体从镜像里取，保证与线上同一份字形
docker create --name fsrc ppts/renderer:dev
docker cp fsrc:/usr/share/fonts/opentype/ppts /tmp/ppts-fonts && docker rm -f fsrc
python3 scripts/fidelity/gen_pages.py --fonts /tmp/ppts-fonts --out /tmp/fidelity

# 2) 编译成计划（底图会被拷进 job 目录，见 ADR-14）
go run ./scripts/fidelity/plan -in /tmp/fidelity -out /tmp/job

# 3) 提交给渲染服务（--assets-dir 指向 /tmp/job 的只读挂载）
curl -s -X POST --data-binary @/tmp/job/plan.json http://127.0.0.1:8090/v1/render
#    然后轮询 GET /v1/render/{jobId} 直到 succeeded，取回 segment_*.mp4

# 4) 比对末帧与源页
python3 scripts/fidelity/compare.py \
    --pages /tmp/fidelity/pages \
    --elements /tmp/fidelity/elements.json \
    --segments /tmp/job-out
```

## 判据

| 指标 | 阈值 | 说明 |
|---|---|---|
| 整页平均绝对差 | ≤ 2.0 | H.264 编码噪声在 0.5–1.3；到 2 以上多半是内容变了 |
| 差 >32 的像素占比 | < 1% | 结构性丢失会到几个百分点（ADR-17 是 5.8%） |
| 元素区域墨量比 | ≥ 0.8 | 文字被盖掉/淡掉时直接趋近 0 |

任何一条不过，脚本以非零退出。这三个阈值来自实测：5 页带文字样片在正确实现下是
平均差 0.56–1.23、差 >32 的像素 <0.35%、墨量比 ≥0.95。

## 两个容易踩的口径坑

- **取末帧**，不要取页中任意一帧：入场动画在页末才回到恒等，取中间帧会把动画状态算成差异。
- **墨量的基准色只从源图取**：两边各自取中位色时，渐变区域会得到不同基准，
  算出来的是基准漂移而不是像素差异（第一版因此虚报了 3.7 个百分点）。

## 想复现 ADR-17 那个缺陷

把 `gen_pages.py` 里 `page1` 的图层顺序改成「先 items 后 card」再跑一遍：
三行要点的墨量会从约 6% 掉到 0.00%，而任务状态仍是 `succeeded`、没有任何 warning。

## 带配音的样片（Q7：动效是否跟着讲解走）

上面那条链路评的是「渲染器画得对不对」，它**测不了**「该动的时候才动」——
成片没有音轨，起播点是 `120 + i*180` 按元素序号排的，trigger 全是 `onEnter`。
这一节是补那条链路：把讲解词合成为音频，把元素的起播点绑到段落上。

### 只改绑定、不改讲解词

`segments.json` 是 `narrate.py` 的产物，`bind` 是它从 `q7-script.json` 抄进去的。
只改绑定（拖时间点、换绑段落）时**不必重打 TTS**——重合成会让音频基线漂移，
同一句话重合成一次时长不一定分毫不差。改用：

```bash
python3 scripts/fidelity/sync_bind.py \
  --script scripts/fidelity/q7-script.json \
  --segments tmp/q7/segments.json --out tmp/q7/segments-d.json
```

文本或段 id 对不上就报错退出（它不做猜测）；时间戳一律不动，因为那描述的是已生成的音频。
页级 `static` 清单（容器底板这类「页首就在」的元素）也由它一并抄过去。

### 绑定写成「念到它的那个词」

```json
"focusAt": [{"elementId": "p2-bar2", "atText": "九百四十三"}]
```

`sync_bind.py` 用 `words.json` 把它解析成 `atMs`，plan 侧一行都不用改。手写 `offsetMs`
的问题是没人能复核：那个数是听出来的，换一个字或换一次语速就作废。写成词之后，
改讲稿重跑一次就自动跟上；找不到、或出现多次而没写 `nth`，它报错退出——错绑一个时刻
比不绑更糟。

零点用**实测的裁剪量**（两次时长相减），不是「第一个词的起点」：TTS 说第一个词起于
96ms，实际音频 200ms 才越过 −45dB。差这 100ms，所有 `atText` 会整体偏晚，而偏晚在
V11 里正好卡在「走神」的容差边上——每根柱子都差一点，其实是尺子错了。

### 什么时候不该等那个词

一句话讲**两根**柱子，切换点当然落在第二根的数上（s2-2「两核一百七十四秒，四核一百三十一秒」）。
但一句话讲**一根**柱子时，整句都是它，句首就该指过去：

```json
{ "id": "s2-3", "text": "两核跑五分钟，九百四十三秒。", "focus": "p2-bar2" }
```

写成 `focusAt: [{elementId: "p2-bar2", atText: "九百四十三"}]` 的后果不是「晚一点」，
是**前半句画面谁也没指**：旁白在说「两核跑五分钟」，四根柱子一样深（K 片页内
4.7s、5.1s 的实测墨量是 1.00/1.00/1.00/1.00）。V11 因此分成两种参照：

| 位置 | 参照 | 理由 |
|---|---|---|
| 段内第一个焦点 | 段开口 | 这一段讲的就是它，句首不指＝讲话了没反应 |
| 段内其余焦点 | 念到它的那个数 | 一句话里换人，必然落在新那个数上 |
| 没有焦点的元素 | 实测出场 vs 数值词 | 原逻辑，覆盖「只有出场」的编排 |

前提是**一段一个主题**。若某段先总述再落到某根柱子（「先看时间，两核一百七十四秒」），
第一个焦点按句首会被判早——目前的解法是把段拆细，不要在一段里先绕一句。

### 换产物目录时：`PPTS_SEG_DIR`

三个测量脚本（`check_alignment` / `check_appearance` / `audit_layout`）都要把每页的起止
时间算出来，口径是「把各段的**实测**时长累加」。段文件位置由 `PPTS_SEG_DIR` 指定，
默认 `tmp/q7/out`。

```bash
PPTS_SEG_DIR=tmp/q7/out-g python3 scripts/fidelity/verify.py \
  --film tmp/q7/film_G_narrated.mp4 --segments tmp/q7/segments.json ... --rerun
```

不指会怎样：它读的是别的目录里的段，把**上一版片子**的页长当这一版的页起点。
G 片第一次跑就是这样——页 2 从 9.87s 变成 5.1s，后面每页的起点都往前挪，页 4 的采样
整段落在页 3 上，于是报「`p4-title` 整页未稳定出现」。那是一个长得像片子坏了的假失败。

所以 `_segtime.py` 里两条都是硬退出：段文件缺失不静默回退到计划值；实测段长与计划
差 >200ms 直接退出（这批段不属于这份计划）。

### 四个必须这么做的选择

| 选择 | 不这么做会怎样 |
|---|---|
| **逐段合成**，不是整页合成后再切 | 整页音频只能靠 VAD 或强制对齐切段，误差几十到几百毫秒；逐段合成的段落边界就是拼接点 |
| **裁掉首尾静音**（`silenceremove` 双向） | edge-tts 的 mp3 头部自带约 100ms 静音，元素按 startMs 出现、声音却晚 100ms——3 帧，正好踩在「不滞后」的判据线上，测出来的是 TTS 的静音头，不是渲染器 |
| **trigger 用 `withSegment`**，不是 `atTime` | 两者都能出片，但用 atTime 时改一句讲解词，音频时长变了、画面还按旧毫秒走，且不报错 |
| **关掉页转场**（`-hard-cut`） | 转场 320ms 逐像素混合，页首 220ms 开口的段落与它重叠，包围盒灰度差量出来的是混合度，不是元素不透明度 |

### 判据与实测

`check_alignment.py` 的算法：取段落开口前 400ms 到开口后 1100ms 的连续帧，裁出元素
包围盒，算它与「开口前那一帧」的灰度平均绝对差（MAD），第一次越过 2.0 的帧就是实际起播点。
只裁包围盒是必须的——整页指标会被大面积纯底色压住，2% 面积的变化看不出来。

2026-10-30 这一版（D 片，30.77s / 13 段 / 14 个绑定元素）：

- **开口前 400ms 内，所有绑定元素的区域变化均为 0** —— 没有「提前出现」。
- **扣除设计偏移后，最大起播延迟 53ms（1.6 帧）**；段内错落也准：页 1 四条
  （设计 240/380/520/660）实测 280/413/547/713，`p3-hero`（+240）实测 247、
  `p3-flow`（+700）实测 713。
- 页 1 的卡片底板 **不建轨道**（页级 `static`），所以页首就是完整的一张卡，
  不再有「空框等 8.9s」。页 1 低覆盖只持续 0.3s、页 3 只 0.5s（改前三处分别是 4.2s / 8.9s / 3.6s）。
- 这版只改了编排，讲解词与音轨一字未动，音画 lag 仍是 0.000s。
  C→D 的逐条对照与代价（页 1 之后 10s 画面不再变化）写在
  `openspec/changes/animation-render-service-image/review-packet.md` §8.8。

### E 片：把「静」也量化之后（同日）

D 片把三处编排改对，观感组从 3 红回到全过——但门禁全过不等于片子好看：
页 1 在第 1.4s 就把四件事铺满，**之后约 10 秒画面一动不动**，而旁白还在逐条念。
原有五组判据问的都是「元素在不在、准不准」，没有一条问「画面还在不在动」。

这一版做两件事：

1. **给 IR 加页级焦点**（`page.focus`）：`[{startMs, elementId}]` 描述「此刻讲的是谁」。
   非焦点元素降透明度（0.55），焦点元素保持。它不进 `clips`——压暗是**互斥**关系
   （甲亮则乙暗），而 clip 的叠加规则是逐属性相加/相乘，表达不了互斥。
   求值只有一份：`shared/motion.ts` 的 `focusDim`，Remotion 与分享播放器共用。
2. **焦点从哪来**：讲解脚本每段多一个 `focus` 字段，与 `bind` 并列。
   `bind` 决定元素**何时出场**，`focus` 决定讲它时**谁让位**。
   之前两件事挤在 `bind` 里，所以只能二选一：绑得早 → 元素齐活后全静；
   绑得晚 → 讲到才出现、前面全空。D 片选了前者，E 片把两者拆开。
3. **新增 V8.1「讲着话时画面不长静止」**：每 100ms 抽一帧缩到 320×180，
   算相邻帧差，连续不变的区间再与讲解区间求交。阈值 3.5s（本片最长一句 3.24s）。

| 读数 | D 片 | E 片 |
|---|---|---|
| 最长「讲着话但画面不动」 | **10.80s**（6.70–17.50） | **3.10s** |
| 第二长 | 4.00s（23.80–27.80） | 2.50s |
| V8.1 | **红** | 过 |

E 片 20 项全过。剩下的 3.10s 是「一句话的长度」——页 1 讲第一条时，
其余三条压暗着，讲到下一条才切换。这是当前结构的上限，不是余量。

#### 压暗带来的一个测量口径问题（已修）

加了焦点之后，`check_appearance.py` 的读数整个错位：`p1-item0` 的到位时刻从 6.03s
变成 12.43s。原因很简单——它拿**页末那一帧**当终态，而页末恰好是「最后一条亮、
前面几条暗」。前面几条被压暗的那一刻，就被判成了「刚到位」。

改成**框内对比度能量**（像素偏离自身中位数的平均绝对值）之后恢复正常：
压暗是仿射变换（`a·x+(1−a)·底色`），中位数跟着移动、偏离量等比缩小，信号还在。
输出的 `preSegDiff`（与终态的灰度差）也随之换成 `preSegLevel`（相对峰值的比例，0–1），
判据「不提前」改成 `preSegLevel ≥ 0.5`。门禁自检 22 → 23 项。

#### 渲染器改了但 plan 没变，会命中旧缓存

`planHash` 只含计划字节与 `RendererVersion` 常量。这次改了合成器（压暗），
plan 一个字节没动，提交后直接复用了上一次的产物——抽帧一看还是旧画面。
换渲染行为时必须同时递增 `RendererVersion`（或清掉 `workdir/<jobId>`），
否则「两次渲染逐字节相同」这条保真基线会保护一个过时的结果。

### 这版样片的边界

- 配音来自 **edge-tts**（免密钥的在线合成），不是产品链路的 SiliconFlow TTS。段落时长是真实的，
  音色与线上不同——判对齐够用，判音质不够。
- 元素 → 段落的绑定是**手写**的 `q7-script.json`，不是模型或规则自动生成的。这证明的是
  「`withSegment` 这条路通、渲染端按时出画」，不证明「绑定能自动生成」。后者是 Q7 第 1 件事。
- 4 个元素刻意不绑定（`p0-eyebrow`、`p0-meta`、`p3-caption`、`p4-note`），放在页末淡入，
  作为「不空转」的对照组。

## 元素→段落的绑定实验（Q7 第 1 件事）

结论写在 `openspec/changes/animation-render-service-image/q7-bind-experiment.md`，
这里只记怎么复跑。

### 三条不要改坏的性质

- **单调对齐**（DP）而不是逐个取最大：后者会把四行条目全绑到第一段，且允许「倒退」，
  而讲解是线性的。
- **绑定来源全部分开记账**：字面 / 计数 / 序数 / 方位 / 同块 / 标题先验 / 结构推断。
  混在一起会把「容器按位置挂上去」算成「文本匹配成功」，召回率会虚高 5–10 个点。
- **golden 可以标 `role: "decor"`**：图标、圆形底座这类伴随装饰绑不上时，不该算成
  内容召回失败。报告里内容召回与总召回分列。

## 结构词消融：0.972 里有多少是「讲稿替你把版面念出来」

6.1 要的是一份真人讲稿，回答「0.972 是否自证」。真人讲稿拿不到，但这个问题有一半
是能算的：**0.972 里有多少来自字面相似，多少来自讲稿里顺着版面说的结构词**
（「第二部分」「分五个部分」「右边那张图」）。写 q8 讲稿的人看着 PPT 写——虽然 golden
是逐条指定、写时没跑绑定器——所以结构词天然会出现，而 v2 的计数 / 序数 / 空间三条
规则吃的正是这些词。

做法是把结构词从讲稿里**删掉**（golden 一字不动，段 id 与段数不动），重跑绑定：

```bash
python3 scripts/fidelity/ablate_structure.py \
  --segments scripts/fidelity/q8-script.json \
  --elements tmp/q8/fid/elements.json \
  --golden   scripts/fidelity/q8-script.json \
  --out-dir  tmp/q8/ablate
```

### 实测（2026-11-01，真实 5 页 / 71 元素）

| 变体 | 删词处 | 召回（内容） | 召回（全部） | 精确 | 漏绑 | 绑错段 |
|---|---|---|---|---|---|---|
| 原始讲稿 | 0 | **0.972** | 0.981 | 0.962 | 0 | 1 |

| 去全部结构词 | 13 | **0.667** | 0.712 | 0.902 | 12 | 3 |
| 去全部结构词（`--rules base`） | 13 | 0.500 | 0.404 | 0.955 | 30 | 1 |

三个读数：

- **13 处结构词撑着 0.305 的内容召回**（0.972 → 0.667）。删掉它们，剩下的 0.667
  才是「字面 + 顺序 + 同块」的本事——这部分抹不掉，是规则真的在做语义。
- **最大单点是 3 处数量词，掉 0.222**，全部集中在目录页那一句「今天分五个部分」：
  一句话撑起 10 条绑定（整页 11 条）。规则的威力和它的脆点是同一处。
- **「几个」与整句删掉同分（0.750）**。规则要的是精确数字，真人说「分几个部分」
  和不说，在它眼里一样——模糊数量现在既不算信号，也没被当成「有信息但不精确」。

自检落点：去全部结构词 + `base` 档得 0.500，与合成口语样本的 `base` 档（0.400）
同一量级；若这条落到 0.9 说明扰动没打准，落到 0.2 说明删出了语法碎片（实测最短段
7 字符，没有空串）。这一条是**扰动的校验**，不是结论。

同一份消融讲稿喂给 Go 实现（`bind.Run`）逐项相同：`exact=37 wrong_seg=3 missed=12
extra=1 both_skip=18`、内容召回 0.667、精确 0.902，来源 `text17 / sibling16 / prior1 /
structural7`。所以这个读数不只是实验脚本的行为——两侧在**扰动后的输入**上也一致，
而不只是在金标这一个输入上一致。

### 这个数能说什么、不能说什么

**能说**：真人讲稿的预期不该按 0.972 报。按「顺序 + 字面 + 同块」这一档，
合理预期是 **0.67–0.75**；0.972 成立的前提是讲稿把版面结构念了出来。

**不能说**：这不是真人讲稿的实测。真人还会换顺序、省略整块、插入题外话、
把四条合并成一句——这四种失效都不在「删词」的覆盖范围里，真实值可能比 0.667 更低。
6.1 仍然需要一份真人讲稿，只是现在有了一个可复现的下界参照。

**产品含义（已修，`changes/animation-prefill-script-signal`）**：`classifyBand` 过去只读元素
几何、不读讲稿，于是「版面有编号/卡片、讲稿却没有结构词」这一格会被判成 `structured`、
不给低置信提示，而实测召回是 **0.667** 而不是 0.972。现在分档要两侧都在才判结构化，低置信
还要说明缺的是哪一侧（`layout` / `script` / `both`）——`script` 档的文案会直接告诉用户
「该改讲解词，不是版式」。这条判据与规则同口径（数量词走 `detectCount` 的 2..12，
「高一个点」不算结构），否则会出现「分档说有信号、规则一条也绑不上」。

### 为什么是「对账」，不是「把三个脚本串起来」

5.5 与 5.6 两轮评分都没能收口，查下来片子两次都不是主要问题，**是测量工具有盲区**：

| 洞 | 表现 | 现在怎么堵 |
|---|---|---|
| `check_alignment.py` 只回看开口前 400ms | 元素若更早出现，窗口里它「已经在了」，差恒为 0 → 报「不提前、准时」。**「通过」和「看不见」长得一模一样** | 门禁 V4.1：凡是 `settledMs` 早于该窗口起点的元素，直接判它的读数无效 |
| 判据写「3 帧」，播放器没有步进键 | 评审人没法数帧，只能凭观感给分 | `q7.html` 的 `←/→`、0.25–1×、「距开口 ±N 帧」直读；`probe-q7.mjs` 回归它 |
| 参照点是文本时间轴 `startMs` | 音频整体偏移（AAC priming）一个都发现不了 | `check_av_sync.py` 量音画 lag，门禁要求 ≤ 1 帧且互相关峰够尖 |

所以门禁的第一职责不是「再测一遍」，是**拒绝在证据自相矛盾或结构上看不见的时候放行**。

### 为什么又加了一组 V7：前六组全过，人看着还是不对

**前六组问的是「元素准时吗」，而人看的是「这一刻画面上有多少东西」。**
这是两个问题，前者全过不蕴含后者成立。V7 就是后者：

- **V7.1 内容覆盖**：已到位元素占本页内容面积的比例。低于 50% 且持续 ≥1.5s 判红。
  **按面积不按像素**：像素法在页 1 上是瞎的——10.15s 时四条要点只出两条，
  卡片里空着三分之二，但卡片底色已经铺满，整页像素到位率 93%。九宫格也不够，
  底色同样占满每一格。
- **V7.2 空框悬挂**：容器的框先出现、内容后填，超过 2s 判红。观众看到的是
  「还没加载完」。

容器不计入覆盖分母：卡片底板到位不等于内容到位，算进去会让空盒子看起来是满的。

**加上 V7 之后，同一条片子从 14/14 变成 3 项红**（页 1 空 4.2s、页 1 空框 8.9s、
页 3 空 3.6s）。这不是片子变差了，是门禁终于开始问对问题。

`audit_layout.py` 是这个检查的独立工具版：多了「页末闪现」（元素出现到本页结束
不足 1s —— 它不影响任何一刻的画面完整度，但等于没出现），并且打印每个时段的
缺件清单，适合调排版时手跑。

### `check_appearance.py` 现在报三个数，别用错

参照物换过三次，前两次都被片子推翻（详见 `review-packet.md` §8.10）：

1. **该页最后一帧** —— 被页级焦点打破：页末是「最后一条亮、前面几条暗」，
   前面几条被压暗的那一刻判成「刚到位」。
2. **框内对比度能量** —— 被实心块打破：柱子长满后框内是一整块纯色，
   能量在「长了一半」时最高，四根柱子全被报成「整页未稳定出现」。
3. **出场前那一帧**（现行）—— 信号是「框内与它出现之前差多少」，连续量。
   柱子 0→峰值、淡入 0→峰值、压暗等比缩到 0.55 仍在半程以上。

| 字段 | 含义 | 能判什么 |
|---|---|---|
| `settledMs` | 变化量最后一次低于峰值一半的下一帧 = **到位** | 到位时刻。带淡入的元素比开口晚一个淡入时长（220–450ms），**不能拿来判滞后** |
| `onsetMs` | 变化量第一次达到峰值 30% = **开始变** | 只作诊断。若背后有同步淡入的容器，读数会塌到容器出现的那一刻 |
| `preSegLevel` | 开口前 100ms 那一帧的变化量占峰值的比例（0–1） | **「不提前」就用它**：还没出现 → ≈0；已经在了 → ≈1 |

`LEVEL_SETTLED` 必须留 0.5 而不是 0.85：非焦点元素被压到 0.55 不透明度，变化量随之
落到约 0.55；取 0.85 的话，压暗那一刻会被当成「又到位了一次」（页 3 的流程块踩过）。

## 模型通道对照（6.2）

规则通道在「讲稿不替版面念结构词」的那一档只有 **0.667**（见上一节的消融实验）。
6.2 要回答的是：**接一个模型，能不能补上这 0.08–0.33 的缺口**。

`bind_llm.py` 是这一步的离线对照，不碰产品代码：同一份夹具、同一份 golden、
同一套指标（`compare` / `summarize` 直接从 `bind_elements.py` import，不重写）。

### 三条约束写进了代码

| 约束 | 落点 | 为什么 |
|---|---|---|
| 模型只输出 id 映射 | `SYSTEM_PROMPT` + `validate` | 输出越窄，校验越能做成纯函数；不许它给时间、坐标、改写文本 |
| 确定性只能靠缓存 | `cache_key` / `call_cached` | 温度 0 + 固定模型版本**实测仍不保证**同结果（同 prompt 三次 6/11/7 条）；key = model + promptVersion + 采样序号 + 输入 |
| confidence 不作门槛 | `judge` 只看金标召回/精确 | 自我评价与正确率没有校准关系，它只能用来排序复核 |

校验器有六条拒绝规则：越界 id、非法段、重复、**规则已绑（rule_locked）**、aux 元信息、
无文字装饰、非法 confidence。`rule_locked` 单独记而不并进 `duplicate`——「模型重复输出」
和「模型想覆盖规则」是两种失败，混起来就看不出来了。

### 三条不需要 key 的出口

一条命令先跑完前两项，没有 key 就明确跳过第三项并退出 0：

```bash
./scripts/fidelity/llm_check.sh
```

拆开看：

```bash
# 1. 校验器 + 评测链路 + 门槛判定的自测（含反向验证：削弱任一条就会红）
python3 scripts/fidelity/bind_llm.py --selftest

# 2. 用同一套评测路径重算规则基线，并与锚点对账
python3 scripts/fidelity/bind_llm.py --rules-baseline

# 3. 打印将要发送的 prompt 与 token 估算，不发请求
python3 scripts/fidelity/bind_llm.py --dry-run
```

`--rules-baseline` 是脚本正确性的锚：它必须复现 **0.972 / 0.962**（q8 原稿）与
**0.667 / 0.902**（去全部结构词）。对不上就是脚本或规则漂了，先查这个再谈模型。
口语样本只做**软锚点**（只打印差值不判红）——那个 0.533 属于旧夹具，硬校验一个已失效
的数字只会训练人「看到红就改阈值」。

### 门槛（不过就不上线）

| 变体 | 判据 | 门槛 |
|---|---|---|
| 去全部结构词（主战场） | 内容召回 | ≥ 0.75（规则 0.667） |
| 去全部结构词 | 精确 | ≥ 0.90（错绑不可见） |
| 口语样本 | 内容召回 | ≥ 0.70 |
| 原稿（不能倒退） | 内容召回 | ≥ 0.922（规则 0.972 减 0.05） |

### 实测 Ⅰ：先跑单轮，结论是错的

`--mode model` + 默认 `--struct-fill`（模型绑完再用规则补容器与标题），每档只跑一次：

| 变体 | 模型召回 | 模型精确 | 规则召回 | 规则精确 |
|---|---|---|---|---|
| q8 原稿 | 0.694 | 1.000 | **0.972** | 0.962 |
| q8 去全部结构词 | **0.972** | 0.975 | 0.667 | 0.902 |
| q7 口语样本 | 0.353 | 0.400 | 0.353 | 0.750 |

按这张表得出的结论是「模型补 0.305，精确还高 0.073」。**这个结论站不住**，因为它是
一次抽样。下面这条线索是自查时发现的：同一页、同一 prompt、同一模型，两次调用的
召回差了 10 倍（1.000 对 0.091）。于是有了实测 Ⅱ。

### 实测 Ⅱ：温度 0 不等于确定性

同一段 prompt 连调三次，模型分别输出 **6 / 11 / 7 条绑定**（completion token 196 / 254 / 168）。
`temperature: 0`、`top_p: 1`、`response_format: json_object` 全都设了，网关仍然每次不一样。

所以必须多次采样。`--repeat 5`，同一变体独立跑 5 次（采样序号进缓存键，重跑可复现）：

| 变体 | 各轮召回 | 均值 | **最差** | 极差 | 精确均值 | 规则召回 / 精确 |
|---|---|---|---|---|---|---|
| q8 原稿 | 0.972 / 0.472 / 0.583 / 0.944 / 0.722 | 0.739 | 0.472 | **0.500** | 0.983 | 0.972 / 0.962 |
| q8 去结构词 | 0.806 / 0.972 / 0.694 / 0.833 / 0.861 | 0.833 | 0.694 | 0.278 | 0.966 | 0.667 / 0.902 |
| q8 混合 | 0.833 / 0.861 / 0.472 / 0.944 / 0.750 | 0.772 | 0.472 | 0.472 | 0.985 | 0.694 / 0.927 |

**0.972 是 5 轮里最好的一次，不是稳定值。** 原稿上模型的极差是 0.500——同一份输入，
运气好 0.972、运气差 0.472。任何单次测量都不能当结论。

修正后的三条：

**一、「模型补 0.305」改成「均值补 0.166，最差轮只补 0.027」。** 去结构词档规则 0.667，
模型均值 0.833、最差 0.694。收益是真的，但只有原报告的一半，而且下界贴着规则。
按「门槛用最差一轮」的口径，这一档**过不了 0.75 的门槛**。

**二、模型不能替代规则，这条反而更稳。** 原稿 5 轮全部低于规则 0.972，均值 0.739。
差距的来源仍是目录页：一句话「今天分五个部分」对应 11 个元素，规则的数量词规则一把
全绑上，模型最好一次也只绑 1 条。**「一段话概括 N 项」是确定性结构推理，模型学不会**。

**三、格式合法率仍是 100%。** 25 次调用里没有一条非 JSON、没有编造 id；精确均值
0.966–0.985 高于规则 0.902–0.962。模型错得少，但漏得多——它是保守，不是乱来。

| | run0 | run1 | run2 | run3 | run4 | 最差 |
|---|---|---|---|---|---|---|
| 路由 − 全模型 | 0.000 | +0.111 | **+0.250** | +0.028 | +0.111 | **0.000** |
| 路由 − 全规则 | +0.139 | +0.278 | +0.028 | +0.278 | +0.167 | **+0.028** |

**五轮里路由一次都没输给全模型，且每轮都优于全规则。** 这条判据写进了
`route_gate()`，取最差一轮守门——不是「平均不输」就算过。

但收益的来源和预期不同，这点必须说清：

- **不是模型更强，是规则在某些页上没有短板。** 四步流程页（p3）规则 18/18，模型
  三个变体都是 10/18（漏 8 条容器/配图，`:struct-fill` 只补回 4 条）。把它固定给规则，
  等于每轮白捡 8 条，方差也随之消失——路由的极差 0.250 低于全模型 0.472。
- **路由有确定的代价：精确从 0.985 降到 0.956。** 封面页（p0）被判 `structured` 走规则，
  而规则在这一页只有召回 0.5、精确 0.333（1 正确 / 1 错段 / 1 多绑）。`clusters` 信号
  在「标题 + 副标题」的封面上会误判成卡片簇，但那一页并没有讲解顺序。这条已记进
  tasks 6.2 的遗留项，没有在这次改动里修。

### 样本三：真实客户 deck，测出了两个和讲稿无关的缺陷

前两个样本都有讲稿，也都「干净」。第三份是真实的商业方案
（`大模型Token私有化运营解决方案V2`，33 页 392 元素；客户资料，不入库，复现需自备同类 deck），
拿它的过程本身出了两条结论。

**它不能当绑定样本。** 24 个 notesSlide 里只有 6 页有正文，且都是资料出处与功能清单
（「China Daily / 艾瑞咨询《2026…》」），不是口播稿。把这 6 页当讲稿跑规则绑定，
只有 3 页绑得上（2 + 5 + 6 条），另 3 页一条没有。

**它能当版面样本，而且当场测出两件事。**

**一、「有分段但一个字没有」被当成「讲稿没念出结构」。** 先把边界说清：完全没讲稿的页
走不到分档——`internal/api/animation.go` 在 `len(segs)==0` 就短路成 `no_segments`，
前端显示「预填已跳过」，这条路径本来就是对的。真正出问题的是**有分段、文本全空**
（讲稿生成失败、占位段）：它会进 `classifyBand`，而 `hasScriptStructure` 返回假值，
于是判 `low-confidence / script`、信号 `script-flat`，编辑器说「讲稿没有把它讲出来……
要提升就先改讲解词」——这一页根本没有讲解词可改。

同一个假值还漏到了离线侧：`bandcheck` 和 `bind_llm.py` 直接喂 `classifyBand`，没有 API
那层短路，33 页空讲稿因此全被判 `script-flat`。现在分开：全空段落出
`script-absent` / `no-script`，文案是「先写讲解词」。造出来的 5 页样本每页都有讲稿，
这条分支永远测不到，所以七版测试都没发现。

**二、绑定器吃的是 z-order，不是阅读顺序。** 自引用召回（`selfrecall.py`：把页面自己的
文字当讲稿，看能不能绑回自己，两种造稿方式见脚本头）。第一次修复前测到的对照：

| 样本 | 元素按 z-order 喂 | 按阅读序喂 |
|---|---|---|
| 33 页 Token 方案 | 62.8% | **92.6%** |
| 14 页客户 deck | 76.9% | **100%** |
| 5 页造样本 | 80.6% | **100%** |

`align` 的单调 DP 假设「元素顺序就是讲解顺序」，而 `PageBindElements` 用的是
`walk(page.Shapes)`——形状树顺序。作者先放正文块、后放标题，整页顺序就是反的
（p6 的 y 从 676 一路递减到 30）。现在 `bind.Run` 入口统一按阅读序重排（`order.go`），
调用方给什么顺序都不影响结果。回归锚点没动：q8 仍是 0.972 / 0.667，5 页 53 条绑定。

**三、行带的基准不能是空形状，容差也不能被底板撑大。** 上一版结论说剩下的 7.4%
是「同前缀短标签互相摊薄，要靠容器分组」——**这个判断错了**。同一页 8 个 `Token*`
标签本身没出问题，出问题的是**行带**：

- 行带容差取「中位高度 × 0.6」。全 33 页算高度时把底板、蒙层一起算进去，
  中位高度被 200–300px 的高盒子抬高，`p16` 的容差 32.4px 把 y=546 的 `Token增值`
  和 y=570 的 `智能体` 并成一行；行内按 x 排序，右栏的 `Token增值`（x=1577）
  被排到正文 `智能体`（x=1183）之后。讲稿里它是前一句，单调对齐于是把 1.00 的
  精确匹配换成后一段的 0.52。
- 更隐蔽的一条：一行字从上往下扫，第一个落进这一行的元素就是基准线。底板常比它装的
  文字高、顶边也靠上几像素（`p7` 的底板 y=326，字在 331），基准线被抬高后，
  下一行字（y=382，只差 51）掉出了这一行，顺序反过来，`核心逻辑闭环` 整段让给了
  后面的段落，自己反倒变成「同块带出」。

两处一起改：容差与分行只拿**有文字**的元素做（底板的高度不参与、底板也不当基准），
空形状随后挂到纵向中心最近的那一行——它从不参与字面匹配（相似度恒为 0），
放进哪一行对结果没有影响，唯一的影响就是那条基准线。`selfrecall.py` 同步成同一套
（一份 `bands`），否则离线实验和产品行为量的不是同一件事。

同一批 gold 口径下的前后对照：

| 模式 | 修复前 | 修复后 |
|---|---|---|
| per-element（一元素一段） | 135/146 = 92.5%，字面精确 94.4%（错绑 8） | **144/146 = 98.6%**，精确 98.6%（错绑 2） |
| per-row（一行一段） | 137/146 = 93.8%，精确 96.5%（错绑 5） | **146/146 = 100%**，精确 100% |

`p16` 从 94.4% → 97.2%（唯一漏掉的是个省略号），`p7` 从 75% → 100%。

顺带修了 gold 的两处口径：`…` / `……` 这类纯标点归一化后是空串，任何阈值都绑不上，
算进 gold 只会凭空扣分（产品侧它本来也不该有出场动画）；容器推断（`structural` /
`sibling` / `prior`）作用在没有文字的形状上，gold 里没有它们的条目，
按「不在 gold 里就算错」统计会把精确率系统性压低——现在分开报，精确率只对字面匹配定义。

**四、同文元素被堆到同一段上。** 上面两条改完后还剩 2 条，`p32` 两个一模一样的
`主要产品`（左右两张卡片各一个）、`p16` 两个一模一样的 `Token运营`（网关框内、右栏各一个）。
不是「只有位置能区分」——是 DP 的退化解与正解**同分**：`bind` 分支不推进 `j`，
所以「两个都绑第一句」（0.8+0.8）与「各绑各的」（0.8+0.8）总分相等，它选了前者，
第二个句子空着，第二个元素成了错绑。

先试过「位置先验」（按元素与段的相对位置加一个万分之一量级的加分）——**p16 修好了，
p32 没动**：p32 有 26 个元素、9 段，归一化后元素 0.23 处离段 3.5/9 比离 4.5/9 更近，
先验反而把两个「主要产品」都推向第一句。前提（元素数与段数相当）不成立，这条先验
已撤掉。

改成直接做局部修正（`spreadDuplicates`）：一段上堆了多个元素时，从第二个起依次挪到
后面**同样匹配（分数不低于原段）、且还空着**的段，且不越过后面已被占用的段（越过就
打乱单调顺序）。只在同文时才会触发——讲稿只提了一次时后面没有对应句，挪过去分数会降，
那时保持原样，「一段带出多个元素」本来就是常态。

改完 33 页 per-element 与 per-row 都是 **146/146 = 100%**，字面精确 100%；
q8 真实讲稿锚点 0.972 / 0.667 与 q7 0.353 一条没动。

### 还缺什么

- **延迟仍不达标，而且比单轮更差**：5 轮并发的 P95 是 28–43 秒（含 429 重试），
  单页生成 4–13 秒。结论不变：**必须异步 job**，不能挂在同步的 `?prefill=true` 上。
- **样本太小**：5 页 × 5 轮 = 25 个观测，够看出方差，不够定阈值。极差 0.5 说明
  要 20 轮以上才能把均值压到 ±0.05。真要做产品决策，得扩充页数而不是加大采样。
  版面侧的页数已经补上了（33 页真实 deck），但**绑定侧的页数还没补**——那 33 页没有讲稿，
  要有人写 8–10 页的口播稿才能进 `bind_llm.py`。
- **中间样本只造了一种**：`--mix-pages 1,4` 是唯一一次混合。换个消融组合（比如只消融
  目录页）结论可能不同——路由的收益取决于「有多少页是模型永远漏 8 条的那种」。
- **模型不可迁移**：`agnes-2.5-flash` 格式错 57.9%、召回 0.306；`agnes-2.5-pro-alpha` 403。
  3.0-flash 是当前唯一可用档，换版本必须重跑。
- **q7 口语样本没做多轮采样**：单轮 0.353 / 精确 0.400，与规则同分。它回答的是
  「版面本身没结构时模型能不能救」——不能。这条不依赖方差就能定，但严格说也是单轮。

### 产品侧实现（M1b 异步通道，2026-11-01）

「必须异步 job」这条结论已经落到产品代码里。入口不再是同步的 `?prefill=true`，
而是 `POST .../animation/prefill`：

| 分档 | 走什么 | 响应 |
|---|---|---|
| structured | 规则（0.972 对模型的 0.772） | 200，当场给规格，不建任务 |
| layout / both | 规则（0.533 对 0.353，模型救不回来） | 200，当场给规格并标低置信 |
| **script** | 规则底稿 + 后台问模型（0.667 → 0.833） | **202 + jobId**，`GET .../prefill?jobId=` 换结果 |
| 无分段 | 不预填 | 200，`applied=false reason=no_segments` |

几个刻意的选择：

- **受理时一定返回一份可用的规格**。模型挂掉、超时、额度不足时，用户手里仍有可编辑的
  规则底稿——而不是一屏空白加一个红字。所以 `POST` 的 `spec` 永远可以直接渲染。
- **快照里带元素与分段**，worker 不重新解析。解析产物在排队期间可能被新版本覆盖，
  那时绑的是另一版页面的元素，结果却落回这一页——一片看得见但查不出的错绑。
- **结果按内容指纹落对象存储**（`prefill/slide.<hash>.json`）。页面文字或讲稿一改指纹就变，
  旧结果自然读不到，不需要任何失效逻辑。指纹只算元素与分段，不算预设/语言：
  换预设不该触发一次模型调用。
- **token 预占/结算进同一本账**（`usage.KindLLMTokens`），额度不足时**不发请求**
  （发出去再退是退不回来的），原因记 `quota`。取消/失败由 worker 释放预占，
  逻辑操作 id 由 `app.PrefillOpID` 单点定义。
- **命中已终结任务时换键重开**：否则这一页的预填会永久停在上一次的失败上，
  重开编辑器也只会等到同一个终态。

前端侧（`AnimationEditor`）在模型结果到达时**不无条件覆盖**草案：底稿上屏后用户可能
已经开始调强度、拖轨道，静默替换等于把这十几秒的手工调整扔掉。未改动则自动换，
已改动则挂一条「采用模型结果」由用户决定。

`GET ?default=true&prefill=true` 的同步路径保留：它是纯规则的，毫秒级，作为兜底还在。

### 真机联调（`scripts/e2e/prefill_live.sh`）

上面所有用例都停在进程内：假 resolver、假模型、假账本。它们证明不了「服务端把快照交给
worker 之后还是同一份内容」，也证明不了「HTTP 请求真的按 OpenAI 协议发了出去」。这两件事
只有跑真实进程才能验：

```bash
bash scripts/e2e/prefill_live.sh
```

它起真实的 `ppts server` + `ppts worker`（SQLite + 本地对象存储 + fake TTS），模型侧用
本机假 OpenAI 兼容服务（`scripts/e2e/fake_llm.py`，协议是真的，答案是固定的）。八步走完
上传 → 解析 → 讲稿 → 配音 → 预填 → 模型 → 落盘 → 读回，并逐步断言：

| 步骤 | 断言 | 它拦的是什么 |
|---|---|---|
| 5 | script 档返回 202，最终 `route=model` | 快照/路由接错，模型根本没被问 |
| 6 | 模型停掉后 `route=rule` + `fallback=error`，任务仍成功 | 模型挂掉时编辑器拿到空白 |
| 7 | 模型恢复、内容不变，再点预填仍是 202 并重新问模型 | **上一次失败被当成结论缓存**（见下） |
| 8 | 结果成功后再点走 200，模型调用次数不变 | 一轮修复把缓存整个废掉 |
| 5–8 | 每步顺手查 `/metrics`：`runs{route,band,reason}`、`fallback{reason}`、`model_calls`、`cache{result}` | 计数只写在代码里、没接上；标签被渲染成指标名的一部分 |
| 末 | `usage_ledger` 有 `prefill:<jobId>` 的 token 记账 | 「预填偷偷烧额度」 |

第 7 步是这次联调抓到的真缺陷：结果按内容指纹缓存，而缓存短路排在路由之前，于是
「模型没问成」的失败结果也会被当成成品复用。实测现象是——模型服务恢复后，同一页反复
点预填始终显示 `fallback=error`，模型一次都没被调用，只有改一个字（换指纹）才恢复。
配上模型却不生效，比多花一次调用糟得多，所以现在只有 `Model.Fallback == ""` 的结果才短路
（`TestPrefillPostRetriesCachedModelFailure` 钉住它，且在旧实现上会红）。

脚本会直插一行 `narration_scripts`（`source_revision_no=0`）：产品里的讲稿来自「AI 生成草稿」
或「PPT 备注导入」，两条路都要 LLM 或备注，而这一段要验的是预填不是讲稿生成。此后每次编辑
仍走真实 RPC（`ScriptService.Update` 会从 legacy 分叉）。

它**不点前端**：界面与像素归 `npm run animation:test` 与 `web/animation-check.mjs`。
这里保证的是「后端到模型到落盘再读回」这条路是真的。点下去之后看到什么，归下一节。

### 点击级联调（`scripts/e2e/prefill_click.sh`）

接口返回 202 和一份规则底稿，只说明服务端守约；它不说明编辑器真的把底稿摆上了屏，
也不说明模型结果到了以后是替换、是挂一条「采用模型结果」，还是悄悄丢了。

```bash
bash scripts/e2e/prefill_click.sh          # 没有现场会先跑一遍 prefill_live.sh
KEEP=1 bash scripts/e2e/prefill_click.sh   # 跑完留住浏览器与服务，供人工接着看
```

它复用 `prefill_live.sh` 留下的 `tmp/live-e2e/run.json`（项目、页面、端口、指标 token），
重启 server/worker，用 `FAKE_LLM_DELAY_MS=5000` 把异步窗口撑开，然后启动无头 Chrome，
通过 CDP 真点：左边栏第 N 页 → 「动效」→「按讲稿自动绑定」。三个场景各管一条分支：

| 场景 | 做了什么 | 断言 | 它拦的是什么 |
|---|---|---|---|
| A 主路径 | 点完不动 | 2.5s 内按钮变「正在按讲稿绑定…」且复核区已有「N 条预填绑定」；最终无「没有采用模型结果」；探针看到 POST 202/pending、GET `route=model` | 底稿没先上屏；模型结果被静默丢弃却看着一切正常 |
| B 用户改过 | 底稿上屏后把强度从 1.00× 拖到 1.30× | 模型到达时强度仍是 1.30×、复核区仍是规则那份；出现「采用模型结果」；点它之后强度变回 1.00× | 静默覆盖用户手工调整；或既覆盖又挂「采用」按钮——把选择权给了一个已经生效的结果 |
| C 等不到 | 拨快页面时钟 120s，越过 90s 预算 | 3s 内按钮放开，面板出现「模型结果迟迟没有回来」 | 任务一直 pending 时按钮永久禁用，用户只能刷新页面 |

A 的因果很直接：模型要 5s 才回，2.5s 时看到的那份只可能来自 202 的规则底稿。
C 只拨时钟、不改预算常量——预算判断本身要跑产品代码，改了常量验的就是另一个预算。
C 还把上限压在 3s：若预算失效，模型 5s 后正常返回同样会放开按钮，这条断言就退化成 A，
所以放开的那一刻还要查探针，确认没有 succeeded 记录。

A 的第三条用探针而不是猜 DOM，因为规则与模型在这一页恰好都是 8 条绑定，数字区分不了；
脚本会把这件事打出来（`注意：规则底稿与模型结果都是 8 条`），不假装是替换的证据。

**三个场景各自验证过会红**（改实现 → 重跑 → 恢复）：

| 破坏 | 结果 |
|---|---|
| `runPrefill` 改回 M1a 的同步行为（pending 时不 `setDraft`） | A 第一条立刻红：「当前按钮=正在按讲稿绑定… 复核区=""」 |
| 把「用户改过」的判据改成恒真（永远静默替换） | B 红：「强度从 1.30× 变成了 1.00×」 |
| `prefillWaitExpired` 恒返回 false | C 红：3s 内按钮没放开 |

三次都是恢复后重新变绿。没有这一步，这些用例和「页面能打开」没有区别。

**一个容易踩的坑**：Node 的 `fetch` 会自动带 `Accept-Language: *`，而服务端在缺
`X-PPTS-Language` 时优先取它，于是拿 `*` 去查讲稿，得到 404 `narration: script not found`。
同一个请求 curl 与 `node:http` 都是 200——差别全在这个头。脚本现在显式带
`X-PPTS-Language: zh-CN`。（前端本身是显式带这个头的，所以线上不受影响。）


它不动内容指纹就验不了：同一页已有成功缓存，直接命中会走 200 同步通道。所以脚本先用
`ScriptService.Get/Update` 在第一段末尾追加一个零宽空格。每次运行追加的数量 +1，内容逐次唯一
——用「加句号／去句号」两态来回切会撞上之前跑出来的缓存，这一条在写的时候踩过，表现是
按钮直接变「重新按讲稿绑定」、根本没有 pending 阶段。

不做的事：不比对像素，不做多浏览器兼容。它回答的是「异步通道在界面上走得通」，
画面好不好看仍归保真脚本。

### 可观测（`/metrics`）

预填跑在 worker 里，产物只有一份 JSON——**不问就只能靠用户说「感觉慢」**。四个计数
（`internal/observability/prefill.go`）各回答一个具体决策：

| 指标 | 回答的问题 | 数值异常时该动哪里 |
|---|---|---|
| `ppts_animation_prefill_runs_total{route,band,reason}` | 这一档页面到底有没有走模型 | `route=rule` 而 `reason=script` 占多数 → 路由/模型配置没生效 |
| `ppts_animation_prefill_model_fallback_total{reason}` | 没用上的原因分布 | `quota` 充值、`timeout` 调超时或查网关、`no_model` 配模型 |
| `ppts_animation_prefill_model_calls_total` + `..._latency_ms_total` | 真调用了几次、平均多慢 | 均值逼近 45s（`defaultModelTimeout`）→ 超时给得太松 |
| `ppts_animation_prefill_cache_total{result}` | 复用/重算的比例 | `retry_after_failure` 随打开次数线性增长 → 该考虑负缓存 |

两个刻意的口径：

- **`band` 与 `reason` 分开标**。`band` 只有 `structured` / `low-confidence` 两种，而
  `low-confidence` 里「讲稿没念出结构」（值得问模型，实测 0.833）与「版面本身没结构」
  （问也白问，0.353）是同一档。只看 band 会发现 `route=rule` 占多数，却分不出这是正常
  还是整档在空跑。
- **`fallback` 的空值不记**。空串是「模型正常产出」或「这一页本就不该问」，记进去会让
  回退率的分母变成全部任务，看起来永远正常。

前端另有一条**等待预算**（`PREFILL_WAIT_BUDGET_MS = 90s`，服务端模型超时 45s）：任务一直
`pending` 时按钮是禁用的，没有预算就意味着一次「任务没被领走」能把按钮永久按住，用户除了
刷新页面没有出路。超预算后停止轮询、放开按钮，原因记成 `client_timeout`——与服务端的
`timeout` 分开：前者查 worker 有没有起、任务有没有被领取，后者说明模型自己慢。

### 复现

```bash
# 1. 全模型，5 轮采样（决定「能不能用」）
PPTS_LLM_API_KEY=... python3 scripts/fidelity/bind_llm.py \
    --base-url https://apihub.agnes-ai.com/v1 --model agnes-3.0-flash \
    --mode model --variants baseline no-structure mixed --repeat 5 \
    --out-dir tmp/q8/llm-rep --cache-dir tmp/llm-cache-rep

# 2. 分档（用产品代码，不要在 Python 里复刻）
go run ./scripts/fidelity/bandcheck -elements tmp/q8/fid/elements.json \
    -segments tmp/q8/mixed-script.json -out tmp/q8/band-mixed.json

# 3. 按页路由，同样 5 轮（与第 1 步共用缓存，不额外花钱）
PPTS_LLM_API_KEY=... python3 scripts/fidelity/bind_llm.py \
    --base-url https://apihub.agnes-ai.com/v1 --model agnes-3.0-flash \
    --mode route --variants mixed --repeat 5 \
    --band-file tmp/q8/band-mixed.json \
    --out-dir tmp/q8/llm-rep --cache-dir tmp/llm-cache-rep
```

缓存按 `model + promptVersion + 采样序号 + 输入` 分键：同一 sample 重跑命中即同结果，
不同 sample 才是新抽样。`--no-struct-fill` 关掉结构收尾，得到的是模型的裸成绩。

自引用召回不需要讲稿、不花钱，任何时候都能跑——它是「绑定器本身还准不准」的体检：

```bash
# 先抽元素，再让页面自己当讲稿
python3 scripts/fidelity/selfrecall.py --elements tmp/q9/fid/elements.json \
    --mode both --out tmp/q9/fid/selfrecall.json --worst 8

# 对照：order.go 上线后绑定器内部会自己重排，--order asis / reading 已经同结果；
# 这个开关留着是为了能复现「不重排会怎样」的旧对照，不是产品路径
python3 scripts/fidelity/selfrecall.py --elements tmp/q9/fid/elements.json --order asis
```

修复后两者应当一致；不一致就说明 `readingOrder` 没生效，或者有人在调用链上又排了一次序。

## 配音 PPTX 的客户端门禁（G0-8）

结构校验只能证明「我们按规范写了」，不能证明**客户端认**。PowerPoint 判损的触发点很杂
（关系指向、内容类型、计时树引用、媒体图标几何），任何一条不合它的意，它会弹「需要修复」
然后悄悄丢掉一段。所以这一项单独立门禁，而不是靠 `Validate()` 通过就算数。

```bash
# 完整门禁（Windows + PowerPoint，约 40s）
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/e2e/audio_pptx_gate.ps1

# 只验包结构（任何平台，CI 可跑）：同上加 -SkipClient
```

三段，失败即停：

1. **生成**（`scripts/e2e/audiogate`）走产品同一条写入路径
   （`integrations.GoPPTXNarrationWriter`），源文件用仓库里的真实 deck（14 页、含图片与
   多级文本），不是合成的最小页——修复提示多由复杂版面触发，最小页测出来的「能打开」
   证明力很弱。每页音频是不同频率的合成音：可按频率区分「这页放的是不是自己那段」，
   也不必依赖 TTS。
2. **包结构**（`audiogate/verify`）：每页 `<p:transition advTm>` 与该页停留时长一致；
   音频页有 `presetClass="mediacall"` + `playFrom(0.0)`（进页即播）；
   `endCond evt="onStopAudio"`（离页即停，这是「不串音」的结构表述）；
   没有 `numSld`（没有跨页播放声明）；每页的 audio 关系指向**自己的**部件，
   且 WAV 头算出的时长等于该页计划时长；`[Content_Types].xml` 声明了 `audio/wav`。
3. **客户端**（`pptx_client.ps1`）：PowerPoint 无窗口打开 → 逐页读回对象模型 → 另存 .pptx
   → **重开另存后的文件**再读一遍。断言：媒体形状数（音频页 1、静默页 0）、
   `MediaType=2`（ppMediaTypeSound）、`AdvanceOnTime` 与 `AdvanceTime`、
   `MainSequence` 里恰好 1 个 `EffectType=83`（msoAnimEffectMediaPlay）且时长等于该页音频。
   重开后上述全部不得变化——这一条就是「重开保存」。

**修复提示怎么判**：需要修复时 PowerPoint 弹模态框并阻塞 `Open()`，于是脚本在超时窗口内
回不来；编排脚本用 `Start-Job` + `Wait-Job -Timeout` 压住它，超时即判 `REPAIR_PROMPT`。
这与 go-pptx L3 的判据是同一套。打不开（`CLIENT=FAIL ... could not open`）是另一条快速
失败路径，同样判失败。

### 实测（2026-11-01）

| 项 | 结果 |
|---|---|
| 客户端 | PowerPoint **16.0**，14 页，打开 / 另存 / 重开均成功，无修复提示 |
| 断言 | 结构 177 项、含客户端 329 项，**0 失败** |
| 重开保存 | 各页媒体形状、自动切页、媒体效果时长与保存前逐项一致 |
| 静默页 | 第 3 页无音频，仍有 `advTm="1500"`，客户端读到 `AdvanceOnTime=True / 1.5s` |
| 留白页 | 第 6 页音频 2.4s、停留 3.1s：效果时长与停留时长分开，各自对得上 |

### 有牙验证（各自恢复后变绿）

| 破坏 | 结果 |
|---|---|
| 删掉 `slide1.xml` 的 `advTm` | `缺自动切页时长 advTm="2000"` |
| 让第 2 页的 audio 关系指向第 1 页的 wav | `音频时长 2000ms，计划 2600ms` + `被 slide1、slide2 共用` |
| 把某音频页的 `onStopAudio` 改成 `onStop` | `缺 onStopAudio 结束条件（切页可能串音）` |
| 伪造客户端报告：`advanceOnTime=false` | `第 1 页：客户端认为没有自动切页` |
| 伪造客户端报告：删掉媒体效果 | `第 1 页：媒体播放效果 0 个，期望 1 个` |
| 伪造客户端报告：重开后丢自动切页 | `重开保存后第 1 页：自动切页丢了` |

第三条第一次没打中：破坏打在了第 3 页，而那是静默页，本来就没有 `onStopAudio`——破坏样本
本身无效，跑出来是绿的。换成第 4 页才真红。**验证「用例有牙」时，先确认破坏真的破坏了目标。**

### 这个门禁不证明什么

- **不证明「真的出声」**。COM 读得到媒体形状、播放效果与时长，读不到扬声器有没有响。
  脚本通过后仍要人工按 F5 听一次（清单在脚本末尾打印）。这是唯一保留的人工项，不要把它
  当成已自动化的部分。
- **音频不是 TTS 结果**。这里验的是容器与计时；音轨拼接（`media.AssembleTimelineWAV`）
  由导出链路的用例覆盖。
- **没有覆盖 WPS**。WPS 与 PowerPoint 的故障模式不同（前者宽容、后者严格），要验得另跑
  一遍 `Kwpp.Application`；本机没装，未做。

### 写的时候踩到的（都留在代码里）

- **ps1 必须纯 ASCII**：Windows PowerShell 5.1 把无 BOM 文件按 ANSI/GBK 解码，UTF-8 多字节
  序列会吞掉后面一个 ASCII 字节（包括引号），报的是与真实原因无关的语法错误。
- **PowerPoint 是单实例**：`New-Object -ComObject` 会附着到用户已打开的实例；只有本次新建的
  才允许 `Quit()`，否则会关掉用户正在编辑的文档。残留实例只清理「本次新起的 PID」。
- **`Stop-Job` 没有 `-Force`**（PS 5.1），写了会直接抛参数错误。
- **`$null -ne 0` 为 True**：`PlayInBackground` 实测返回空值，若用它判「是否跨页播放」，
  每个文件都会被报成后台播放。改用 XML 的 `numSld` / `onStopAudio`。
- **PowerShell 的 `>` 默认写 UTF-16**：计划 JSON 由 Go 自己写文件，不经过重定向。

## SLO 实测：字幕对齐与音画累计误差（G0-9）

技术方案 V4.0 §14.4 把这两条写成"试点目标，在规定机器、语料和并发下验证后再承诺"。
这里给出**在本机、在受控语料上**测到的数，并把"能证明什么、不能证明什么"分开写在下面。

### 一、字幕对齐：句首偏差 P95

```bash
go test ./internal/integrations/tts -run TestAlignmentSLOSentenceOnsetP95 -count=1 -v
```

| 分组 | 样本（句首） | P50 | P95 | Max |
|---|---|---|---|---|
| 常规中文 | 30 | 0.0 ms | 10.0 ms | 10.8 ms |
| 压力抖动（±16%） | 20 | 0.0 ms | 10.0 ms | 10.0 ms |
| 中英混读 / 专业词 | 20 | 0.0 ms | 10.0 ms | 10.0 ms |
| **全量** | **70** | **0.0 ms** | **10.0 ms** | **10.8 ms** |

门槛 P95 ≤ 200 ms → **通过，余量约 20 倍**。

测的是**句首**（每句话第一个字出现的时刻），不是逐字平均误差：观众感知的是
"这句话什么时候开始"；逐字 MAE 30ms 的算法完全可能让句首整体偏移 200ms。

口径与局限（重要）：

- **真值是合成的，不是人工标注的**。本机没有付费合成的 CosyVoice 语料，也没人听过、
  标过每一句的起点。合成音节包络能精确知道每个字的真实起始时刻，因此适合验证
  "算法能不能定位"，但不能替代上线前的人工标注验收。两者结论不一致时以人工为准。
- 句首静音刻意在 **60–680 ms** 之间变化。算法内部有一个固定 lead 假设，只有真实
  lead 偏离它，句首偏差才被真正检验；全部用 200 ms 生成等于让被测代码自证。
- 合成音频叠加了 **±50（约 -46 dB）确定性底噪**。干净的数字零静音会让 VAD 一测一个准，
  "全部 0.0 ms"只证明语料是合成的。加噪后仍然准，才说明算法抗得住。

有牙验证：把音节核检测关掉（退回盲估匀速），压力组与中英混读组 P95 立刻变成
**220 ms**，用例红；恢复后变绿。这条破坏第一次只改 lead 估计时*没*红（P95 140ms），
所以语料跨度从 120–340ms 扩到了 60–680ms —— 门槛的检验力本身就依赖语料跨度。

### 二、音画累计误差：30 分钟成片尾部

```bash
python3 scripts/fidelity/slo_av_sync_30min.py --duration 1800 --mark-every 60
```

| 测量项 | 实测 |
|---|---|
| 音频尾部偏差（vs 计划） | 0.0 ms |
| 视频尾部偏差（vs 计划） | 0.0 ms |
| 音画相对偏移 | 0.0 ms |
| 时间分辨率 | 音轨包络 5 ms / 视频帧 33.3 ms |
| 尾部标记解码后时长 | 50.0 ms（与合成时一致，没有被截断） |

门槛 ≤ 100 ms → **通过**。

做法：合成 30 分钟音轨（每 60 秒一个 50 ms burst），与静态画面一起封装成 H.264 + AAC
的 mp4（画面在同一时刻闪一帧白），再**解码回来**测最后一个标记的真实位置。
比的是解码后的时间戳，不是文件头里的标称时长 —— AAC 的 priming 与编码器补帧都会让
两者错开，而错开量随片子变长累积。

口径与局限：

- 这是**编码/封装链路**的累计误差，不含渲染与合成环节。
- 音频是合成 burst，不是真实 TTS 音轨；真实音频有气音与底噪，编码器行为不完全相同。
- 5 ms 包络窗口意味着小于 5 ms 的偏差读成 0.0；对 100 ms 门槛够用，但不能拿它证"零偏差"。
- 若 `ffmpeg` 不在 PATH，脚本回退到 `imageio_ffmpeg` 自带的那一份（本机就是这种情形）。

### 这两条都还没覆盖的部分

- **真实 TTS 音频的人工标注验收**（SLO 原文要求"抽样、人工标注"）。
- **多并发下的生成耗时曲线**：§14.4 明确说"生成耗时不写固定几秒"，需要
  `生成耗时/成品时长` 与吞吐随并发的实测，目前没有。
- **HA 版的可用性/恢复目标**（99.5%、RPO/RTO）：属于部署形态，本机测不了。
