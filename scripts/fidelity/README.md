# 出片保真检查（ADR-18）

回答一个问题：**渲染出来的视频，内容比源页少了什么没有？**

仓库里原先的样片是用色块占位的，画面里一个字形都没有。它适合验时间轴、转场、残影，
但对「文字丢没丢」完全不敏感 —— ADR-15 的空格缺陷和 ADR-17 的图层顺序缺陷都是
换成带真实文字的样片之后才暴露的。这套脚本就是那份样片的来源。

## 四步跑完

```bash
# 1) 造底图：字体从镜像里取，保证与线上同一份字形
docker create --name fsrc ppts/renderer:dev
docker cp fsrc:/usr/share/fonts/opentype/ppts /tmp/ppts-fonts && docker rm -f fsrc
python3 scripts/fidelity/gen_pages.py --fonts /tmp/ppts-fonts --out /tmp/fidelity

# 2) 编译成计划（底图会被拷进 job 目录，见 ADR-14）
go run ./scripts/fidelity/plan -in /tmp/fidelity -out /tmp/job

# 3) 提交给渲染服务（--assets-dir 指向 /tmp/job 的只读挂载）
curl -s -X POST --data-binary @/tmp/job/plan.json http://127.0.0.1:8090/v1/render
#    然后轮询 GET /v1/render/{jobId} 直到 succeeded，取回 segment_*.mp4

# 4) 比对末帧与源页
python3 scripts/fidelity/compare.py \
    --pages /tmp/fidelity/pages \
    --elements /tmp/fidelity/elements.json \
    --segments /tmp/job-out
```

## 判据

| 指标 | 阈值 | 说明 |
|---|---|---|
| 整页平均绝对差 | ≤ 2.0 | H.264 编码噪声在 0.5–1.3；到 2 以上多半是内容变了 |
| 差 >32 的像素占比 | < 1% | 结构性丢失会到几个百分点（ADR-17 是 5.8%） |
| 元素区域墨量比 | ≥ 0.8 | 文字被盖掉/淡掉时直接趋近 0 |

任何一条不过，脚本以非零退出。这三个阈值来自实测：5 页带文字样片在正确实现下是
平均差 0.56–1.23、差 >32 的像素 <0.35%、墨量比 ≥0.95。

## 两个容易踩的口径坑

- **取末帧**，不要取页中任意一帧：入场动画在页末才回到恒等，取中间帧会把动画状态算成差异。
- **墨量的基准色只从源图取**：两边各自取中位色时，渐变区域会得到不同基准，
  算出来的是基准漂移而不是像素差异（第一版因此虚报了 3.7 个百分点）。

## 想复现 ADR-17 那个缺陷

把 `gen_pages.py` 里 `page1` 的图层顺序改成「先 items 后 card」再跑一遍：
三行要点的墨量会从约 6% 掉到 0.00%，而任务状态仍是 `succeeded`、没有任何 warning。

## 带配音的样片（Q7：动效是否跟着讲解走）

上面那条链路评的是「渲染器画得对不对」，它**测不了**「该动的时候才动」——
成片没有音轨，起播点是 `120 + i*180` 按元素序号排的，trigger 全是 `onEnter`。
这一节是补那条链路：把讲解词合成为音频，把元素的起播点绑到段落上。

### 只改绑定、不改讲解词

`segments.json` 是 `narrate.py` 的产物，`bind` 是它从 `q7-script.json` 抄进去的。
只改绑定（拖时间点、换绑段落）时**不必重打 TTS**——重合成会让音频基线漂移，
同一句话重合成一次时长不一定分毫不差。改用：

```bash
python3 scripts/fidelity/sync_bind.py \
  --script scripts/fidelity/q7-script.json \
  --segments tmp/q7/segments.json --out tmp/q7/segments-d.json
```

文本或段 id 对不上就报错退出（它不做猜测）；时间戳一律不动，因为那描述的是已生成的音频。
页级 `static` 清单（容器底板这类「页首就在」的元素）也由它一并抄过去。

### 绑定写成「念到它的那个词」

```json
"focusAt": [{"elementId": "p2-bar2", "atText": "九百四十三"}]
```

`sync_bind.py` 用 `words.json` 把它解析成 `atMs`，plan 侧一行都不用改。手写 `offsetMs`
的问题是没人能复核：那个数是听出来的，换一个字或换一次语速就作废。写成词之后，
改讲稿重跑一次就自动跟上；找不到、或出现多次而没写 `nth`，它报错退出——错绑一个时刻
比不绑更糟。

零点用**实测的裁剪量**（两次时长相减），不是「第一个词的起点」：TTS 说第一个词起于
96ms，实际音频 200ms 才越过 −45dB。差这 100ms，所有 `atText` 会整体偏晚，而偏晚在
V11 里正好卡在「走神」的容差边上——每根柱子都差一点，其实是尺子错了。

### 什么时候不该等那个词

一句话讲**两根**柱子，切换点当然落在第二根的数上（s2-2「两核一百七十四秒，四核一百三十一秒」）。
但一句话讲**一根**柱子时，整句都是它，句首就该指过去：

```json
{ "id": "s2-3", "text": "两核跑五分钟，九百四十三秒。", "focus": "p2-bar2" }
```

写成 `focusAt: [{elementId: "p2-bar2", atText: "九百四十三"}]` 的后果不是「晚一点」，
是**前半句画面谁也没指**：旁白在说「两核跑五分钟」，四根柱子一样深（K 片页内
4.7s、5.1s 的实测墨量是 1.00/1.00/1.00/1.00）。V11 因此分成两种参照：

| 位置 | 参照 | 理由 |
|---|---|---|
| 段内第一个焦点 | 段开口 | 这一段讲的就是它，句首不指＝讲话了没反应 |
| 段内其余焦点 | 念到它的那个数 | 一句话里换人，必然落在新那个数上 |
| 没有焦点的元素 | 实测出场 vs 数值词 | 原逻辑，覆盖「只有出场」的编排 |

前提是**一段一个主题**。若某段先总述再落到某根柱子（「先看时间，两核一百七十四秒」），
第一个焦点按句首会被判早——目前的解法是把段拆细，不要在一段里先绕一句。

### 换产物目录时：`PPTS_SEG_DIR`

三个测量脚本（`check_alignment` / `check_appearance` / `audit_layout`）都要把每页的起止
时间算出来，口径是「把各段的**实测**时长累加」。段文件位置由 `PPTS_SEG_DIR` 指定，
默认 `tmp/q7/out`。

```bash
PPTS_SEG_DIR=tmp/q7/out-g python3 scripts/fidelity/verify.py \
  --film tmp/q7/film_G_narrated.mp4 --segments tmp/q7/segments.json ... --rerun
```

不指会怎样：它读的是别的目录里的段，把**上一版片子**的页长当这一版的页起点。
G 片第一次跑就是这样——页 2 从 9.87s 变成 5.1s，后面每页的起点都往前挪，页 4 的采样
整段落在页 3 上，于是报「`p4-title` 整页未稳定出现」。那是一个长得像片子坏了的假失败。

所以 `_segtime.py` 里两条都是硬退出：段文件缺失不静默回退到计划值；实测段长与计划
差 >200ms 直接退出（这批段不属于这份计划）。

### 四个必须这么做的选择

| 选择 | 不这么做会怎样 |
|---|---|
| **逐段合成**，不是整页合成后再切 | 整页音频只能靠 VAD 或强制对齐切段，误差几十到几百毫秒；逐段合成的段落边界就是拼接点 |
| **裁掉首尾静音**（`silenceremove` 双向） | edge-tts 的 mp3 头部自带约 100ms 静音，元素按 startMs 出现、声音却晚 100ms——3 帧，正好踩在「不滞后」的判据线上，测出来的是 TTS 的静音头，不是渲染器 |
| **trigger 用 `withSegment`**，不是 `atTime` | 两者都能出片，但用 atTime 时改一句讲解词，音频时长变了、画面还按旧毫秒走，且不报错 |
| **关掉页转场**（`-hard-cut`） | 转场 320ms 逐像素混合，页首 220ms 开口的段落与它重叠，包围盒灰度差量出来的是混合度，不是元素不透明度 |

### 判据与实测

`check_alignment.py` 的算法：取段落开口前 400ms 到开口后 1100ms 的连续帧，裁出元素
包围盒，算它与「开口前那一帧」的灰度平均绝对差（MAD），第一次越过 2.0 的帧就是实际起播点。
只裁包围盒是必须的——整页指标会被大面积纯底色压住，2% 面积的变化看不出来。

2026-10-30 这一版（D 片，30.77s / 13 段 / 14 个绑定元素）：

- **开口前 400ms 内，所有绑定元素的区域变化均为 0** —— 没有「提前出现」。
- **扣除设计偏移后，最大起播延迟 53ms（1.6 帧）**；段内错落也准：页 1 四条
  （设计 240/380/520/660）实测 280/413/547/713，`p3-hero`（+240）实测 247、
  `p3-flow`（+700）实测 713。
- 页 1 的卡片底板 **不建轨道**（页级 `static`），所以页首就是完整的一张卡，
  不再有「空框等 8.9s」。页 1 低覆盖只持续 0.3s、页 3 只 0.5s（改前三处分别是 4.2s / 8.9s / 3.6s）。
- 这版只改了编排，讲解词与音轨一字未动，音画 lag 仍是 0.000s。
  C→D 的逐条对照与代价（页 1 之后 10s 画面不再变化）写在
  `openspec/changes/animation-render-service-image/review-packet.md` §8.8。

### E 片：把「静」也量化之后（同日）

D 片把三处编排改对，观感组从 3 红回到全过——但门禁全过不等于片子好看：
页 1 在第 1.4s 就把四件事铺满，**之后约 10 秒画面一动不动**，而旁白还在逐条念。
原有五组判据问的都是「元素在不在、准不准」，没有一条问「画面还在不在动」。

这一版做两件事：

1. **给 IR 加页级焦点**（`page.focus`）：`[{startMs, elementId}]` 描述「此刻讲的是谁」。
   非焦点元素降透明度（0.55），焦点元素保持。它不进 `clips`——压暗是**互斥**关系
   （甲亮则乙暗），而 clip 的叠加规则是逐属性相加/相乘，表达不了互斥。
   求值只有一份：`shared/motion.ts` 的 `focusDim`，Remotion 与分享播放器共用。
2. **焦点从哪来**：讲解脚本每段多一个 `focus` 字段，与 `bind` 并列。
   `bind` 决定元素**何时出场**，`focus` 决定讲它时**谁让位**。
   之前两件事挤在 `bind` 里，所以只能二选一：绑得早 → 元素齐活后全静；
   绑得晚 → 讲到才出现、前面全空。D 片选了前者，E 片把两者拆开。
3. **新增 V8.1「讲着话时画面不长静止」**：每 100ms 抽一帧缩到 320×180，
   算相邻帧差，连续不变的区间再与讲解区间求交。阈值 3.5s（本片最长一句 3.24s）。

| 读数 | D 片 | E 片 |
|---|---|---|
| 最长「讲着话但画面不动」 | **10.80s**（6.70–17.50） | **3.10s** |
| 第二长 | 4.00s（23.80–27.80） | 2.50s |
| V8.1 | **红** | 过 |

E 片 20 项全过。剩下的 3.10s 是「一句话的长度」——页 1 讲第一条时，
其余三条压暗着，讲到下一条才切换。这是当前结构的上限，不是余量。

#### 压暗带来的一个测量口径问题（已修）

加了焦点之后，`check_appearance.py` 的读数整个错位：`p1-item0` 的到位时刻从 6.03s
变成 12.43s。原因很简单——它拿**页末那一帧**当终态，而页末恰好是「最后一条亮、
前面几条暗」。前面几条被压暗的那一刻，就被判成了「刚到位」。

改成**框内对比度能量**（像素偏离自身中位数的平均绝对值）之后恢复正常：
压暗是仿射变换（`a·x+(1−a)·底色`），中位数跟着移动、偏离量等比缩小，信号还在。
输出的 `preSegDiff`（与终态的灰度差）也随之换成 `preSegLevel`（相对峰值的比例，0–1），
判据「不提前」改成 `preSegLevel ≥ 0.5`。门禁自检 22 → 23 项。

#### 渲染器改了但 plan 没变，会命中旧缓存

`planHash` 只含计划字节与 `RendererVersion` 常量。这次改了合成器（压暗），
plan 一个字节没动，提交后直接复用了上一次的产物——抽帧一看还是旧画面。
换渲染行为时必须同时递增 `RendererVersion`（或清掉 `workdir/<jobId>`），
否则「两次渲染逐字节相同」这条保真基线会保护一个过时的结果。

### 这版样片的边界

- 配音来自 **edge-tts**（免密钥的在线合成），不是产品链路的 SiliconFlow TTS。段落时长是真实的，
  音色与线上不同——判对齐够用，判音质不够。
- 元素 → 段落的绑定是**手写**的 `q7-script.json`，不是模型或规则自动生成的。这证明的是
  「`withSegment` 这条路通、渲染端按时出画」，不证明「绑定能自动生成」。后者是 Q7 第 1 件事。
- 4 个元素刻意不绑定（`p0-eyebrow`、`p0-meta`、`p3-caption`、`p4-note`），放在页末淡入，
  作为「不空转」的对照组。

## 元素→段落的绑定实验（Q7 第 1 件事）

上一节证明了「绑上去之后，元素确实跟着讲解出现」。这一节问的是**绑定本身从哪来**。
结论写在 `openspec/changes/animation-render-service-image/q7-bind-experiment.md`，
这里只记怎么复跑。

```bash
# 0) 元素文本：render.Element 只有 ID/Kind/Bounds，文本在 PageElements 换算时被丢掉。
#    从 gen_pages.py 的源头补回（底图一个字节不动）
python3 scripts/fidelity/enrich_elements.py tmp/q7/fid/elements.json

# 1) 复述式讲稿（照元素文字写，字面重合被抬高）
python3 scripts/fidelity/bind_elements.py --show-matrix --out tmp/q7/bind-report.json

# 2) 口语式讲稿（正常讲法：不复述标题、用指代、口语数量）—— 消融对照
python3 scripts/fidelity/bind_elements.py \
  --segments scripts/fidelity/q7-script-colloquial.json \
  --out tmp/q7/bind-report-colloquial.json

# 3) 只看字面匹配（第一轮的算法），用来对照 v2 加了多少
python3 scripts/fidelity/bind_elements.py --rules base --out tmp/q7/bind-report-base.json

# 4) 第二个样本：真实讲义 5 页（带表格/卡片/页码/装饰形状），元素从 pptx 抽
python3 scripts/fidelity/extract_pptx_elements.py \
  --slides 1,2,4,8,10 --out tmp/q8/fid/elements.json
python3 scripts/fidelity/bind_elements.py --rules base \
  --segments scripts/fidelity/q8-script.json \
  --elements tmp/q8/fid/elements.json --golden scripts/fidelity/q8-script.json \
  --out tmp/q8/bind-report-base.json
python3 scripts/fidelity/bind_elements.py --rules v2 \
  --segments scripts/fidelity/q8-script.json \
  --elements tmp/q8/fid/elements.json --golden scripts/fidelity/q8-script.json \
  --out tmp/q8/bind-report-v2.json
```

`--show-matrix` 打印每页「元素 × 段落」的相似度，调阈值、看失败原因都从这张表开始，
不要凭结果反推参数。`--rules base|v2` 是同一个脚本的两档：`base` 只有字面匹配，
`v2` 再加辅助白名单、数量词、序数、方位、同块带出五条规则（`--no-siblings` 可单独关掉
同块带出）。**报数必须说明用的是哪一档**，否则两组数字不可比。

### 三条不要改坏的性质

- **单调对齐**（DP）而不是逐个取最大：后者会把四行条目全绑到第一段，且允许「倒退」，
  而讲解是线性的。
- **绑定来源全部分开记账**：字面 / 计数 / 序数 / 方位 / 同块 / 标题先验 / 结构推断。
  混在一起会把「容器按位置挂上去」算成「文本匹配成功」，召回率会虚高 5–10 个点。
- **golden 可以标 `role: "decor"`**：图标、圆形底座这类伴随装饰绑不上时，不该算成
  内容召回失败。报告里内容召回与总召回分列。

### 实测（2026-10-30）

| 样本 | 讲稿 | 规则 | 召回（全部） | 召回（内容） | 精确 |
|---|---|---|---|---|---|
| 合成 5 页 / 19 元素 | 复述式 | base | 0.800 | 0.800 | 0.923 |
| 合成 5 页 | 口语式 | base | 0.400 | 0.400 | 1.000 |
| 合成 5 页 | 复述式 | v2 | 0.933 | 0.933 | 1.000 |
| 合成 5 页 | 口语式 | v2 | 0.533 | 0.533 | 1.000 |
| 真实 5 页 / 71 元素 | 自然讲法 | base | 0.404 | 0.500 | 0.955 |
| 真实 5 页 | 自然讲法 | v2 | **0.981** | **0.972** | 0.962 |

两个数字最值得记住：**真实讲义上 0.97，合成样本的口语版上 0.53**。同一套规则、
同一档参数，差在版面有没有把讲解顺序编码出来（编号、卡片、方位）。引用「0.97」
必须带上这半句，否则会变成「规则够用了」的错误结论。

## 机器门禁：一条命令验完「该动的时候才动」

```bash

python3 scripts/fidelity/verify.py --rerun       # 重跑三个测量 + 审计真片，约 2 分钟
python3 scripts/fidelity/verify.py               # 只审计已有报告（快，但报告必须是新的）
```

退出码 0 全过 / 1 有阻断项 / 2 缺输入。结果同时写进 `tmp/q7/verify.json`，
评审页 `scripts/review/q7.html` 会把它折叠在「机器实测」里——**默认收起**，
先看到「全过」会把人往 5 分上推，盲评就白评了。

### 为什么是「对账」，不是「把三个脚本串起来」

5.5 与 5.6 两轮评分都没能收口，查下来片子两次都不是主要问题，**是测量工具有盲区**：

| 洞 | 表现 | 现在怎么堵 |
|---|---|---|
| `check_alignment.py` 只回看开口前 400ms | 元素若更早出现，窗口里它「已经在了」，差恒为 0 → 报「不提前、准时」。**「通过」和「看不见」长得一模一样** | 门禁 V4.1：凡是 `settledMs` 早于该窗口起点的元素，直接判它的读数无效 |
| 判据写「3 帧」，播放器没有步进键 | 评审人没法数帧，只能凭观感给分 | `q7.html` 的 `←/→`、0.25–1×、「距开口 ±N 帧」直读；`probe-q7.mjs` 回归它 |
| 参照点是文本时间轴 `startMs` | 音频整体偏移（AAC priming）一个都发现不了 | `check_av_sync.py` 量音画 lag，门禁要求 ≤ 1 帧且互相关峰够尖 |

所以门禁的第一职责不是「再测一遍」，是**拒绝在证据自相矛盾或结构上看不见的时候放行**。

### 为什么又加了一组 V7：前六组全过，人看着还是不对

5.5 / 5.6 两轮评分都收不了口。前六组（制品/音画/覆盖/盲区/四条判据/新鲜度）在
`film_C_narrated.mp4` 上 **14/14 全过** —— 元素都准时，最大偏差 47ms。
但把片子按秒抽帧看，问题很明显：

| 时刻 | 画面 | 前六组 |
|---|---|---|
| 页 1 / 10.15s | 卡片里只有 2 条，下面三分之二空着 | ok（两条都准时） |
| 页 1 / 5.99–14.94s | 卡片底板 6s 就淡入，最后一条 14.9s 才到 → **空框挂了 8.9s** | ok |
| 页 3 / 24.0s | 右半页只有一个空边框（图片 26.7s 才进）→ **空 3.6s** | ok |
| 页 2 / 19.0s | 柱状图没有 y 轴基线，174s 与 943s 画得像差 1.5 倍（实际 5.4 倍） | ok（图表是一个整体元素，内部看不到） |

**前六组问的是「元素准时吗」，而人看的是「这一刻画面上有多少东西」。**
这是两个问题，前者全过不蕴含后者成立。V7 就是后者：

- **V7.1 内容覆盖**：已到位元素占本页内容面积的比例。低于 50% 且持续 ≥1.5s 判红。
  **按面积不按像素**：像素法在页 1 上是瞎的——10.15s 时四条要点只出两条，
  卡片里空着三分之二，但卡片底色已经铺满，整页像素到位率 93%。九宫格也不够，
  底色同样占满每一格。
- **V7.2 空框悬挂**：容器的框先出现、内容后填，超过 2s 判红。观众看到的是
  「还没加载完」。

容器不计入覆盖分母：卡片底板到位不等于内容到位，算进去会让空盒子看起来是满的。

**加上 V7 之后，同一条片子从 14/14 变成 3 项红**（页 1 空 4.2s、页 1 空框 8.9s、
页 3 空 3.6s）。这不是片子变差了，是门禁终于开始问对问题。

`audit_layout.py` 是这个检查的独立工具版：多了「页末闪现」（元素出现到本页结束
不足 1s —— 它不影响任何一刻的画面完整度，但等于没出现），并且打印每个时段的
缺件清单，适合调排版时手跑。

没有它，门禁本身会重演「看起来通过了」，而那正是 5.6 的教训。

### `check_appearance.py` 现在报三个数，别用错

参照物换过三次，前两次都被片子推翻（详见 `review-packet.md` §8.10）：

1. **该页最后一帧** —— 被页级焦点打破：页末是「最后一条亮、前面几条暗」，
   前面几条被压暗的那一刻判成「刚到位」。
2. **框内对比度能量** —— 被实心块打破：柱子长满后框内是一整块纯色，
   能量在「长了一半」时最高，四根柱子全被报成「整页未稳定出现」。
3. **出场前那一帧**（现行）—— 信号是「框内与它出现之前差多少」，连续量。
   柱子 0→峰值、淡入 0→峰值、压暗等比缩到 0.55 仍在半程以上。

| 字段 | 含义 | 能判什么 |
|---|---|---|
| `settledMs` | 变化量最后一次低于峰值一半的下一帧 = **到位** | 到位时刻。带淡入的元素比开口晚一个淡入时长（220–450ms），**不能拿来判滞后** |
| `onsetMs` | 变化量第一次达到峰值 30% = **开始变** | 只作诊断。若背后有同步淡入的容器，读数会塌到容器出现的那一刻 |
| `preSegLevel` | 开口前 100ms 那一帧的变化量占峰值的比例（0–1） | **「不提前」就用它**：还没出现 → ≈0；已经在了 → ≈1 |

`LEVEL_SETTLED` 必须留 0.5 而不是 0.85：非焦点元素被压到 0.55 不透明度，变化量随之
落到约 0.55；取 0.85 的话，压暗那一刻会被当成「又到位了一次」（页 3 的流程块踩过）。
